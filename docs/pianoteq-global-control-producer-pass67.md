# pass67：全局模态的控制选择、衰减限速和连续更新队列

将pass66观察的“选定衰减”推进为独立计算：按键关联权重取最大值、控制选择、衰减变化速率限制、四系数刷新及双队列交换均接入三个连续模态内核。128块5135960项检查逐位相同，包含自己的791个限速重排标记；完整原生PCM与官方参考逐字节相同。

## 恢复的具体计算

REA/Ghidra的 `3ca148` 与原始ARM64指令共同确定以下步骤。[实现](../dsp/global-control-producer.mjs) 使用初始2930条80字节模态记录，其中前1478条有按键权重控制。关联表共5553对、涉及105个按键控制槽；这些初始模型字段和关联表仍来自捕获，并非全部预设生成器。

当第一组dirty集合标记模态i时，先计算：

```
v[i] = min(1, max(0, float32(weight[i,k] * key[k].value) for each k))
all[i] = every associated key[k].flag equals 1
```

空关联表给v=0、all=1；超过weightedModeCount的记录给v=1、all=0。结果写入自己持续保存的v/all，并标记第二组dirty集合。

第二组标记的模态选择控制c：all非零时使用v，否则取v与globalControl的较大值。只有 `abs(float32(c - previousSelected)) > 0.001` 才刷新；阈值比较是原生double阈值，差值先float32舍入。

```
previousSelected = c
proposedDecay = fma32(c, slope, baseDecay)
if float32(proposedDecay - oldDecay) > maximumIncrease:
    decay = float32(oldDecay + maximumIncrease)
    previousSelected = -1
    mark this mode for another update
else:
    decay = proposedDecay
```

baseDecay、slope、maximumIncrease分别是模态记录4、8、1c字段。仅限制增大的方向。新decay直接进入pass66四参数公式，再写自己的系数表，驱动pass65连续模态状态；不读取原生计算出的decay或刷新参数作为种子。

第一阶段处理后清第一集合，第二阶段处理后清第二集合并交换两组存储与flag。限速产生的791个标记从自己上一调用的队列传入下一调用。下一次入口只补入观测到的新增外部标记（261个），已有内部标记不得消失，flag由持续状态及新增标记计算；没有用原生完整dirty集合重置自己的队列。

## 真实调用时机与捕获

[采集器](../scripts/pianoteq_capture_global_control_producer.py) 使用四个固定逻辑硬件点：首次全局入口、生产者入口、模态入口、模态返回。首次入口取得初态后关闭自己、启用生产者点，转换后同时启用三个点。没有改目标内存、注入函数或修改原应用。

生产者实际执行51次：block14及60–109；并非每个块都调用。产生889次系数刷新，其中791次限速；第一阶段权重聚合261次。block60有调用但不产生新系数，不能把“调用”直接等同“有表更新”。

首次采集错误地要求每个音频块都有生产者调用，在block1断言停止，窗口不完整且原生未正常渲染结束，严格保留为失败。确认进程84558退出/不再存在后，修正为记录真实可选调用，另建v2目录。正式85101正常exit0，128块完整、无采集错误。

初始模式字段只复制一次，之后每次入口和出口模式动态字段都作为核对目标；不作为更新输入。初始静态字段身份在捕获中跨阶段核对。完整系数版本表也只作比较。每块mono输入和处理前已有目标仍观察，最终mono仅作目标。
