# pass75：连续释放包络，经实际复制提交进入再击计算

本轮把pass74尚在观察的旧释放值改成自己连续计算：模态包络→实际复制提交→下一击旧释放输入→再击控制。3734次更新、3664次复制、4次再击读取，共18564项比较逐位相同。**整段PCM仍不一致，衰减时长的生成和调度分歧尚未闭合，不能认定完整声音复刻。**

## 具体计算

新增 [ReleaseProgressEnvelope](../dsp/release-progress-envelope.mjs)，依据上一轮REA证据`ev_003749d0b92eeb15cdd00c313813e1eb7edc38cb7c7afcfc5dab727581b1e125`与同一ARM64指令恢复`472f20`末尾计算。f为float32舍入：

```
if duration != 0:
    if ownPosition < 1:
        delta = f(f(timestep) * f(samples))
        denominator = min(f(duration), f(f(baseDuration) * 5))
        ownPosition = min(1, f(ownPosition + f(delta/denominator)))
    else:
        ownPosition = 1
```

duration=V944、baseDuration=V914、timestep=V8fc；先乘、后除、再加，没有FMA。duration=0保持原状态。模型自己累计uint32样本计数；活动分支要求正分母，非有限或不支持的输入拒绝。

5个声部首次包络位置均实测为0，作为一次性的观察初态；之后不再从原生位置重置。duration/baseDuration/timestep和块长仍为观察输入，**duration生产没有被本轮恢复**。

## 四个固定硬件点与异步边界

[采集器](../scripts/pianoteq_capture_release_envelope_chain.py)使用固定地址：

| 地址 | 读取内容 |
| --- | --- |
| 35ef10 | 已匹配旧声部及新击键控制输入 |
| 472f80 | 模态包络更新前、时长/步长/块长/计数 |
| 472fd0 | 同一模态更新后的实际位置 |
| 4604d4 | 声部+2f24已经从模态位置复制完成 |

每个回调核对frame PC与硬件站点地址，最多4点，运行中不重排地址。包络前/后通过线程、模态地址和配对序号绑定，不假定其线程等于声部初始化线程。模态对象必须等于本轮已创建声部+168。

首轮A使用再击生产者after点而没有复制提交点，工作线程硬件停顿后只取得26个更新，未当完整窗口；关闭站点后让原生正常exit0。它证明声部启动在主线程、包络在工作线程；下一轮B加入明确复制点。不能直接把工作线程最新包络等同于主线程读到的旧释放值。

正式B进程35997完整渲染并明确exit0。原生5次击键，已捕获的包络更新均在同一个工作线程118476542，生产者在主线程118476448。采集完整无读取错误，finish前待配对为空。

该轮出现macOS/LLDB的附带硬件停顿：包括空ID主线程停顿伴随另一个线程命中本轮站点、站点后一条指令处的`EXC_BREAKPOINT (6,1,0)`伴随实际站点，以及实际包络返回点的硬件异常。每次续行都先核对属于本轮固定点；不支持的原因立即停下。共14次普通Continue，13条有结构化sidecar，另一次在完整LLDB日志和保留的失败辅助脚本中记录。没有跳过目标指令、改PC/寄存器、写目标内存、注入内部调用或使用软件断点/Pedalboard。

公开`resume_owned_stops`是实测守卫的整理版本，只允许已经完成读取的包络返回继续；本轮实际使用的v1–v4脚本全部私有保留。公开守卫条件以13组真实停顿元数据和3组不支持条件回放检查，**不是另一次原生活动采集验证**。候选只读补采分支实际未调用；本轮所有数值记录均来自正常硬件回调。未知停顿或读取错误不能由该助手自动通过。

## 自己的状态如何成为下一击输入

[重放器](../scripts/pianoteq_replay_release_envelope_chain.mjs)按实际事件顺序执行：

1. 每个声部初态只初始化一次；后续更新前位置只比较。
2. 保存本次观察到的步长/时长，配对返回时推进自己的位置；原生更新后位置只比较。
3. 在**实际复制提交事件**中，将自己的最新已完成位置写入自己的copied-release表；同时比较原生模态值与声部值。
4. 下一击匹配旧声部后，从自己的copied-release表读r，与原生old.release比较，再以自己的r计算再击控制。
5. 在新声部首次复制事件中核对其已生成的repeatFlag、age、旧力度、attenuation与继承历史。

本轮同次末端是再击控制生产结果，没有同次采硬度谱；pass74的硬度消费证据不能拼作本轮硬度的额外检查。原生exp中间量同样未在本轮另采。

## 连续性与计数

5个声部各覆盖804/495/468/445/1522个64帧包络块，共3734。首次模态计数均为64，后续每次都恰好增加本块样本数，**没有采样计数缺口**。这项检查能拒绝“状态未变所以漏掉一整块仍通过”的假阳性。

| 检查 | 数量 |
| --- | ---: |
| float32比较：连续状态、复制、旧读取及再击结果 | 14825 |
| 整数比较：独立累计模态计数和再击标志 | 3739 |
| 合计 | **18564，零差异** |

2353次活动包络更新，1266次活动更新处于/达到上界。三个来源字段或时长不是输出回填，原生包络/复制/old.release均仅作目标。数值项是比较次数，不是独立机械状态数量。

## 实际音频仍失败

正式B完整142080帧、双声道24-bit/48kHz WAV的PCM SHA256为：

```
f0465aab64160cabf271b80a68f2b77fcf2b1b77808677af9cebb55b6caf212b
```

| 参考 | 不同交错样本 | 最大整数差 | 首差帧 |
| --- | ---: | ---: | ---: |
| pass73同刺激原版 | 170463 | 6320 | 10244 |
| pass74 A | 171125 | 6320 | 10244 |
| pass74 C | 153284 | 19 | 10832 |

B第2击r与pass74 C一致，但整段PCM仍不同。没有把较小差异解释成仅量化误差，也没有以状态吻合豁免无扰动/声音等价要求；没有独立声源完整WAV。

14项负对照全部拒绝。duration/baseDuration/timestep分别改动导致2222/2230/2230处差异；改一个块长导致803处。单项计数、更新前/后、复制、旧释放目标、生产者目标扰动各精确一处。删除整对更新并同步减少元数据计数仍有803处差异；删除下一击前最后复制并同步调整计数有2处差异，证明不是只核对记录长度。错误对象和不完整窗口严格拒绝。

私有证据：`debug-pass75-envelope-repeat-a/`、正式`debug-pass75-envelope-repeat-b/`、`pass75-*`。新代码通过实际目标数值重放、负对照与Python/JS检查；初始包络、时长生产、声部选择/年龄/力度/历史、全部模型/预设及完整琴槌/弦/制音毡方程仍未全部自计算。网页集成、完整复刻、最终合并与Pages更新未完成。
