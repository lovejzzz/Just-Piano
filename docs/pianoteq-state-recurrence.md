# Pianoteq 9 双历史状态递推：第二轮代码证据

本报告针对 ARM64 9.2.5，与音板 IR 主循环是不同的代码路径。当前可以恢复一个实际算术递推及其输出路径，但尚不能给对象贴上“琴弦”“琴槌”或“制音器”的确定标签。

## 虚函数表的边界

`pass2-mode-vtable.json` 从 `0x100ba05b0` 读取 64 字节。首个 8 字节为零，随后 8 字节是 RTTI 指针；典型 Itanium ABI 下实际对象 vptr 的 address point 是 `0x100ba05c0`，不是读取起点：

| address-point 相对偏移 | 槽地址 | 函数 |
|---|---|---|
| +0x18 | 0x100ba05d8 | 0x1004903a4 |
| +0x20 | 0x100ba05e0 | 0x10004972c |
| +0x28 | 0x100ba05e8 | 0x10032ce58 |

`0x1004e285c` 渲染函数存在以上三种偏移的虚调用。逐样本路径使用 +0x28，块处理路径使用 +0x18 或 +0x20。追加证据 `0x10086c8a0` 在分配对象后明确将 `0x100ba05c0` 写入对象首字段。RTTI 字符串为 `N4mdrt13SGenImpl_NEONE`，即 `mdrt::SGenImpl_NEON`。因此可以称为 NEON 合成实现；仍不能仅凭此名称认定对象专指琴弦。

## 已恢复的双输入二阶更新

`0x10032ce58` 在对象 O 的 +0xe0 字节不等于 1 时，读取以下数据：

| 对象字段 | 角色 |
|---|---|
| O+0x08 | 递推系数数组基址 |
| O+0x30 | 两个输入的耦合权重数组基址 |
| O+0x58 | 较早历史向量 P |
| O+0x80 | 当前历史向量 Q |

对每组四个 lane，系数数组相邻的两个四元组记为 A、B；输入权重数组相邻两个四元组记为 C、D。每个 lane ℓ 的操作是：

\[
Q'_{\ell}=A_{\ell}P_{\ell}+B_{\ell}Q_{\ell}+D_{\ell}I_0+C_{\ell}I_1,
\qquad P'_{\ell}=Q_{\ell}.
\]

I0、I1 是函数的两个 float 参数。二者均为零时走单独分支，省去输入贡献。状态范围由整数参数给出，按四 lane 向下定位起点、向上取处理组数。更新之前仅对该范围**最后一个四 lane 组**的两个历史向量做门限处理：绝对值不大于 `1e-18` 的元素清零。不能误写成每个元素每一步都做门限。

这是明确的二阶线性递推，但系数构建、更新时机和 I0/I1 的物理身份未知。静态形式与模态振子一致，并不能单靠形式证明它一定表示琴弦模态；也不能据此假定包含接触非线性。

## 无输入的块输出路径

`0x1004903a4` 从相同对象字段取得 P、Q、递推系数，处理末组低幅值后调用 `0x1007c0bcc`。后者对多个状态累加输出，并将时间循环以四样本展开。

令 `s[-1]=P`、`s[0]=Q`，随后 `s[n+1]=A*s[n-1]+B*s[n]`。一个时间迭代写出的四个累加样本为各 lane/各状态组的 `sum(s[-1])`、`sum(s[0])`、`sum(s[1])`、`sum(s[2])`；保存回去的两个历史状态是 `s[3]`、`s[4]`。这解释了块渲染中先输出旧状态、再以展开式推进四步的结构。SIMD 加法次序与数学 sum 的舍入顺序不同，不应宣称逐位等价。

渲染函数的逐样本路径也在虚调用前从状态范围求和，虚调用之后将刚才的和写到输出。这支持同一时序约定，构造函数确认此具体 vtable 确实可被创建；运行时何种乐器/设置选择该实现仍需动态核验。

## 观察到但尚未物理定名的反馈

`0x1004e285c` 在一个标志开启时，还会对记录数组执行带阈值的反馈：先将 O+0x80 的状态与一组权重做点积，按记录阈值设置状态标志；已置位且点积低于阈值时，计算类似 `gain * max(0, (stored_value-dot_product)*scale)` 的量，并将它乘另一组权重加回 O+0x80。随后滚动记录的两个历史字段。

这已经是状态依赖的非线性分支，超出“找到函数名”，但尚未确定它是哪个物理接触过程。仍需记录初始化函数、阈值/权重来源及动态参数对应。没有证据时不能直接称它为制音器或琴槌接触力。

## 激励路径进一步闭环

`0x10020b28c` 创建临时输入缓冲，在外层对象的模式 O+0x2f90 为 1 或 2 时调用 `0x1005df61c`，然后将该缓冲传给 `0x100472f20` → `0x1004e285c`。注意这里的外层对象 O 与前文合成状态对象并不是同一基址。

`0x1005df61c` 的 mode 1 不是可见的琴槌接触方程，而是从已有序列取出一个块：

\[
b[t]=(1-v)g_1g_2\,s[iN+t],
\]

其中块索引 i 位于外层 O+0x8d8，N 为输出块长；v/g1/g2 分别来自 O+0x2f24、O+0x2e88、O+0x2e8c。i<0 时清空输出；输入序列不足时先清空输出再拷贝可用部分。**i=0 时强制 b[0]=1**，覆盖上述乘积。这是确定的首样本脉冲行为，不能根据路径在合成器之前就叫它“琴槌”。mode 2 且第二个整数入参为 0 时，调用 `0x10005e8e4(O+0x2db8, output)`，再乘 g2。

在 `0x1004e285c` 中还发现：临时缓冲 +0x0c 放入上块保存的末样本（合成器容器 +0x77c），当前输入缓冲通过 `0x1000883dc` 放到 +0x10；每次虚调用读取两条地址流 `+0x0c+4t` 与 `+0x10+4t`。追加反编译 `0x1000883dc` 已确认该 helper 从第二地址向第一地址复制 16 字节组。因此前述 I0/I1 实为同一激励的相邻时间样本 `x[n-1]`、`x[n]`，并不是两个独立物理源。更准确的表达为：

\[
Q'_{\ell}=A_{\ell}P_{\ell}+B_{\ell}Q_{\ell}+D_{\ell}x[n-1]+C_{\ell}x[n].
\]

复制证据为 `pass2-input-copy.json` / `ev_41840306c7c19da12446c2a180cb0a824e03a4774e71b318174115d89283cbf8`。末块样本在处理结束后写回 +0x77c 支持跨块连续性解释。mode 1/2 的输入模式不能外推为普通琴键演奏的全部激励路径。

激励路径 evidence：`pass2-excitation.json` / `ev_99aca95f4d55e5ddb98a3d4194c47b43fda37f30c611575a71dda5e732634d03`；调用路径见 `pass2-render-dispatch.json`、`pass2-synthesis-core.json`、`pass2-model-render.json`。


### mode 2 实际是带状态的噪声滤波路径

`0x10005e8e4` 追加反编译发现直接日志字符串 `bow_pressure=`，并且每个输出样本更新一个四字 uint 随机状态（移位 11、8、19 的 XOR 递推），再驱动多个两级递归滤波器。因此该模式不应被直接称为钢琴琴槌。字符串和算术共同支持它与弓压/噪声激励相关，但具体乐器如何选择此模式仍需更高层证据。

对每个十 float 记录 j，令 c1=record[2]、c2=record[3]、gain=record[1]；P 为源对象 +0x14 存储的当前控制值，E 为 +0x38 的指数偏移，a_j=record[0]，a_ref 为首记录的 record[0]。代码实现：

\[
r_n=2 U_n/2^{32}-1,\qquad x_j[n]=r_n (a_j/a_{ref})^{E+P},
\]
\[
y_j[n]=x_j[n]-x_j[n-2]-c_{1j}y_j[n-1]-c_{2j}y_j[n-2],
\]
\[
z_j[n]=y_j[n]-y_j[n-2]-c_{1j}z_j[n-1]-c_{2j}z_j[n-2],
\]
\[
b[n]=P\sum_j gain_j z_j[n].
\]

六个历史值保存在记录 [4..9]，分别是两级滤波所需的 x/y/z 两帧历史。每个样本所有记录使用同一个随机数 U_n。代码对 P 做块级渐变或按曲线覆盖，并可能刷新滤波记录；这些系数的物理含义仍未知。源函数结果还要经过外层 g2 缩放。

这里的具体可验证结论是：这一 mode 2 分支不是已恢复的琴槌接触求解器，而是一条有明确二级滤波公式的噪声源。证据：`pass2-excitation-mode2.json` / `ev_35e82bc4056fd5854f348998c524ddd3d5d9d55b8e35038ce54e94da135cfaf6`。

## 系数刷新已经连接到上述递推

`0x100863008` 不是只有标签的注册函数：它直接向合成对象 +0x08 的 A/B 系数数组及 +0x30 的 C/D 输入系数数组写值。因此下面计算可与 `0x10032ce58` 的使用处连接。令容器为 V、其首指针指向的合成对象为 O，避免混淆两种偏移。

令每个 lane 的 R 是刷新函数准备的指数样变换结果，K/S 分别是 V+0xe8、V+0x110 指向的数组元素，U/W 分别为 V+0x70、V+0x98 指向的数组元素。在 O+0xe0 的 bit0 为 0 的分支：

\[
A=-R^2,\qquad B=2KR,\qquad C=W,\qquad D=(US-WK)R.
\]

输入模式不启用时 C、D 被置零。bit0 为 1 的另一分支中，A 换成 `-R/(2K)`，B 仍为 `2KR`；倒数使用 NEON 估计与两次校正，因此数学除法只是其理想形式。不能忽略这一模式差异。

R 的输入是 `-(V+0x0c 的 float) × 已准备的 lane 数值`。当两个相邻 SIMD 组的所有输入绝对值均不超过 0.15 时，代码使用明确的近指数多项式：

\[
P(x)=1+x\{1+x[0.49999973+x(0.16683996+0.041710194x)]\}.
\]

其他情况走 `0x10071033c`（已核验为系统 `_vexpf` 包装）或 `0x1009a3048`（已核验为带输入钳位、log2 范围缩减和多项式的向量 exp 近似）。因此可以把 R 定性为衰减指数的计算结果，但不能将整个实现无条件写成精确 `exp(x)`。

K/S 的更新源于 `0x1001d0364` 的两个输出，输入组合为 `θ_i=(F_i+J_i(k-1))·τ·2π·v`：F/J 来自 V+0x20 / V+0x1b0 的数组，τ=V+0x0c，v=V+0x780，k=V+0x804。当前公式中的 F、τ、v 尚不赋予 Hz、秒等单位。追加核验 `0x1001d0364` 确认：绝对值范围缩减使用 4/π 与拆分的 π/4，随后计算 sin/cos 多项式并按象限选择及恢复符号；第一输出为 sin 近似，第二输出为 cos 近似。因此 S≈sin(θ)、K≈cos(θ)，K 还在调用者处做极小值钳位。常规分支可解释为 A=-R²、B≈2Rcos(θ) 的阻尼振荡递推；这是数学类型辨识，不是具体琴弦物理身份或 GUI 单位的证明。

### 非线性反馈记录的权重预处理

相同函数处理 V+0x268 起的记录（数量 V+0x260、步长 0x70）。记录 +0x18 指向观测权重，+0x40 指向反馈权重，+0x68 保存归一化量。在一组处理中先复制权重、再对先前记录做投影修正，最后逐 lane 使用向量 H 缩放反馈权重。其 scalar 分支明确为：

\[
\widetilde w_i=H_iw_i,\qquad s=\sum_i H_iw_i^2,\qquad record[+0x68]=1/s.
\]

H 来自 V+0x6c8 所指数组，并由如下中性表达式生成：

\[
H_i=\tau^2 / \{[S_i/(K_i+1)]^2+1+L_i\tau\},
\]

L 是此处临时数组元素，其生成尚未完全追溯。这样已连接了“权重准备 → 加权点积 → 触发非负反馈 → 写回模态状态”的数据流，但还缺记录的物理类型和初始化语义。不能仅因存在阈值就将此反馈等同于完整制音器接触模型。

日志中出现的 `_logf()` 在伪代码里没有参数，属于反编译缺失，故没有将它强行解释为某个 T60/阻尼换算公式。证据文件：`pass2-coefficient-refresh.json`。
