# pass51：校准全局帧并越过已知音频差异起点

新捕获将银行记录和最终立体声浮点块放在同一条时间线上。前8192帧最终浮点块经已恢复的量化算法编码后，与同次真实WAV逐样本一致，因此帧号获得了音频校准。

独立计算的335个银行输出块全部匹配，三路均覆盖已知差异起点frame4611之后至8191。此次完整原生WAV也与官方基准一致。不过，中间乘加记录少于模型预期两条，逐事件严格检查仍失败；输出端验证和中间事件完整性分别报告。

## 真实帧位置与短窗口边界

[捕获器](../scripts/pianoteq_capture_convolution_timeline.py) 使用四个主线程固定硬件点：输入推入、乘加调用、重叠输出结束、末级音量之后。末级点 `1bc114` 每次取得双声道64帧；前缀编码与WAV一致才能认定从全局frame0开始的标号正确。

银行首次输入出现在frame896，内部时间戳为0，后续每次均满足 `globalFrame = timestamp + 896`。本次114次银行调用、1026次输入推入，最后一块起点8128，窗口结束8192。frame4608至8191的56块中，三路输出均被检查，覆盖frame4611之后10743个输出样本。

pass50的414次推入、26496个输入float与本次前缀逐位同。在这次已校准运行中，对应范围是896至3839帧，早于已知frame4611差异。这个跨运行对应不等于直接测得了pass50自己的绝对时钟；它明确显示仅凭此前短窗口不足以定位差异起点。

## 输出端计算验证

[输出端重放器](../scripts/pianoteq_replay_convolution_output.mjs) 从输入样本、初始化时域核和编译计划自行计算全部15000次乘加、FFT、逆变换和重叠历史，直接核对335个最终银行输出。它不使用中间乘加记录作输入或比较目标。

| 检查 | 结果 |
| --- | --- |
| 144个初始化核频谱、逆变换结果、银行输出及新历史 | 104192项float32逐位同 |
| 推入游标、时间戳、全局帧关系和对象状态 | 11244项精确相同 |
| 最终立体声浮点块编码与同次WAV前缀 | 16384个交错PCM样本相同 |
| 同次WAV前8192帧与官方参考 | 相同 |
| 完整原生WAV与官方参考 | 113152帧逐字节同 |

完整PCM SHA-256为 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`，原生进程35038正常exit0，没有受限继续记录。

最终立体声浮点块仍由原生程序提供，仅用于校准帧号和PCM比较；本轮独立计算的终点是银行三路输出。这个WAV不能视为浏览器或独立完整声源生成的音频。核时域初始化继续使用pass49的跨运行证据，编译计划及物理输入样本也仍有观察边界。

## 中间事件严格检查仍失败

[逐事件重放器](../scripts/pianoteq_replay_convolution_timeline.mjs) 要求每个预计乘加都有对应记录，在frame3584被拒绝。后续诊断还在frame7680发现第二个未对应事件：模型计算15000次，捕获记录14998次。

诊断仅跳过这两个比较位置，保持模型的全部乘加计算不变，剩余5878422项float32及251212项字段检查均相同，包括335个完整输出。该诊断始终标记失败，不计逐事件通过。结果支持检查采集事件完整性，但尚不能单凭它唯一判定是线程过滤、硬件断点漏报还是其它原因。

输出端验证是另一项范围明确的检查：保留严格事件检查的失败，并以直接计算的块结果核对实际输出。删除全部14998条中间乘加观察后，输出端重放仍计算15000次乘加并通过；不存在读取这些中间结果来补算的路径。

## 控制实验和未完成事项

六个负对照均失败：frame4672之后的输出目标、逆变换目标、初始化核目标各改一ULP，以及推入游标加一，各恰好一项不匹配；把frame4672的PCM浮点块循环移位一帧产生128个校准样本差异；删除首个推入记录则被顺序检查拒绝。另有上述删除全部乘加观察的正对照。测试夹具显式重建SHA绑定，原始捕获没有修改。

一次预定的同配置复测在启动线程断点处中断，窗口为0帧，没有正常原生退出，不计验证成功。两次尝试和所有失败证据均保留。

本轮没有复现旧的 `19481af4…` 音频变体，也没有证明它已解决。后续仍需调查较长分区、尾部调度与CABN外层输出，并追踪中间事件完整性。完整琴槌—弦—制音毡耦合、全部模型/预设、浏览器整段声音等价性和最终合并部署均未完成。

私有证据位于 `~/.local/share/just-piano-analysis/debug-pass51-*`、`pass51-*.json`；本轮动态验证依赖已有REA分析，未新增静态反编译结论。
