# 模态筛选、分组索引与音频复核：pass23

本轮将 pass22 仍从捕获读取的分组索引改为独立计算。依据 REA/Ghidra 的 `839c04` / `9511bc` 证据 `ev_8c2f7ca6a780a8b3a95b6be3e17f50e221b83650d4859fe9c17324e12d80c7a3`，并核对 ARM64 指令的 float32 FMA、double 除法及循环次序。目标身份与 [pass22](pianoteq-voice-source-mapping-pass22.md) 相同。

## 实际计算

`dsp/voice-mode-selection.mjs` 按“组 → 列 → 行”遍历激励后的源表。三组运行配置中，行到达 `splitRow` 后路由编号加一；超过分界频率的非零编号进入第零组，其余按组数取余。频率超过 `float32(sampleRate * 0.485)` 的分量被剔除。

非旁路时，计算 `projected = float32(amplitude * fma32(-float32(64/sampleRate), decay, 1))`。当 projected 不高于阈值，执行幅度下限和预计衰减时间筛选。后者使用 amplitude 的 float32 指数字段、阈值的标量 log2f，以及 `float32((sampleRate * ln(2)) / decay)`；这里的乘法、除法先用 double，区别于反编译预览中容易误读的全 float 计算。每组索引按运行时 alignment 补齐，空组仍保留。

模块显式接收 `log2f` 回调。当前验证使用 `float32(Math.log2(x))`，并与真实原生返回对照；**只验证了本次阈值 `float32(1e-6)`，没有恢复通用的系统 log2f 实现**。不能把这一点外推到所有质量设置。

## 五组真实输入

所有案例使用同一 NY Steinway 干声 FXP、48kHz/24-bit 双声道，运行时只读内存，单个固定硬件断点；未使用 Pedalboard。

| MIDI 音高 / 力度 | 源分量数 | 有效索引数 | 三组有效数 |
|---|---:|---:|---|
| 69 / 96 | 183 | 181 | 148 / 17 / 16 |
| 21 / 32 | 577 | 333 | 194 / 139 / 0 |
| 60 / 64 | 306 | 240 | 182 / 29 / 29 |
| 72 / 100 | 162 | 162 | 134 / 14 / 14 |
| 108 / 127 | 39 | 33 | 27 / 3 / 3 |

A4 的日志返回、布局、181 个索引、五张初始化数组和参考衰减共 **1,115 项逐位一致**；新增四例共 **4,734 项逐位一致**。949 个有效索引全部由计算产生。预测的 318 个剔除分量中，315 个因幅度、3 个因频率被剔除。预计衰减时间分支已按指令实现，但本批没有分量由该分支剔除，不能声称它已有独立运行覆盖。旁路、单组/双组及特殊 bzz/多平面配置也未覆盖。

低音案例发现实际保留空组，模块已支持；验证器同时限制尾部比较到原函数实际初始化的末端，未将未捕获的末尾容量误作有效数据。此前越过该边界的比较报错未被当成通过。

将 A4 首索引的实际对照值从 0 人为改成 3 后，验证器 exit 1，恰好报告该索引一处错误；没有使用修改后的对照索引作计算输入。

## 连续输出与真实 PCM

将筛选和映射预测接回 pass20/21：不再读取原生索引，也不从原生声部数组取得初始频率、振幅、相位、J 或衰减。8 个块、7 次频率投影、1,536 个完整分组输出样本，合计 **35,907 个 float32 比较全同**。连续状态仍由自己的前一块推进。激励源表及筛选控制仍来自捕获，最终音板/效果/立体声链尚未独立闭合。

A4 两次新硬件断点采集均正常 exit 0、错误为空，PCM 与既有原版基准相同：`1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`。

四音序列的两次调试采集、调试副本直接运行、原版三次重跑，PCM 均为 `8c098aa4730a8fb78bac70fe0e04c7e2cdd0c49519e629a4bf40fa7fe29061c5`（249856 帧）。但**首次原版基准**为 `3d788b07c4b04db23b3692b7e3c9e03eafe0ac1197464fec825b50f98886e4a0`：10151 个交错采样值不同，最大差 1 个 24-bit 整数单位，首差在交错位置 159483。原因未确定；原始文件和命令完整保留。本轮因此能证明采集与后续原版重跑一致，不能宣称该多音序列每次运行都逐样本确定，也不能把这些原程序 PCM 当作 JS 最终音频匹配。

首次 log2 捕获误用整数寄存器解析，得到无效的 0；已标注失败并保留。v2 改用寄存器原始字节读取，才作为数学对照。

私有证据：`debug-pass23-voice-selection/`、`debug-pass23-selection-log-v2/`、`debug-pass23-selection-range/`、`debug-pass23-selection-range-log/`、`audio-pass23-selection-range-baseline/`、`audio-pass23-selection-repeat/`；音频核验与异常记录见 `pass23-pcm-verification.json`。商业模型表、原生程序字节及反编译全文不提交到仓库。

运行验证器时在 pass22 命令后增加 `--selection-log <log捕获的runtime.json>`。不传该选项仍可执行旧版映射验证；报告明确区分 `modeSelectionComputed` 与 `indexMapStillCaptured`。
