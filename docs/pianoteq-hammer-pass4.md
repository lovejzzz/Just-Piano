# 第四轮：琴槌硬度状态到模型系数的读取路径

**当前结论：已在直接复制分支建立命名闭环。** 编辑侧 Piano/Mezzo/Forte/总体硬度及 Fine 曲线，经 root+160 模型成员、临时模型、渲染接口 I+130 的深复制，进入五点曲线和力度插值，最终参与主模型系数计算。合成/选择分支仍可能改写模型；没有将所有预设、所有分支或完整琴槌接触方程宣称为已恢复。下文早期筛选作为排错记录保留，末节给出解决命名缺口的证据。

分析对象仍为本机 Pianoteq 9.2.5 ARM64 的只读副本。依据第三轮真实参数解析器，编辑状态 S 的 `+0xb0c/+0xb10/+0xb14/+0xb18` 分别是 Piano / Mezzo / Forte / 总体硬度的可写 float。此记录追踪这些字段的消费者，不重复归一化曲线。

## 全文件汇编筛选

对 `~/.local/share/just-piano-analysis/pass3-arm64-disassembly.txt`（完整 ARM64 文本反汇编）做立即数地址筛选，发现 45 处 `ldr/ldrh/ldrb/ldp` 等读取指令以这四个精确偏移寻址，其中 **0 处为直接 `ldr sN,[base,#目标偏移]`**。候选及前后指令已保存至 `pass4-hammer-offset-candidates.json`。

这个结果不能证明硬度没有被使用：运行时可以通过引用解析器获得字段指针后从 `[pointer]` 读取、批量复制整个状态、使用调整后的基址，或转换成另一套模型对象。四个裸偏移的全文搜索没有覆盖这些路径。

已逐项排除的一组有代表性误命中：

| 指令地址 | 为什么不能视为硬度消费者 |
|---|---|
| `0x1000fe07c` | 基址来自 `adrp ... 0x100c18000`，读取全局地址，不是 S |
| `0x100492294`、`0x100496e40`、`0x10060f534` | q 寄存器从 `0x100b41000` 常量页载入，再写新分配对象 |
| `0x1005d209c` | SIMD 运算的向量常量来自 `0x100b43000`，不能因有浮点算术就命名为硬度 |
| `0x100683370` | 常量向量用于元数据初始化，邻近文本为 Noise/Portamento 参数 |
| `0x10011ebf8`、`0x10043c9d4` | 指向固定页内字节表并读字节，非 S |
| `0x100330188` | 固定地址用于类型身份比较 |
| `0x1007288a8` | 形成函数地址，写入函数指针表 |
| `0x1003ab3f4`、`0x1008b381c`、`0x100994644` | 基址来自全局页，非编辑状态字段 |

## 下一跳候选与证据门槛

1. `0x100585d90` 所属函数连续写入 `x19+0xb0c/+0xb10/+0xb14/+0xb18`。每次调用 `FUN_10007e8d4` 后从栈取 4 字节写入。这是一个值得检查的对象构造候选，但尚未证明 x19 就是 S；不能仅由四个偏移相邻便给它命名。
2. `FUN_1001a8124`：第三轮已经确定它位于 RPC 归一化修改之前，用来读取当前值。追踪它的内部取值路径有望定位通用状态读取器，再按调用方区别 UI 取值与模型构建；相较于继续盲扫偏移，这条候选有真实调用数据流支持。

目前没有找到可命名为“琴槌接触刚度公式”的新计算。最终应以字段指针来源、读取、转换、下游系数消费者共同确认，而不是偏移命中、pow 调用或音频变亮的相关性单独确认。

## 候选反编译后的纠正

`0x100585d90` 所属函数确定为 `FUN_100581ca0`。它连续处理大量形如 `0xff65558f`、`0xff625b71`、`0xffffffff` 的 32 位常量并写数组。这与颜色表初始化吻合，且没有状态根来源的支持。因而不能把它认定为琴槌状态初始化；分析文件名 `pass4-state-constructor.json` 只是查询时的工作命名，不是已证实类型。证据 `ev_3b5f91411e1770593e4b1294838df70bf896a498f978b6c780cacd3d46bfb37a`。

`FUN_1001a8124` 则确认类型 1 分支先调用 `FUN_1008d8fb4(ref,context,&value)` 读取原始 float，再取标度对象调用 `FUN_1002c1450` 转成归一化值。因此实际可继续追踪的读入口是 `0x1008d8fb4`，其调用方需要区分 UI 与模型构建用途。证据 `pass4-normalized-reader.json`，`ev_e503139160547c04eba46b74d23360dea358d29f0d5ccac18720740dc22ddf55`。

另查已取得的巨函数 `FUN_1004fe958`（`pass4-state-transform.json`）：其目标对象 `+0xb08/+0xb10/+0xb18` 是 begin/end/capacity 风格的三指针容器，由 `FUN_10093d810` 构造。它与 S 上上述 float 布局不相容，不能把同偏移的读写当作 S 的硬度计算。

## 通用 float 读取器及调用方筛选

`FUN_1008d8fb4` 与第三轮 setter 使用同一 `FUN_1003957c4` 逐级解析器。它通过只读上下文取得根，找到最终类型 1 的指针后执行 `*output=*resolved`，然后释放上下文。这解释了为何完整反汇编没有直接以 S+固定硬度偏移进行浮点读取：该入口采用解析后的裸指针读取。证据 `pass4-state-reader.json`：`ev_0a8600946925a562775afe226aa8cd3e736d1b2116eafb90b9cc2393007b9875`。

其 31 个直接调用方已先用完整汇编的字面量与运算上下文筛选。以下函数可以排除为本次寻找的琴槌系数生成入口：`0x1000c4510`（comp_mix/ratio/attack/release 控件）、`0x10037b90c`（auto_rand_param_edit.hh）、`0x10072d270`（equ_vel_graph_common.hh/curve_grid.hh）、`0x1007e8950`（ppp/pp/p/mp/mf/f 与 Graph 标签）、`0x1002c7154` 和 `0x1007591e8`（调律显示）、`0x1009ae200`（踏板标签文本）。其中若干含大量浮点运算，仍然是 UI 计算；不能据浮点运算数量认定为 DSP。

下一小组为 `0x1001a8424`、`0x1002a9610`、`0x10035a474` 及短转发 `0x10005c610`。查询关系证据 `pass4-state-reader-callers.json`：`ev_bb62384a30663b36132a0cd83eb0c549c7bd348cd5a295365788496af82acbf5`。

## 小读取调用方排除，转入真实触发链

新增四个小读取调用方均未连接琴槌系数：`1001a8424` 按输入事件差值乘 .02 调整并夹在 0..1，`10005c610` 做 0/1 翻转；`1002a9610` 和 `10035a474` 处理指定更新事件后计算 `exp(value×0.115129255)` 并写另一对象 `+0x1a8`。后者是 dB 到幅度形式，但动态参数引用身份没有确定，不能命名为琴槌硬度。

随后改沿已经与 hammer_bounce 重触发相连的 `FUN_10053f47c`。其事件 case0/2 将输入力度经 `FUN_100252000` 处理后传入 `FUN_100793674`。该下级先从每条 `0x1248` 字节模型记录 `+0xa4` 读取系数 a，对力度 v 做：

```text
v′ = v + 0.3 a sin(πv)
```

之后处理多个有效分支的相对触发延迟，存在 `exp(-16v)` 形式的时间量，最终调用 `FUN_10035ed60`。这些是从真实触发链获得的数值关系，但 `+0xa4` 尚未关联具体 GUI 参数，且尚未发现三档硬度之间的分段/重叠关系。不得把力度修形本身当作琴槌压缩力公式。对应原始证据为 `pass4-note-on.json`、`pass4-note-start.json`。

## 已闭环的实际 voice 路径

`10035ed60` 按 note 选取步长 `0x1248` 的 G 记录，取得或分配 voice X，将 G 写到 `X+0x2fb8`、原始模型写到 `X+0x2fc0`，调整后的力度写 `X+0x2fd8`，然后调用 `10007a60c` 初始化，符合条件再调用已知主准备函数 `100715f98`。这把先前孤立的 G/X 布局连接到实际 note-on，而非仅凭字段形状猜测。

`10007a60c` 将该力度复制到 `X+0x78`，夹在 0..1 后写 `X+0x7c`。`100715f98` 调用 `10057e4d8` 产生 `X+0x80/+0x88/+0x8c/+0x90` 等力度相关量，然后调用 `100692ffc` 准备主模型数组，最后交给 `10043dcb0`/`1009511bc`。

`10057e4d8` 的一个已知关系是 `X+0x88 = 1 / (1 + (1−2z)h)`，其中 z 来自 `10051a700` 的力度计算，h 来自 G 的嵌套对象 `+0x30`。另有条件指数幅度项 `exp(X[2fe0]×G[c0]×0.115129255)`。这些关系尚未与 GUI 的命名硬度逐一绑定。

证据：`pass4-voice-start.json`、`pass4-voice-configure.json`、`pass4-velocity-coefficients.json`、`pass3-contact-parent-c.json`。

## 主准备函数里的五节点力度曲线

`100692ffc` 确实调用 `1008c89ac` 两次，使用同一实际力度（X+0x2fd8）分别求两组模型曲线。第一组节点容器 G+0xef8，值容器 G+0xf10；第二组 G+0xf28、G+0xf40。修改值容器分别为 G+0xf58、G+0xf70，随机配置 G+0xf88。函数要求节点和值各恰好五个 float，节点非递减。

`1008c89ac` 不是平滑多项式：它在相邻节点间做线性插值，区间外取首末值；重复节点跨度为零时选择后一值。若额外参数 u 非零，先逐点将值 y 修正为 `y / (1 + (2/r−2)u)`；某模式位还把第 3 节点乘 .75、第 4/5 节点乘 .8。启用随机配置时，第 1/2 节点共享一个乘子，第 3 节点独享，末 2 节点共享第三个乘子，然后夹在 0..2。

第一曲线返回值乘增益后 h 进入 `t = (1−1.01/(h+0.00999999))×G[f0]`，并参与后续逐模态数组修改。这是力度到模型系数的实际计算链，尚需曲线生产者绑定 S 的命名硬度。不能单凭三组随机乘子或音频的三段响应把它直接命名成三档硬度。

直接生产者候选已由汇编定位：`1001c59ec–1001c5a10` 向 `100065fe4` 同时传入 G+ef8、f10、f58、f28、f40、f70、f88 七个容器地址。这与上述使用点的整组布局一致；继续分析该生产者是闭环所需的下一步。

证据：`pass4-main-excitation.json`、`pass4-hardness-interpolation.json`、完整 `pass3-arm64-disassembly.txt` 对应地址。

## 曲线生产者确认及尚缺的命名桥接

`1001c5320` 是上述调用所在函数，实际调用 `100065fe4`。后者把六个输出 float 容器调整成五元素，然后从模型接口的虚表槽 0 取基础模型 B、槽 +8 取编辑模型 M。注意这里 M 是该接口返回值，不是此前仅按地址相近推测的 S。

已恢复生产关系如下（E(F,n) 表示 `100019a34` 在当前音高 n 对字段曲线 F 求值）：

```text
p = M[9ac] × E(M+a28,n)
m = M[9b0] × E(M+a78,n)
f = M[9b4] × E(M+ac8,n)
a = clamp(M[9b8] + E(M+b18,n), −1, 1)
```

若 a 非零，各组先计算 `q=clamp(group×(1+a),0,2)`；a<.5 使用 q，a>=.5 再使用 `q+(2−q)×(2a−1)`。随后五点值依次为：

```text
[p×E(B+c58,n), p×E(B+ca8,n), m×E(B+cf8,n),
 f×E(B+d48,n), f×E(B+d98,n)]
```

这里 p/m/f 指经过上述 a 修正后的组值，仅是工作符号；未将其直接当成已绑定的 GUI Piano/Mezzo/Forte。节点曲线本身由 `10009edcc(n,B+de8,output,3)` 产生，并非本函数硬编码固定 MIDI 分界。第二套五节点从 B+fc8 产生。

这条链现在有明确的模型字段→五点生成→力度线性插值→主模型系数计算，而非参数名称或函数结构。此阶段剩余命名桥接是 S+b0c/b10/b14/b18 到此 M+9ac/9b0/9b4/9b8 的实际转译；本轮末节已经用实际深复制链解决直接复制分支的缺口。两组偏移相差 0x160 本身不构成证明。完整汇编中 `10031f7fc–10031f820` 发现以标志 0x2b/0x2c 为条件拷贝 M+9ac/9b0，另 `1007e0fcc` 一带用同标志记录差异；这些只能作为后续追踪位置。

证据：`pass4-hardness-curve-builder.json`、`pass4-note-model-builder.json`；反编译对 float 返回值产生很多 `CONCAT` 伪影，本文只提取能由显式字段与赋值关系支持的式子。

## 音频分界可检验预测与接口身份

五点采用 `[p,p,m,f,f]` 组乘子，则低组只影响 k2 以下，中组只影响开区间 `(k1,k3)`，高组只影响 k2 以上（退化或零值另论）。本轮官方渲染测得低组至 MIDI velocity 71、中组 45..98、高组从 72 开始的现象，与这一结构相容；定量验证还必须取得当前预设在该音高的 k1/k2/k3，并纳入力度表及修形。不能用这些实验阈值直接代替内部节点。

另一路确认模型接口 I 是 stride `0x1b60` 的向量记录，构造 `1000701cc` 写虚表 `100bc1828`。槽 +8 的 `1008867d0` 返回 I+0x130（此处 M），槽 0 的 `1001f0188` 返回 `*(I+0x118)`（此处 B）。这消除了接口返回对象的身份模糊，当时 S 到 M 的字段转译仍需直接证据；末节现已补齐直接复制分支。

## 节点曲线读取与 v2 迁移反例

`10009edcc(n,C,out,3)` 中 C+0x48 是输出维数，C+0x18/+0x20 是输入坐标向量，C+0x30 是按输入点排列的多分量输出表。一般路径取包围 n 的输入区间，逐分量计算 `(1−t)Y0+tY1`。C+0x4c 的 bit0 为零时 `t=(n−x0)/(x1−x0)`；置位时以夹至 `[1e−10,1e10]` 的正值作 `t=log(n/x0)/log(x1/x0)`。分母过小时 t=1。调用的 mode3 在区间外取端点。C+0x4d==1 则分派到另一个实现 `1001a6468`，本次尚未展开；不能将一般路径强加给所有预设。

曲线的 archive 来源已定位 `10059f2cc`。正常路径使用 `1000b1090` 从 archive 读入 B+c58/ca8/cf8/d48/d98/de8，故节点不是只由 GUI 三个硬度值生成。特定兼容分支明确写描述 `This is an instrument from Pianoteq v2.x` 并将 bVar2=true；只有该分支把五条基础值设为 1，把节点置为 `[-0.0078125,0,0.5,1,1.015625]`。前四项由地址 `100aa4374` 的 16 字节读取，第五项位模式 `0x3f820000`。另旧 archive 版本 `<0x2e` 会复制第一套曲线到第二套。

这些 fallback 常量不能当作本次当前预设的运行节点，不能据此声称已预测实测 45/72/99 阈值。当前仍缺 archive 的当前节点表及其模式、力度映射后的实际运行值。

证据：`pass4-knot-builder.json`、`pass4-knot-model-source.json`、`pass4-default-knot-bytes.json`（具体导出文件名以分析目录为准）。

## All 组修正的 ARM64 复核

对 `pass4-hardness-builder-asm.json` 核对后，上述 `q+(2−q)×(2a−1)` 保持成立：`100066300` 执行 `s0=a−0.5`，`100066304` **仅一次** `fadd s0,s0,s0`，`10006630c` 用 `fmadd` 算 q+s0×(2−q)。两个其余组在 `100066330` 复用同一个 s0 作矢量乘加。`100066348/34c` 的 `fcsel ... pl` 使用 `1000662f8` 对 a 与 .5 的比较标志，选择修正结果或 q。因此系数是 `2a−1`，不是 `4a−2`；不能从反编译变量复用或视觉重复推导第二次倍增。

## 编辑模型到渲染模型：实际复制桥接

此前 S 与 M 的偏移差 0x160 只是线索，本轮新增构造器、虚表和复制调用三组证据。

- `1000ee56c` 的编辑根对象在 root+160 调用 `1004ae764` 构造模型成员，root+19a8 调用 `10049bf1c` 构造另一配置成员。这与命名解析器使用的完整编辑根布局相符。
- 渲染接口 I 的 stride 为 0x1b60。`10007018c`（查询点0701cc）在 I+130 调用同一 `1004ae764`，在 I+1978 调用同一 `10049bf1c`，并写虚表 `100bc1828`。虚表+8指向 `1008867d0`，原生只有 `add x0,x0,#0x130; ret`，因此运行时 M=I+130。虚表0返回 `*(I+118)`，+10返回 I+1978。
- `pass4-edit-model-assembly.json` 中，模型组装从受 guard 保护的编辑快照根取 root+160，经 `1007aa33c` 拷贝到临时 M_A（原生348fec，stack+1ae8）。直接分支再将 M_A 拷贝到 M_B（349540/349558，stack+2a0）。另有从资源 root+160 取得默认模型的 fallback（3495f4），以及 `10031e97c` 的选择/合成分支；不能把全部路径简化成恒等复制。
- `3496e4` 将 M_B 传给 `10052105c`，后者 `521324` 调用 `1003f2ce8(I,...,M_B,...)`。该函数明确调用 `1007aa33c(I+130,M_B)`，将编辑侧完整模型成员实际送入上述 getter 返回的 M。

复制函数 `1007aa33c` 对 src/dst+9a8 调用 `1005ff9b0`；该 helper 的开头复制24字节，覆盖9a8..9bf，因而包括硬度9ac/9b0/9b4/9b8，后续复制各 fine 曲线的动态数组。由此在直接复制分支，命名编辑字段 S+b0c/b10/b14/b18 对应模型成员(S+160)+9ac/9b0/9b4/9b8，最终进入运行时 I+130 的相同字段。这个对应由成员构造和实际复制确认，**不是把运行时 M 指针宣称为编辑 S 指针加160**。

证据文件：`pass4-interface-vtable.json`、`pass4-interface-getter.json`、`pass4-interface-constructor.json`、`pass4-edit-state-constructor.json`、`pass4-edit-model-assembly.json`、`pass4-edit-to-render-state.json`、`pass4-interface-state-assign.json`、`pass4-model-state-copy.json`；`pass4-hardness-state-copy.json` 保存5ff9b0证据，24字节头复制亦已用本机保存的原生反汇编逐指令确认。命名解析器完整根布局与这里的编辑快照根布局一致，但未采集两个运行对象的实时指针或 GUI 修改的运行时数值轨迹。
