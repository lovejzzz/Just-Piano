# pass68：原始按键值到曲线、更新标记与连续全局模态

将pass67的“映射后键值与新增dirty标记作为输入”进一步移除。原始105键值/flag经过原生标量曲线，按每个键关联的模态编号生成全部261个外部更新标记，再驱动控制选择、衰减限速、系数刷新和三个连续模态内核。128块6159839项逐位相同，完整原生PCM与官方参考同。

## 已恢复的按键映射

REA/Ghidra将实际键映射绑定到 `83a7c0`，调用者为 `096558`。每键128字节记录包含原始值20、映射值24、flag28及8/10处的模态编号表（偏移为十六进制）。仅在原始值或flag改变时，执行 `1d17f8`、边界mode3的标量曲线，再将关联模态写入第一dirty集合，置其flag为0。

[实现](../dsp/global-key-mapping.mjs) 复用已有 [compactScalarCurve](../dsp/post-excitation.mjs)：区间内先计算float32倒数，再计算位置比例，以原生非对称乘法/FMA次序插值；两端钳制，未用普通双精度线性插值替换。默认配置实际曲线有六个节点，曲线和每键模态编号表仍作为初始模型输入。

本窗口只有键槽60发生9次变化：block14由0到1，block60–67依次下降至0。槽号由实际结构定位，不把它未经证明地当作MIDI编号；测试MIDI音符为69。9次变化各遍历29个关联模态，自己产生261次标记写入。

## 全局控制和真实刷新门槛

`73f328` 保存rawGlobalControl到170，沿同一标量曲线算出174字段。若映射全局值改变，标记前weightedModeCount个模态的第二集合；否则只有任一dirty集合flag为0才执行 `3ca148`。这些条件现在也由自己的状态判断。

因此127次全局控制入口中，自己计算出51次实际生产者执行，随后889次四系数刷新、791次限速重排。初始两组队列只复制一次，之后所有外部标记和内部重排都由计算产生；没有以原生新增位补入队列。pass67接口仍保留独立重放用途，新链通过受检的addDirtyModes写自己的队列。

globalControl本次始终为0，所以非零全局踏板曲线和全体模态失效路径尚未以实际正例验证；公式的负对照不能替代该覆盖。
