# 重复击弦计算链及跨运行验证：pass32

本轮把 pass31 两个已恢复的重复修正阶段接回完整激励链：硬度调制 → 谱控制与弦间准备 → 对数谱和指数权重 → 追加模态 → 原始模态随机修正 → 主路历史更新 → `692ffc` 最终四张源表。输入仍依赖捕获的位置修正后源表、模型表和初始随机种子；这不是从全部预设独立生成最终立体声的完成证明。

## 硬度中的再击相位

`excitationHardness` 原有重复路径现在通过真实快、慢连击验证器执行，而非只写静态分支。频率和 age 先转换为 double，与 double 2*pi 相乘，再将结果舍入为 float32 调用 cosf：

```
argument = f((double(referenceFrequency)*double(2*pi))*double(age))
amount = f(attenuation*f(repeatScale-1))
repeatFactor = FMA(cosf(argument),amount,1)
common = f(common*repeatFactor)
```

两组各10条主次记录，三个输出各30项同。`--cosf-candidate` 必须显式指定，传入 `float32(Math.cos(x))`；没有将该候选冒充通用原生 cosf 移植。已有 exp2f、log10f 候选的限制同样保留。

REA/Ghidra 精确指令证据 `ev_df913dbf77a512ef085855fe1d6cafa7387c1d3ec135a7cf0c8427b175e1d466` 确认 `693ef4` 的重复调制因子 FMA；双精度相位乘法及最终单精度转换同时核对了保留的 ARM64 指令。

## 保留跨运行失败，补齐同次输入

第一次将 pass31 的硬度报告直接接到本轮早期控制捕获时，原验证器报告6处差异：快连击第二击的两路硬度值及斜率不同。该失败报告保留在首次 `replay.json`，没有用新成功报告覆盖。

随后把硬度输入读取提取为 `capture_inputs`，在控制点和完整谱点同时捕获该次调用使用的参考频率、age、历史混合量、硬度曲线等。`--embedded-hardness` 明确用这些**输入**重算各观察点的硬度，原生硬度输出仍只用于比较。报告区分外部硬度报告和同次输入来源，也列出两个捕获之间的控制差异。

补采 v2 的快/慢两组，完整谱验证各5120项全部同，两个阶段的硬度输入未发现差异。另对快连击控制点补采 v3/v4，与v2共30条主路或次路记录，30个原生 primary 输出均与同次输入计算逐位同，age 也一致。因此“旧异常由 age 变化引起”仍只是未证实的假设，**不能用这次补采替旧异常指定原因**。新验证不放宽相等条件；它避免把来自不同运行的控制无条件当成同一组输入。

## 接通追加与连续历史

`appendExcitationSupport` 明确只完成历史更新之前的追加过程，不再因真实 repeatFlag 拒绝该阶段。完整输出验证器仍要求传入 `--repeat-captures` 四个实际阶段文件；缺失时不会把追加前结果当作重复击弦的最终输出。

验证器实际执行：

1. 用本轮完整谱计算的加权源表求参考行、追加对数幅度、频率、衰减与幅度。
2. 与追加后真实四表比较，再以计算结果和观察到的起始种子执行原始模态随机修正。
3. 将计算出的随机状态和源表传入主路历史计算。每次再击的历史来自上次计算结果，保持四次连续更新。
4. 比较历史和随机状态，最后比较 `692ffc` 最终四表及边界。次路同样执行随机修正；其路径不进入主路历史更新。

所有阶段核对音符、主次路径、表维度和重复控制一致性。快、慢各5次击弦、10条主次路径，完整报告分别 **11849项，0差异**；每组含4次连续主路历史更新。比较包含输入表、阶段输出重复核对和整数状态，不能当作11849个独立物理状态。

最终再击末振幅改动一单位 float32 的负例，准确报告一处 final-amplitude 差异并退出1。普通 A4与四音域的 pass30 验证器回归也全部通过；缺少重复阶段输入时的拒绝仍保留。

## 实际音频仍不满足严格一致性

本轮20次独立硬件采集全部 exit0、无读取错误。每个样本都保存48kHz/24-bit双声道 WAV，并比较 pass31 同刺激的原版参考输出：

- 18次最大差为5–15个24-bit整数单位。
- 初次快连击控制点最大差6320；快连击追加后观察最大差12222。
- 20次均未达到 PCM 逐字节相等。失败样本全部保留。

上轮原版自身重复渲染也有不稳定输出，本轮尚未定位原因。不能据内部源表全部相同就忽略后续状态、输出混合或其它时序依赖，也不能把较大差异归结为单纯最终量化。

已直接检查本机原版 `--help`，该版本列出的离线导出选项中没有线程控制参数。未编造不支持的命令行开关，也未更改原版或系统线程/安全设置。

## 剩余范围

这次闭合的是**给定位置修正后输入**的普通/重复激励函数链。前置琴槌—弦接触、原始模态与完整模型表生成，单弦历史和其它模型/预设，完整声部输出混合及最终音频稳定性仍需继续验证。当前浏览器尚未使用整个研究链，暂不合并，不以现有独立六音色代替最终目标。

`npm test`、相关 JS/Python语法检查、负例和旧普通音符回归通过；这些结果与失败的最终音频检查分别记录。
