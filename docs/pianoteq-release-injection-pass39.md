# pass39：释放附加信号接通主组消费链

pass38 的3199个主组样本差异已全部由自己的计算逐位复现。本轮恢复了 `0fbb44` 的幅值整形、位置平滑、三节滤波、复数振荡调制和信号相加，再连接已验证的后段增益。加入标准初始化后，默认96块消费链 **80996项检查逐位同**；五个正式场景合计179966项，原生捕获运行正常退出0，真实PCM与各自对应官方基准相同。

这仍是一个声部消费窗口。释放目标值及上游全局物理控制量仍来自观察，输入的完整独立激励、最终麦克风/立体声混合及全预设覆盖尚未完成，网页尚未接入本链。

## 实际触发和算术

[硬件捕获器](../scripts/pianoteq_capture_release_injection.py) 只在四个固定位置读状态：入口、生成后、滤波后、调制并相加后。96块中，前46块因目标位置=1、当前位置=1、上一附加信号峰值很低而立即返回；后50块真正执行。对跳过块和活动块分别检查阶段完整性。

[release-injection.mjs](../dsp/release-injection.mjs) 实现了以下次序：

1. 以64样本线性靠近释放目标，步长受限。本批最大步长为0.0020833334419876337。相差不超过1e-5时直接采用目标。四条SIMD位置轨迹分别初始化，之后每四样本递增，不能用标量逐样本相加替代。
2. 由主组当前样本的绝对值生成分段幅值。形状量本批为0.26250001788139343，分界为其一半：分界内乘 `2/shape−1`，分界外加 `1−shape`；再乘 `1−position`。
3. 三节滤波处理生成的信号。
4. 以 `f32(f32(filtered * f32(amplitude/5)) * f32(2*oscReal+3))` 调制。本批 amplitude=0.18000000715255737。复数状态每样本按各自的乘法/FMA次序更新，由初始化计算建立状态，没有逐块回填原生振荡相位。
5. float32相加回主组，并计算附加信号的最大绝对值，供后续旁路判断。这里是峰值，不能写成RMS能量。

## 从初始控制量生成滤波系数

[release-filter-design.mjs](../dsp/release-filter-design.mjs) 从运行时初始频率、Q和dB控制量计算本批实际使用的类型2、3、5；其它类型明确拒绝。输入如下：

| 节 | 原生类型 | 频率 | Q | dB |
|---|---:|---:|---:|---:|
| 0 | 5 | 875Hz | 0.699999988079071 | 0 |
| 1 | 2 | 500Hz | 0.5 | 0 |
| 2 | 3 | 3300Hz | 0.5 | −73.5 |

采样率从捕获的滤波器对象读取，本批48000Hz。角度先用双精度π乘已舍入的归一化频率，再转float32；指数使用既有原生标量exp重建；随后逐项遵守原指令的float32运算顺序。不能随意融合设计过程中的普通乘加。

12个归一化系数、3个节增益、通道增益和96个SIMD表系数均与原生更新后结果逐位同。系数与表由自己的计算产生；原生更新后的表只作比较目标。

[vector-filter.mjs](../dsp/vector-filter.mjs) 实现 `19a3d0` 的四样本表生成与 `6bc124` 的实际SIMD滤波。前两节配对执行，第三节单独执行：配对第二节的FMA累加顺序与第一节不同，普通逐节标量IIR未被用作近似。12个历史值从已验证的零初态开始连续保留，不读取后续原生滤波历史作输入。

本轮sin/cos及设计分支只在上述参数范围得到验证，未声称所有频率、动态系数平滑及其它滤波类型均已等价。

## 与已计算声部输出连接

[重放器](../scripts/pianoteq_replay_release_injection.mjs) 使用pass38计算的96块延迟后主组输入，计算附加信号的整个活动窗口。pass38输入中15块继续来自pass36/37计算的模态源；其余81块的模态源仍为原生观察值。报告明确跨运行来源，不把它称为一份同进程整段独立音源。

重放器每块比较：输入、入口递推状态、生成样本、位置、设计系数和表、滤波输出和历史、调制输出、振荡状态以及相加结果。此前3199处相加差异全部被复现。随后将计算出的主组与pass38其它两组连接，比较增益前、增益后和最后消费点。释放附加链25690项、初始化10项，加上三个消费阶段55296项，共80996项。

临时运行生成的48kHz/24-bit立体声PCM SHA256为 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`，与相同官方预设/MIDI基准逐字节同。它证明捕获未改变本次真实输出，不能替代尚未生成的JavaScript整段立体声音频验证。

## Damper Noise保存后的真实不完全可逆性

将既有同进程A/B/A脚本增加 `--parameter damper_noise`，保持 `.5 → .25 → .5`、三次之间不重载预设。每份新预设均在全新进程恢复全部215项参数，均无误差超限；三个官方渲染进程均退出0。新增严格门要求A/A真实PCM相同，否则脚本exit1。此次该门**失败**，完整失败结果保留。

A的PCM为原始 `1907f8…`；B为 `48c002…`；恢复后的A为 `3b1499…`。两份A同为113152帧，但68507个交错样本不同，首差第3907帧，最大整数差4，归一化RMS差8.639220122769471e-8。该微小差异不能被容差“通过”。B相对最初A的最大整数差18885、首差3840帧；由于严格A/A失败，不能把全部WAV差异归因于唯一界面参数。
