# pass249：基础时长到制音器初始化的实际边界

本轮确认开发者模式已启用。使用授权的独立调试副本，在四个硬件观察点读取自然执行中的值：41e7a0（基础时长返回）、1c5b6c（频率下限处理之后）、71869c（声部时长变化及截断之后）和43e048（制音器模型初始化之后）。没有修改目标代码、寄存器、数据或执行位置，没有使用 Pedalboard。

新增[私有存档输入导出器](../scripts/pianoteq_export_duration_archive_inputs.py)、[只读采集器](../scripts/pianoteq_capture_duration_source.py)和[边界核对器](../scripts/pianoteq_verify_duration_boundaries.mjs)。复用已有的 archiveDampingDuration，而非重新实现另一份基础时长算法。导出器重新读取当前资源和FXP，保留完整摘要及匹配的基础模型身份；商业逐键表、曲线和捕获记录留在仓库外。

## 已验证的数值

当前 NY Steinway/A4 预设中，独立基础时长是 float32 的0.48124998807907104。三次基础返回、三次频率下限输出、五个声部的源时长、五次声部结果和五次初始化，共21项浮点逐位相同，0差异。

自然执行观察到的 G+78 为440.0000305175781，因此 float32(2/G+78) 小于基础时长，当前频率下限不改变结果。乐器特殊分支标志为0，声部随机时长配置的启用值也为0，末尾截断不改变结果。71869c之后的五个H地址与43e048的五个初始化H地址一一匹配。

必须区分G+78与合并模态数据的参考频率：后者在现有场景约为439.7203369140625，不能代替这里的440.0000305175781。已有 source-tuning 实现能计算G+78，但其报告尚需与当前预设和资源建立可检验的输入绑定，不能把历史计算报告直接当作当前来源。

## 验证的边界

原生进程正常结束、exitStatus=0，普通错误与durationErrors均为空。继承的音板采集器仍写出 `completed=false`：本轮没有执行它的整套音板采集协议。核对报告因此保留 `parentSoundboardCaptureComplete=false`，仅按实际时长阶段覆盖和进程终态验收；不把这个文件宣称为完整音板或连续音频捕获。

本轮 `audioSamplesCompared=0`。生成了原生WAV，但未将其与新浏览器输出作对照，也没有修改连续链的时长输入。pass248已有的连续音轨验证仍只证明它原有的受限范围。

频率下限输入仍来自观察；逐键曲线运行模式仍按显式 `linear-clamp` 条件处理。当前没有验证活动频率下限、condition增量、特殊乐器覆盖或启用后的声部随机化。核对器拒绝特殊乐器、启用的声部随机化和活动condition，避免把未知分支当成当前已验证分支。21项比较和五个声部只覆盖一个音符。

## 反向检查

分别修改基础返回、下限输出、声部源时长、声部结果或初始化时长，每项恰好1处差异，独立预测摘要不变。只修改解码的编辑时长输入，独立预测摘要改变，21项全部产生差异。启用特殊乐器、启用声部随机化、移除一个初始化记录均被拒绝。共9项反向检查符合预期。

私有证据位于 `pass249-duration-source/baseline-v1`、`pass249-duration-current-inputs.json`、`pass249-duration-boundaries-report.json`、`pass249-duration-negatives/results.json`。资源摘要为 `d8383d3910cb17cda98075acccfeb9e3829b0ad34a6af1fc1cde67484c805d3d`；FXP摘要为 `c9073553f6d62c716b874f15418902d15e58edc97a56f79b112ccb3e4a01e751`；捕获摘要为 `d81490d30a728d44ddf664f8ddf585955573416720ba4547090a742c0402fa9a`。

下一步是绑定并复算G+78的独立调音来源，补充活动分支，再将存档生成的时长接入连续链，重新核对真实PCM。整机立体声、全部音区/预设、AudioWorklet及参数持久化验收仍未完成。
