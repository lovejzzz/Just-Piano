# 完整复刻与发布：完成条件

用户目标：完整复刻 Pianoteq 9 的声音及预设，保留暗色电影感界面，最终合并并提供正常工作的 GitHub Pages 链接。该目标持续有效；下面的局部通过不缩小最终范围。

| 要求 | 当前权威证据 | 状态 |
|---|---|---|
| 精确声音计算 | 真实复系数、复根、频率/衰减、制音控制、无输入块内核的数值验证；详见研究状态 | 局部实现；完整生成/输入/控制/输出路径仍缺 |
| 完整琴槌、琴弦和制音行为 | 激励、重击、模态递推、释放已部分恢复；瞬时接触系统完整状态尚未证明 | 未完成 |
| 全部实际预设 | 800份NKS为lean选择记录；42份完整FXP详细尾部按reader消费至末端；基础instrument资源仍在解析 | 未完成；网页六个原创音色不满足本项 |
| 每键、力度、踏板及参数有效 | 当前原创引擎有功能检查；研究音频只覆盖明确列出的案例 | 未完成全模型校准/等价性验证 |
| 浏览器使用恢复后的引擎 | 研究JS内核位级重放4096状态和8192输出 | 未接入；网页仍使用原独立引擎 |
| 原版音频等价性 | 部分原版与被观察副本PCM一致，只证明对应采集运行的非扰动 | 尚无完整网页输出匹配证据 |

最终验证必须使用实际浏览器音频与官方Pianoteq相同预设/音符/力度/采样率/控制事件的对照，覆盖键盘音域、代表性和边界力度、单音/和弦、同音重击、踏板连续控制、释放、参数修改和刷新后的恢复。不能用回放测试输入、静态文件存在、音量非零、核对副本PCM或一次听感评价，替代完整网页声音匹配。

合并前应确认全部要求有匹配范围的证据，提交并推送实现、测试和相关说明。合并后检查GitHub Pages构建状态，在实际HTTPS地址检查资源加载、AudioWorklet、安全上下文输入、移动布局、离线更新与发声，再提供最终链接。没有这些证据，不将目标标为完成。
