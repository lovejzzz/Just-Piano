# pass63：全局反馈注入与九行卷积源

九行卷积源并非入口声部组的简单副本。三个三行声部组与九行视图共享存储，在全局处理中还会被反馈支路原位修改；本轮恢复这一步并通过400块、770800项检查。

## 失败假设与真实运算

首次将全局入口三个组按group-major直接连接到卷积源，230400项中220755项不同；换成row-major则221187项不同。两个失败假设均保留，没有按最相似样本寻找映射。

原生 `8dbc80` 的两个矩阵参数方向需要按实际写入确认：它把第二矩阵作为源，以 `454bf8` 将其加进第一矩阵。`6c2ac4` 当前分支向每个声部组注入全局S+0x118的三行反馈，系数取S+0x114。本次系数为float32 `0.3333333432674408`，运算为：

```
for each group g, row r, sample i:
    group[g][r][i] = fma32(feedback[r][i], gain, groupBefore[g][r][i])
cabinetSource[g*3+r] = group[g][r]
```

[injectWorkspaceFeedback](../dsp/workspace-feedback.mjs) 独立计算这一步。gain为零时保留原生跳过行为，不额外FMA以改变符号零。当前动态分支为post-route反馈、行屏蔽关闭；pre-route反馈和启用屏蔽路径不作已验证结论。

## 同次数值证据

[采集器](../scripts/pianoteq_capture_workspace_groups.py) 在全局入口 `6c2ac4` 和卷积入口 `0ef37c` 两个固定主线程硬件点读取处理前组、共享视图、实际反馈、处理后组、九行源及辅助矩阵。[重放器](../scripts/pianoteq_replay_workspace_groups.mjs) 从入口组与反馈独立求值，不以处理后组或九行源补算状态。

三个组的指针依次是九行视图起点加0、768、1536字节，行距64个float；每块都核对相同共享身份及连续布局。九行排列为group-major，而处理前后的数值差别来自真实反馈注入。

| 检查 | 结果 |
| --- | --- |
| 入口组与共享视图 | 230400项float32相同 |
| 计算的处理后组 | 230400项float32逐位同 |
| 计算的九行卷积源 | 230400项float32逐位同 |
| 辅助矩阵在全局阶段未变 | 76800项float32同 |
| 指针与布局绑定 | 2800项相同 |
| 合计 | 770800项，零差异 |

400块中386块反馈非零。按 `f32(f32(feedback*gain)+groupBefore)` 分步舍入的诊断在230400项处理后值中有48738项不同，明确不能代替FMA。

11个负对照全部拒绝：入口组、反馈源、增益、处理后组目标、九行源目标、辅助目标、别名指针、行屏蔽分支、pre-route分支、缺失阶段与不完整窗口。单样本反馈改动影响三个组、两处目标核对，共6项差异；处理后组/九行/辅助目标的一ULP扰动各恰好一项差异。
