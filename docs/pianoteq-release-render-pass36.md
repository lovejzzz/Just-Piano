# pass36：释放状态到连续模态输出、能量反馈与模态压缩

本轮把已恢复的释放控制接到连续模态计算，跨越松键前后的完整观察窗口。无踏板和半踏板在同次原生运行内对照；较深踏板的渲染验证使用上一轮已计算的控制轨迹作跨运行输入。三个成功场景各 15 个连续块，合计 **205825 个 float32 值逐位同**。初始窗口状态只读取一次，之后没有逐块重置为原生状态。

这仍不是完整音源：窗口从中途的 sample_counter=3264 开始，击弦源表及初始状态仍为捕获输入；动态音高/主机控制仍外置；完整琴槌接触力、带输入声部、音板与最终立体声混合尚未闭合。JavaScript 此轮输出的是模态组样本，没有生成完整钢琴 WAV。

## 实际连续验证

窗口为 counter=3264..4160，每块 64 样本、48kHz，覆盖松键和踏板抬起。这是约 20ms 的局部窗口，不是完整音符。

| 场景 | 对照方式 | 检查值 | 完整模态组样本 | 原生捕获 PCM |
|---|---|---:|---:|---|
| 无踏板 | 同次生产事件→释放→渲染 | 68417 | 2880 | 与原版基准同 |
| CC64=64 后抬起 | 同次生产事件→释放→渲染 | 68753 | 2880 | 与该刺激的原版基准同 |
| CC64=96 后抬起 | pass35 计算轨迹→新运行渲染 | 68655 | 2880 | 与该刺激的原版基准同 |

2880=15 块×3 组×64 样本，三场景共 8640 个完整组样本。检查数还包括每个 16/8-lane 子块后的部分累加缓冲、源表搬移、P/Q、能量、三角系数、归一化、R、A/B 等；没有将这些部分累加缓冲另算为完整声部输出。

成功捕获的实际原生进程都 exit 0，原生生成的 24-bit PCM 与相应原版 WAV 相同。这验证了这些成功捕获的原生输出，不能代替 JavaScript 最终立体声等价性。审计始终分别检查数值、完整窗口、原生退出及真实 WAV。

## 从自己的状态生成能量

新增 [modal-energy-pruning.mjs](../dsp/modal-energy-pruning.mjs)。真实 O+e4=2 的四-lane 路径，在下一次音高投影之前使用上一块末态：

```
d = fma32(-K, Q, f32(R * P))
o = f32(sinInverse * d)
E = fma32(Q, Q, f32(o * o))
```

乘法舍入位置重要：把 R*P 放在 FMA 乘法端、另先计算 Q*K，虽然实数代数相同，在 2495 个诊断样本中有 921 个位差；四-lane 原指令实际为 `fmul` 后 `fmls`，正确顺序 2495/2495 同。原失败诊断保留，没有采用浮点容差。

完整连续重放随后只从自己的 P/Q、旧 R/K/inverse 生成 E，不再将每块捕获 E 注入能量归一化。首块窗口状态仍来自原生观察，因此不声称已从零生成整个音符。

## 能量阈值、搬移和清零

`1008db8b0` 比较 E 与 float32(V+774²)。本次 V+774=9.999999974752427e−7，V+718=0，使用压缩槽位分支：低于阈值时取同组最后一个有效模态填补空位，再减少 count。

需要同时搬移的值包括能量、R、频率、J、基础衰减、K/S/inverse、位置权重、A/B 和 P/Q。原代码对末槽直接删除与搬移删除的缓存能量处理不同；实现保留该区别，而非简单过滤列表。

无踏板场景由自己的能量独立预测了三次压缩：

| counter | 被移除槽 | 填入的末槽 |
|---:|---:|---:|
| 3776 | 40 | 145 |
| 4096 | 133 | 144 |
| 4096 | 135 | 143 |

第一组 count 从 146→145→143。原生 layout 仅用作比较目标，下一块的布局、源表和模态状态都由自己的压缩结果传递。其它 keep-slots/freeze 分支虽有算术代码，本轮未动态覆盖；不能推广到所有模型与带输入模式。

## 释放到递推系数与组输出

新增 [damped-modal-refresh.mjs](../dsp/damped-modal-refresh.mjs)：自己的释放 rate/gain 参与基础衰减、位置权重与跨模态能量补偿，再生成有效衰减、R 和 A/B。四-lane 尾部和成对八-lane指数路径分别调用已恢复的原生数学实现。音高变化时也对自己的旧 P 作历史投影。

在 [连续重放器](../scripts/pianoteq_replay_release_render.mjs) 中，上一块自己计算的末态经过能量计算、压缩、投影、系数刷新后，进入下一块 16/8-lane 递推。每组从零累加到完整 64 样本缓冲，并核对真实 before/after 状态及实际输出。完整性检查要求全部块、每块全部子核及正确顺序，漏一个子核会被拒绝。

初始 F、J、衰减、位置权重和窗口状态仍取自首块观察；阈值、主机音高控制和释放多项式缩放也仍是输入。这是特定分支的数值闭合，不是所有预设、所有参数与完整瞬时接触模型的闭合。

## 跨线程观察与捕获失败

生产线程可能在当前渲染块的子核之间写入下一次挂起位置。本轮正常 PCM 运行中，生产累计计数与读取到的声部计数之差出现 448 和 512，不能固定按相同声部 counter 配对。无踏板与半踏板按记录到的生产事件顺序计算；完整调度机制及 pass34 异常 PCM 根因仍未证明。

本轮共七次调试捕获：四次原生正常完成（含首轮诊断捕获），三次停止。首次半踏板窗口边界还暴露捕获器保留旧线程上下文的问题，导致窗口外核误归前一块。修复为在渲染线程越过窗口时结束并清理上下文；重放器另要求全部预期子核，原错误记录不会被接受。

较深踏板两次跨线程捕获都未完成，保留日志和不完整 WAV。随后 worker 模式只设置三个渲染线程硬件点，正常完成；控制输入明确来自 pass35 的计算报告，其 `releaseControlsFromSeparateVerifiedRun=true`，不冒充同次线程关联。全体正式审计纳入三个成功场景和三次停止，结果仍为失败、3/6 通过。

捕获脚本为 [pianoteq_capture_release_render.py](../scripts/pianoteq_capture_release_render.py)。共享系数捕获器抽出只读快照函数，保留原 8/40 条观察限制，并增加 J、能量布局及阈值元数据。旧 pass11 的 48 条、8263 个有效 lane 重放仍全部逐位同。
