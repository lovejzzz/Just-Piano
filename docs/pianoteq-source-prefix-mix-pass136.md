# 采集阶段校正与存档分量混合（pass136）

2026-10-17。重新检查 pass135 的比较阶段，确认不能把 `695108` 读取的表称为未经处理的缓存。加入已有的独立分量混合计算后，五次击键、主次两路的幅度前两列全部相同；完整四表绑定仍失败。

## 为什么需要校正比较阶段

冻结的 `pianoteq_capture_excitation_slopes.py::capture_inputs` 从 scratch+0xb8 取得表指针。原始 ARM64 指令中，`692ffc` 入口保存该表，`6930ec` 对列数至少为2的表先跳到 `6937d8` 做分量混合，再返回 `6930f0`；之后还有位置修正等处理，才到本轮使用的权重采集点 `695108`。

这与 pass26 已恢复并验证的前缀相符。本轮使用缓存证据和不可变 ARM64 反汇编，没有取得新的 REA 查询或新的原生运行采集。

因此 pass135 的数值差异与拒绝结果仍有效，但不能仅据该中途快照推出“G 缓存本身随击键变化”。复制后的表可能已经被修改。频率、衰减和相位的差异来源尚未确定，不用这一阶段校正将它们全部解释为前缀处理。

## 实际重新计算

`pianoteq_audit_source_context.mjs` 新增显式 `--mix-archive <banks.json> <index>`。本次选择完整基础存档中的 NY Steinway index0（不是 pass26 的另一份存档 index11），读取 B2548 的两条三维曲线，自算混合系数，消费 pass110 C 的力度、attenuation、blendFloor、inputBlend。初始幅度仍来自 pass133 独立源构造器的归一化输出，不从目标幅度反推参数。

曲线普通线性模式仍为显式指定，未获得新的运行标志观察。其余三个数组原样比较；未实现的位置或其它中间变换没有补默认、拟合或从目标回填。

同一份完整 pass110 C 捕获 SHA 为 `845ecef901e2215062d7cae298bc6f232be44357a39cef07fb523bfc067a869f`。五次击键、每次两模式：
