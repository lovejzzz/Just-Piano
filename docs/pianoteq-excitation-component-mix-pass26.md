# 原始激励入口的分量幅度混合：pass26

本轮恢复 `692ffc` 入口的第一段跨分量振幅计算，并把系数输入从运行捕获替换为基础模型存档计算；没有把这一小段当成完整原始激励生成。

REA/Ghidra 的精确指令证据 `ev_0386f492c4467a5c0529dcc25621ea034df75c8e4c08dc1e25781de1017e01f2` 核对 `69382c` 的 float32 FMSUB；系数生产者 `676950` 的证据为 `ev_67a0e4081d560d90f6e5328bcba54bce4a971c8b324bc777b646525b771006a0`。其余运算次序与已保留的 `692ffc` 反编译及 ARM64 指令逐项核对。

## 系数由模型存档产生

`676950` 调用基础 B 对象的 `+2600`、`+2650` 两条三维曲线，按音高插值后逐分量限制在 0～1，写到运行 G+348/G+360。完整存档解析中，这对应 B+2548 version-14 复合字段的 `curves[2]` 和 `curves[3]`。

在 getter 返回后的 `676980` 单硬件断点读取真实基础曲线，捕获 note69、note80 各一组完整 X/Y 与运行标志：每条 X=11、Y=33、dimension=3、log-X=0、special=0。与 NY Steinway 私有基础存档 index11 的完整两条曲线全同，共176个坐标对照值。未将存档压缩标志误当作运行插值模式。

`archiveExcitationMixCoefficients` 使用既有 float32/FMA 插值实现，计算曲线并钳制。note80 在曲线非整节点处的实际两组系数为 `[0.09600000083446503, 0.04800000041723251, 0]`、`[0.12799999117851257, 0.08000000566244125, 0]`，预测逐位相同。验证器不再以捕获的 G+348/G+360 向量作为计算输入。

## 实际混合方程

`dsp/excitation-component-mix.mjs` 接受原始分量幅度表及已计算系数。以 `f` 表示 float32 舍入，`FMA` 表示一次融合运算：

```
b = max(inputBlend, blendFloor)
C[k] = FMA(A[k], f(1-b), f(B[k]*b))
p = f(velocity * f(1-parameter40))
x = f(2*p)                         if p < 0.5
x = f(2*f(min(p,1)-0.5))           otherwise
w = FMA(-x, x, f(x+x))
(lo,hi) = (C[0],C[1])              if p < 0.5
(lo,hi) = (C[1],C[2])              otherwise
u = FMA(f(1-lo), a[j], f(lo*a[0]))
v = FMA(f(1-hi), a[j], f(hi*a[0]))
aNew[j] = FMA(w, f(v-u), u)        for j > 0
aNew[0] = a[0]
```

每行分别计算，第一列不修改。这里的列是耦合分量；该算式本身不证明完整的瞬时弦位移反馈或琴槌接触力。parameter40 是调用参数结构 +40 的字段（H+2ff8），数学作用是降低 p；其界面语义尚未认定。捕获文件历史标签 `soft` 不构成 CC67 映射证据，公开计算接口使用 `attenuation`。

## 八个实际演奏案例

入口 `692ffc` 与该步骤完成的 `6930f0` 分别在独立进程放置一个硬件断点，只读内存。覆盖既有 A4/96、四音高/力度序列、A4/32、带 CC67 的 A4/96、note80/32。每例含主、次两路，共16次调用：**983个计算振幅全部逐位同**；同时对照2949个不应变化的频率、衰减和相位值，全部相同。两路合计96个存档到运行系数对照也全部逐位同。每个报告还重复核对176个完整曲线坐标，所以各报告总数不等于独立新增样本数。

低音 note21 的列数为1，直接保留原振幅；它没有被当作非平凡低力度混合证明。另用三列 A4/32 和 note80/32 验证 p<0.5 分支；A4/96、note60/64、note72/100、note108/127 覆盖另一分支及接近上限的 p。所有观察的 parameter40 都为零，包括含 CC67 的案例，因此非零 attenuation 尚未动态验证。

`scripts/pianoteq_replay_excitation_mix.mjs` 的存档验证用法：原前后捕获及报告路径之后增加 `--base-models <私有基础存档JSON> --base-index 11 --curve-capture <真实曲线runtime.json>`。四份正例报告全部通过；人为把 note80 输出的一个振幅改动相邻 float32 后，验证器 exit 1，恰好报告一处错误。

## 真实音频及剩余链条

全部运行正常 exit0、采集错误为空。A4 前/后、低力度与 CC67 序列前/后、note80 前/后及曲线生产者采集，PCM 都与对应原版基准逐字节相同。四音序列的入口采集也匹配已有原版重跑基准；步骤完成采集仍有18443个交错采样值相差、最大1个24-bit整数单位，与pass24保留的那份差异相同。未把它当作无扰动通过，未隐藏前轮的 A4 异常。

本轮只恢复原始激励入口的分量混合，尚未恢复 `692ffc` 后续所有振幅/相位处理、附加分量与重击状态反馈。因此这一步的计算输出还没有替换 pass25 的两路原始激励输入；没有用此前35907项连续渲染结果冒充这一步已经端到端接通。存档到初始模态表、硬度谱及此前最终表到连续渲染的模块仍保留，后续需要把中间缺口继续闭合。

其它模型版本、其它列数、非零 attenuation、非零 blendFloor 等未覆盖分支，以及网页最终声音和全部预设等价性仍未验证。商业曲线、原始模型表及反编译全文只保留在私有分析目录。

原始证据：`debug-pass26-mix-*`、`audio-pass26-mix-low-soft/`、`audio-pass26-mix-note80/`、`pass26-mix-coefficients.json`、`pass26-pcm-verification.json`。最终正例为各步骤完成目录中的 `archive-replay.json`。
