# pass52：64帧节点读出与现有目标相加

从外层九行时域输入计算64帧银行，再核对它如何写入三行目标缓冲：114次节点调用、342次逐行读取，62208项float32逐位同，2280项帧号、游标和时钟检查相同。前8192帧校准成功，完整原生PCM也与官方参考逐字节一致。

本轮确认该节点内部只有一个64帧银行，不能把它等同于整个CABN尾部分支。较长尾部仍需进入上层异步队列继续恢复。

## 直接从节点输入计算

[捕获器](../scripts/pianoteq_capture_convolution_readout.py) 观察 `7ccca0` 入口、`571fac` 逐行读取入口、外层返回以及末级立体声点 `1bc114`。初始核继续由pass49时域核证据计算；源矩阵是本次节点实际收到的九行64帧输入。

[重放器](../scripts/pianoteq_replay_convolution_readout.mjs) 自行推入1026行输入、执行114次编译计划、15000次乘加，计算全部三行读出块。其中335个块经过非空逆变换，七个启动空块也按旧历史读出、随后清空历史的规则处理。[银行模块](../dsp/partitioned-convolution.mjs) 新增完整读出块结果，不改变此前非空输出验证接口。

首次输入仍位于全局frame896，银行时钟0；末次块起点8128。入口与返回时钟均独立按64推进，逐行读取偏移均为0，与64帧银行每次重新准备输出的行为相符。

## 实际为相加模式

最初重放错误地要求复制模式，配置检查明确失败，原诊断保留。114次实际入口和342次读取的mode均为1。原生 `571fac` 调用加法helper，而不是覆盖目标。

[读出组合实现](../dsp/convolution-readout.mjs) 对本次已验证分支执行：

```
destination[i] = f32(existingDestination[i] + calculatedHead[i])
```

现有目标值仍是观察边界，不能由此称完整全局信号已独立生成。把它与九行输入逐行直接比较，没有得到稳定的一对一相等关系；重放没有据此采用猜测的干声映射。

本轮浮点检查包括144个初始化核的18432项、342个独立读出块的21888项、342个相加后返回块的21888项，合计62208项。342次读取均匹配自己计算的银行结果，而非把原生读出缓冲当作计算输入。模块中复制模式和非空后续银行相加分支没有获得本轮动态覆盖。

## 单银行节点与较长尾部的区别

实际节点的银行数为1、块长64、工作步数1。此前设想在这个节点内部直接读取较长银行的方案，不符合本次结构。

已有REA恢复的上层 `0ef37c` 代码另有队列处理路径：调用前段节点后，读取状态中的输入/输出链表，按游标复制输入并把队列输出加到目标，再处理已用完节点的回收。状态中的 `+0xf8`、`+0x100` 和 `+0x158` 是下一步需要动态绑定的队列位置及尺寸相关字段；本轮没有据静态代码宣称其计算已验证。

这使下一步的调查位置更明确：需要恢复上层队列与后台生产者，不能继续把单银行节点输出当作完整CABN输出。

## 实际音频及控制

原生进程39173正常exit0，无受限继续。最终立体声浮点块编码与同次WAV前8192帧一致，完整113152帧、48kHz、双声道24-bit PCM与官方参考相同，SHA-256为 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`。

七个负对照全部失败：读出比较目标、返回比较目标各改一ULP，读取偏移、返回时钟各改一个字段，以及现有目标单样本加0.125，分别恰好一项不匹配；把模式改为复制或删除一行读取则被结构检查拒绝。原始捕获不变，夹具明确重建SHA绑定。银行接口变更后，pass51的输出端回归仍通过。

完整WAV由原生程序生成；末级立体声浮点值仅用于帧校准。现有目标、编译计划、时域IR初始化及物理声源仍有观察边界。旧音频变体、较长分区/队列生产计算、完整琴槌—弦—制音毡耦合、全部预设和网页整段声音等价性仍未解决，尚未最终合并或部署。

私有证据为 `debug-pass52-convolution-readout/`、`pass52-*.json`，静态依据引用已有REA证据；仓库不包含原生二进制或预设资源。
