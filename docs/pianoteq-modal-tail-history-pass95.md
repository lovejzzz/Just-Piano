# 末四通道历史掩码：pass95

本轮定位并修复pass94长窗口中全部32处Q正负零位差。相同320块捕获现在744247项检查零差异，保留先前失败报告，不改变捕获、目标值、比较规则或窗口长度。

## 原因与修复

无输入内核的调用包装4903a4在4903f4..41c读取处理范围内最后一个四通道向量的P/Q，计算`abs(value)>float32(1e-18)`，再以比较结果做位与。常数字为`0x219392ef`。不满足严格大于条件时，位与结果是正零，包括负零和恰好等于阈值的输入。该掩码发生在**每块内核调用前**，仅作用于最后四通道，既不是初始化时执行一次，也不是清除所有模态的小值。

REA/Ghidra指令证据：`ev_e4b1da9af8f126e3ad581048b07271c2981f5f38137f5c7fab693d24dbeb1533`，不可变ARM64原件SHA256 `8e375ff63fcb9056ae1eadd9770d28a0a61c7d79209f52a74f027c3bc13c2094`。与独立静态LLDB指令核对，未启动新的原生音频宿主；新导出的证据包含357条记录。

先前实现正确执行了内核的FMA顺序，却漏掉了这个包装步骤。age8512时lane119的Q已经是负零；若下一块直接保留负零递推，输出波形仍相同，但后续padding历史的符号会不同。新增末向量掩码后，原生与自己的符号演变一致。没有把全部零统一化，也没有在比较器中忽略符号位。

`renderModalVoiceBlock`在每组的`start+ceil(count/4)*4-4`位置处理四个历史，再按原16/8通道顺序渲染。没有逻辑模态时不处理末向量；状态缺失或非有限仍拒绝。

## 同次完整验证

使用pass94 D次进程60154的原始完整捕获，不拼接、不重置自己的模态状态：

- 320块、20480帧、约426.67 ms，全部320次刷新及320个完成输出。
- 743577个float32、650个double、20个uint32，共744247项零差异。
- 61440个实际三组缓冲采样逐位同；90次删模态；28个组/块执行十二模态尾部。
- 实际经过releaseShape=1.2750000953674316的频率分段释放分支，以及gain归零后归一化字段保留路径。
- 原8块50173项、64块205703项回归均通过。64块的110项反向扰动再次全部被拒绝。

另外9项长窗口反向扰动全部拒绝：单改一个完成输出、一个Q目标、归一化目标、以及把age8576/lane119的原生负零目标改成正零，各只报告一处差异；改变十二模态尾部附近的音高源、释放形状或频率下限，会破坏后续独立轨迹；删除末尾输出或刷新则被完整性检查拒绝。没有在失败基准上统计反向测试通过。

## 刷新观测缺口仍需动态验证

静态472f40..4c表明6e4f5c的返回值决定是否置V+80c控制变化标志；6e4f5c本身包含浮点变化比较与提前返回，不能先验要求每块都重建系数。该证据提供了调查pass94 B次末尾两个刷新缺失的方向，但尚不能单独证明B次具体执行了哪个分支。B次仍保留`complete=false`，未补造刷新或改成通过。

## 与最终目标的距离

本次新增的是内部长窗口状态与输出一致性证据，没有新增浏览器最终立体声WAV通过结果。原生完整PCM对照的失败仍见pass94。预权重模型表、部分控制及起音系数等仍有观察输入，完整琴槌/弦/制音毡耦合、全部预设及网页声音等价性尚未完成；本轮不合并或部署为完整复刻。
