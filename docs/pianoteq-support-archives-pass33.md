# 追加模态存档表与实际谱修正：pass33

本轮消除追加阶段对八张最终运行表的直接输入依赖：从解码模型生成两组频率、基础 dB 谱及衰减表，执行真实的频率编辑修正、模态参考归一化，再将计算表传入普通和重复击弦链。编辑曲线、模态模板及归一化输入仍捕获，没有把这部分冒充完整存档自生成。

## 存档来源和运行模式

REA 新分析 `38dbd8`、`1c2e94`、`2ecd44`、`8c1888` 确认这些曲线均由向量求值器按 mode3 求值。第二组仅在 B1320 非空 X 范围内启用，范围端点带 float32 1e-5 容差；本模型74..108启用、109不启用，第二组衰减表仍独立求值。第一组可在边界外钳制。

新模块 `dsp/support-archive.mjs` 从档案取表、按音高插值，不嵌入商业模型数值。当前最终桥接限定实际 supportScale=1；mode3 下其它频率缩放尚未验证，验证器会拒绝以它们套用本批结果。

## 两步额外谱修正

基础 dB 不能直接乘 ln(10)/20 当成最终表。`765f20` 先执行：

```
frequency = f(referenceFrequency * frequencyMultiplier)
x = nativeScalarLogf(frequency)                 // frequency > .001 时
edit = editFlag & 1 ? editCurve(x) : 0
correction = FMA(f(1-blend), baseCurve(x), edit)
correctedDB = f(rawDB + correction)
```

曲线使用已验证的普通标量求值次序，logf 使用已有原生算术恢复。实际记录 editFlag=1，blend=1；因此编辑曲线为非零正例，基础曲线权重此批为0。不能据此声称非恒等 blend 已完成真实验证。

`51af20` 再生成一条模态修正曲线：取模态频率矩阵第一列，最多 `min(matrixRows, correctionLength+1)` 个节点；Y来自对应修正向量，末尾不足项为0。参考 dB 为 `f(20*log10f(referenceAmplitude))`（参考0时为-1000）。每个追加频率倍率 m 在 `f(max(m,1)*firstModalFrequency)` 查询该曲线，将 `f(curveValue-referenceDB)` 加到低、高两张 dB 表。

这里用 compact scalar 的**边界模式0**：多节点曲线范围外返回0，并非边界钳制；区间内是 reciprocal-then-multiply 与 FMA。这个区别已覆盖高频追加模态。完成后按 float32 常数 `0x3debc8e3` 转为自然对数谱。

本批 log10f 显式使用 `float32(Math.log10)` 候选，实际全部输出吻合；通用原生标量 log10f 仍未移植。编辑曲线、模态频率矩阵、修正向量和参考幅度还来自运行时，这是后续需替换的输入。

## 实际验证及接链

真实输入/返回观察点分别是 `765f20`、`51af20` 和其公共返回指令 `51b1ec`。过滤实际调用来源，覆盖21、60、69、72、74、80、108、109八个音符、两族、三次构建：96条频率修正输入、48条归一化输入和48条返回记录，全部正常 exit0、无读取错误。

不同运行的全局构建次序有37个位置不同。因此验证按音符、模态族及该组出现次序配对，而不按整个文件的全局序号误配；每项数值比较仍要求逐位一致。

- 存档与运行曲线只计算一份绑定的8700个 x/y值，其它5份绑定要求完整一致，不把重复曲线当作独立模型。
- 存档 → 两次谱修正 → 运行表的普通四音域报告 **13792次float比较，0差异**；其中8700项为档案曲线绑定。默认A4报告13288项，重复部分不能相加。
- 计算出的八张表传入普通A4追加链1646项同，四音域8864项同。
- 再传入快、慢重复击弦链，各12649项同，保持四次连续历史更新；最终追加表不再是外部输入。
- 将一个归一化返回值改动一单位float32的负例，准确报告一处差异并退出1。
