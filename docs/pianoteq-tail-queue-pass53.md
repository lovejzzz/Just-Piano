# pass53：512帧队列消费与非零尾部相加

把上层 `0ef37c` 的前段结果、512帧队列和实际返回接在同一次捕获中：128个64帧外层块、114176项float32逐位一致，2256项游标、形状及指针连续性检查相同。尾部源在104块中非零，首次位于全局frame1536的第三行。完整原生PCM与官方参考相同。

尾部样本仍由原生工作线程提供，工作线程的卷积生产计算尚未恢复。本轮计算的是前段、队列写入、游标推进及尾部相加，不能称完整CABN或浏览器声音已经独立生成。

## 观测位置与实际队列形状

[捕获器](../scripts/pianoteq_capture_tail_queue.py) 使用四个主线程固定硬件点：`0ef37c` 入口、`0ef75c` 队列消费前、`0eff54` 返回前、末级立体声 `1bc114`。同次前8192帧最终浮点块编码与WAV相同，保持了全局帧校准。

本次状态始终满足：输入增益状态 `[1,1,0,0]`、相加模式1、队列块长512。输入块九行，输出块三行，行距512；每次消费64帧，两边位置同步按 `0,64,…,448` 推进。块耗尽时，当前指针跟随记录的next；本窗口16次next均为空，实际返回指针也都为空。尚未验证后台所有权和完整空闲链回收。

## 前段计算与相加

[重放器](../scripts/pianoteq_replay_tail_queue.mjs) 复用pass52已绑定的头部配置和时域核证据，从本次九行源样本重新计算前段。配置文件、核绑定和原时域捕获的SHA-256必须相符。

pass52观察到初始静音段跳过前段节点；本重放从frame0模拟静音输入，随后连续执行128次银行计划。只比较函数输出，不宣称内部对象游标与跳过优化后的原生状态逐字段一致。全部前段结果仍与本次队列入口的实际目标逐位吻合。

相加分两步进行：

```
headOutput[row][i] = f32(existingDestination[row][i] + calculatedHead[row][i])
result[row][i] = f32(headOutput[row][i] + queuedTail[row][i])
```

队列尾部为零时也执行加法，保留原生浮点零符号行为，不改成跳过零源的捷径。[tail-queue.mjs](../dsp/tail-queue.mjs) 实现九行输入写入、512帧分包和三行尾部相加。

| 本轮浮点比较 | 项数 |
| --- | --- |
| 单位输入增益状态 | 512 |
| 自行计算的前段结果 | 24576 |
| 加上非零/零尾部后的返回 | 24576 |
| 尚未完成块的输入写入片段 | 64512 |
| 合计 | 114176 |

现有目标、物理源输入、编译计划与尾部源样本仍有观察边界。复用配置是跨运行初始化，不是本次重新恢复了预设生成核的过程。

## 完整块交接的验证缺口

每八次写入产生一个九行512帧包，本窗口共16包。重放保存每包的float32原始位及全局范围，供后续与工作线程入口直接比较，负零不丢失。

112个未完成块的64帧写入片段与原生逐位相同。16个块完成点可能已把存储交给工作线程，本轮刻意不在返回时读取其输入数据，防止把异步所有权变化当作稳定快照。**每包最后64帧的原生写入尚未直接核对，下一步必须在工作线程入口比较完整512帧包。** 保存了计算结果不等于交接验证已经完成。

## 真实音频与负对照

原生进程41495正常exit0，无受限继续记录。完整113152帧、48kHz、双声道24-bit PCM与官方参考逐字节同，SHA-256为 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`。WAV仍由原生程序生成；最终立体声观察只用于帧校准。

八个负对照均失败：前段目标、返回目标、已复制输入目标各改一ULP，尾部输入单样本加0.125，输出游标加64，回收尺寸加一，分别恰好一项不匹配；删除队列阶段被结构检查拒绝。将全部尾部源置零产生18330项返回差异，证明非零尾部实际参与计算。原始捕获不变。

下一步是完整包与工作线程入口的字节比较，以及工作线程的较长FFT、分区状态和核计算。旧音频变体原因、全部物理参数/预设、完整琴槌—弦—制音毡耦合和网页整段声音等价性仍未完成，尚未最终合并或部署。

私有证据为 `debug-pass53-tail-queue/`、`pass53-*.json`；本轮动态验证沿用已有REA对队列函数的静态依据。
