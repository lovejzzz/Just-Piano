# pass62：独立后处理生成完整立体声PCM

本轮从观测的内部源开始，独立计算整条已恢复的后处理，生成完整113152帧、48kHz、双声道24-bit WAV。其PCM与同次原生输出、既有官方参考逐字节一致，SHA-256均为：

```
1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6
```

这次WAV由JavaScript计算样本并编码生成，没有复制原生最终浮点或PCM。但输入声部/支路与IR时域初始化仍观察，不能把它称为完整物理模型或网页音源已复刻。

## 接通的计算链

[重放器](../scripts/pianoteq_replay_stereo_chain.mjs) 在同一次原生运行中接通：

1. 两行全局路由源→自行维护延迟缓存→三行输出，与观察的三行支路按float32相加。
2. 计算出的三行既有目标，加上自行生成IR频谱并持续推进的64帧头部和512帧尾部。
3. 卷积结果与观察的另一三行辅助矩阵按float32相加。
4. 三路空EQ、当前干声房间增益、三行到立体声的路由缓存及固定输出音量。
5. 已恢复的float→signed32→24-bit封装，写出完整WAV。

新增 [DryStereoPost64](../dsp/dry-stereo-post.mjs) 实现第3、4步，复用此前验证的滤波、房间、路由及音量内核。所有控制种子来自本次原生状态，没有从旧运行代入固定增益。

空EQ的初始gain=0、updating=1，level为 `[1,1,1,0]`；独立状态首次使用时取当前level=1并清除更新标志。房间无卷积对象、外部源或空间tap，湿增益全零，三行干增益为 `0.5233637690544128, 0.42480674386024475, 2.579881429672241`。末级音量为 `0.15848931670188904`，无活动斜坡。

立体声路由种子已逻辑空、两环读头0、懒清空标志全15。原对象resetPending=1，但本次重置不改变这个逻辑空初态；独立缓存数据由零与自己的写入生成。三行房间输出扩为八行时，另五行独立置零。此配置不覆盖活动FX、非空EQ、湿混响或活动AntiClick/音量斜坡。

## 同次四点与真实时间对应

[采集器](../scripts/pianoteq_capture_stereo_chain.py) 使用初始化复制 `2a4334`、全局路由前 `6c2fd4`、卷积入口 `0ef37c`、最终音量后 `1bc114` 四个主线程硬件点。

在卷积入口通过真实调用栈的 `1bbce4` 帧识别M，验证九行源头确实是工作区B+0x288，再读取B+0x120辅助矩阵。首块读取真实滤波、房间和立体声状态，后续各块独立传递自己的历史；实际末级浮点仅用于比较及WAV时间校准，不进入计算输入。

采集1768个64帧块，完整覆盖113152帧。每块原生末级浮点独立编码后与同次WAV的对应绝对帧一致，零时间校准差异；独立生成的立体声浮点也逐位相同。最终编码长度必须同时等于原生和官方参考的完整PCM长度，没有截成更短前缀通过。
