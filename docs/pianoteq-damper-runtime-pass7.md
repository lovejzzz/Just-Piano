# 制音释放和位置权重：第七轮运行数值验证

本轮在用户授权的独立调试副本上使用固定硬件断点，未修改原程序、指令、寄存器或参数。释放单断点运行取得 8 组输入与输出，按原指令的 float32/FMA 顺序独立验算，**24 个输出分量全部逐位一致**。位置单断点运行取得 57 个模态权重，独立标量计算最大绝对误差 **5.960464477539063e−8**。两次单断点渲染均正常退出，PCM 与相同输入的官方原版逐字节相等。

这填补的是释放状态到衰减参数、制音位置到模态权重的数值验证；不是完整毡接触力或琴槌—弦反馈的恢复。

## 输入和采集位置

版本为 Pianoteq 9.2.5 ARM64，代码段 SHA256 与第六轮一致。使用本机已验证的 `audio-pass3/verified-rest/damper_position_0.75.fxp` 和 `audio-pass5-dry/cc0_A.mid`：A4、力度 96、CC64=0、0.5 秒按键、0.9 秒松键。CLI 设置为 `--headless --no-prefs`、48 kHz、24 bit、dither OFF。

预设文件名中的 `.75` 是接口控制值；不是内部位置值。本次实际 `V+8d4=0.21916981041431427`，大于额外曲线分支的阈值 0.125。

- `1006e5344`：释放活跃分支写入 `V+944`、`V+7e4`、`V+7b0` 之后，`x19=V`。
- `1002890f4`：位置权重计算结束，`x19=V`。

采集脚本先验证 ARM64 `__text` 的 SHA256，版本不符即停止；只读字段和内存。首次执行因 LLDB 不接受带连字符的模块名，在启动被调试程序之前失败；脚本改为下划线命名后正常运行，原失败日志保留。

## 释放公式与实际数值

令 `fl` 表示 float32 舍入，`fma` 表示单次舍入的 float32 乘加。读取 `u=V+8cc`、`x=V+8c4`，按执行顺序计算：

```text
h = fl(x * fl(x*x))
z = fl(h * V91c)
r = min(u, fl(1 - clamp(z, 0, 1)))
r2 = fl(r*r)
q = fl(r2*r2)
t6 = fma(V958, q, V954)
t5 = fma(q, t6, V950)
t4 = fma(q, t5, V94c)
D = fma(q, t4, V914)
V944 = D
V7e4 = fl(double(V910) * K / double(D))
V7b0 = max(fl(fl(1-u)*V90c), fl(h*V920))
```

`K` 的 double 位模式是 `0x3fbd791c5f888823`。不能把中间计算全部改成 Python double，也不能将原指令的 FMA 拆成两次 float32 运算后要求逐位一致。

本次常量为 `V914=0.48124998807907104`、`V94c=25`、`V950=75`、`V954=0`、`V958=900`、`V910=85.81991577148438`、`V90c=V920=6.75`。

| u | V944 | V7e4 | V7b0 |
|---|---|---|---|
| 0.8685315251350403 | 133.35792541503906 | 0.07408920675516129 | 0.8874121904373169 |
| 0.4741261303424835 | 1.9419645071029663 | 5.087828636169434 | 3.5496487617492676 |
| 0 | 0.48124998807907104 | 20.53066635131836 | 6.75 |

全部 8 组、每组三个输出通过内存 float32 字节比较。**本次所有 x=0**，因此没有动态验证 `h` 的非零分支；上述分支公式仍以原指令证据为依据。也未覆盖踏板中间位置、其它琴键和其它预设。

## 位置权重

在本次 `p>=0.125` 分支：

```text
s = fl(double(p) * (2*pi) / double(V918))
e = fl(-1 / V908)
w_i = fl(-cosf(fl(f_i*s)) * expf(fl(f_i*e)))
w_i = 0 if j_i > float32(N-1)
```

实际 `V918=439.7203369140625`、`V908=4250`、`N=26`。从三个分组各读取至多 24 个活跃数组元素，共 57 个；其中包含被索引掩码置零的元素。第一个元素频率 `439.7203369140625`，权重 `−0.17358119785785675`，独立计算相同。

原程序使用 SIMD 数学辅助函数，独立验算使用标量 libm 并保留 float32 乘法舍入。最大绝对误差 `5.960464477539063e−8`，符合本次验算预先使用的 `2e−7` 上限；没有将这种接近误称为全部位级相同。`p<0.125` 的附加曲线本轮未覆盖。

## 实际音频及失败对照

每个 WAV 为双声道、48 kHz、24 bit、249856 帧。原版重复渲染、不设断点的调试副本、仅释放断点、仅位置断点，PCM 均相同：

`SHA256(PCM)=b2c0211fad451a0907323f4092485da8c982387c6a7fbb85e51bd545fb2eb1a6`

先前同时设置两处断点的运行也正常退出，7 组释放输出的 21 个分量全部逐位吻合，但音频未通过逐字节检查：首个差异位于第 43609 帧，归一化 PCM 差值 RMS 为 `7.87414335053616e−6`，最大绝对差 `0.0002391338348388672`。原因尚未确定，不能将其归咎于随机效果或称为无扰动采集。随后拆分断点的两个成功对照保留了数值采集，也通过 PCM 检查。

## 复现与证据

公开脚本：

- `scripts/pianoteq_damper_runtime_capture.py`：LLDB 导入；设置 `PIANOTEQ_CAPTURE_DIR` 为新目录，`PIANOTEQ_CAPTURE_KIND=release` 或 `position`。选择已授权、独立准备好的调试副本后导入脚本，再执行正常 headless 渲染，结束后调用模块的 `save()` 保存最终命中数。
- `scripts/pianoteq_verify_damper_runtime.py`：接受采集 JSON，使用系统 C `fmaf` 独立验算；`--require-kinds release|position` 支持拆分采集，`--observed WAV --official WAV` 检查真实 PCM。任何要求的验证未通过均以非零状态退出。

原始证据根目录为 `~/.local/share/just-piano-analysis/runtime-damper-pass7/`，包含导入失败日志、双断点采集、原版重复与副本对照、两组单断点采集、全部 WAV 和逐项验算 JSON。原版二进制、FXP、WAV 和原始内存记录不放入公开仓库。没有使用 Pedalboard。
