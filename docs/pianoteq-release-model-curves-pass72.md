# pass72：实际模型曲线到释放参数

本轮在正常运行、音频设备running的独立调试副本上，读取真实模型曲线，计算105个键的三个释放字段。**630项float32逐位相同，12项负对照全部拒绝。** 这补上pass71尚未取得的曲线→packed→运行时参数活动证据；曲线本身的模型生成、非恒定释放曲线和完整耦合仍未完成。

## 调试启动失败与实际附加采集

本轮直接调试启动两次均在采集前被Pianoteq拒绝，进程12295/14110 exit1、warning `[B6D907A6,94JO]`。第二次已从分析目录启动；不能将问题归因为工作目录，也没有继续循环重试。

控制实验：原版与已重新签名副本，均在**不带调试器**的CLI下正常exit0，使用既有dry预设/MIDI时完整113152帧PCM都与原参考相同，SHA256 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`；副本codesign严格验证通过。证据说明普通启动可工作，调试启动被拒绝，但未确定原生拒绝检查的具体原因。

随后正常启动本轮拥有的、`--no-prefs --serve 127.0.0.1:8172`副本进程16183，通过正常Devices界面选择系统默认输出，API读回MacBook Pro Speakers、48000Hz、512帧且status=running。只读LLDB附加成功；没有改动检查或程序字节。

[附加采集器](../scripts/pianoteq_capture_attached_release_curves.py)仅使用 `100730884` / `100730898` 两个固定硬件站点，运行时交替启用一个，读取复制前后字段。没有新函数入口点、目标函数调用、表达式注入、目标内存写入或Pedalboard。

通过官方`loadPreset`载入NY Steinway D Mix。同一参数配置没有重建packed表，两个站点未命中；随后正常API将Last Damper从0.7109375（91）改为0.5（64），实际触发构造函数。105行全部采集完成，无错误、pending为空，两个站点各105次命中并均已关闭，随后成功detach。采集发生在实际工作线程118356956，不依赖GUI主线程假设。

最初后台启动的GUI实例15765没有留下活动监听器或采集数据，未用于验证。前述两次失败启动脚本/空捕获和该诊断均私有保留。正常GUI退出请求已通过拥有者PID/监听器校验；进程终止后执行会话返回−1，**不声称此次GUI会话exit0**。后述独立读回与音频CLI均明确exit0。

## 同一模型对象与曲线

从复制构造函数的实际调用栈读取调用者x22，验证返回地址 `1003d2a70`。其虚表首项实际指向 `1001f0188`：

```
ldr x0, [x0, #0x118]
ret
```

采集器读取并验证这两条指令的字，按它们表达的成员地址读取base对象，不执行getter。REA独立恢复同一访问式，证据 `ev_4b0212faf692efdfe587720a6739265676550dde66b9e44f487a73fee59f2475`。

| 实际曲线字段 | X坐标 | Y端点 | packed→运行时偏移 |
| --- | --- | --- | --- |
| base+3c28：T0 | 21,108 | 两端均f32(0.01) | c→38 |
| base+3c78：T1 | 21,108 | 两端均60 | 10→3c |
| base+3cc8：k | 21,108 | 两端均1 | 14→40 |

三条实际dimension=1、log_x=0、special_mode=0。输入是packed存储音高9..113：86个键在两端点之间，19个在边界或外侧。全部记录的同组source/target地址按0x38/0x140连续，来源模型、packedOwner、工作线程和音高映射均验证。

[曲线重放器](../scripts/pianoteq_replay_attached_release_curves.mjs)复用已有 [linearModelCurve](../dsp/model-curves.mjs)，使用实际runtime flags建立linear-clamp模式，执行float32直接除法和FMA次序。没有再新增重复的曲线数学模块。三个插值结果分别比较packed源与实际写后字段，105×3×2=630项。源曲线是观测边界；packed与runtime值不回填计算。

这是常量端点曲线的活动证据，不能因为执行了86次内部区间插值，就声称非恒定释放曲线、log-x、特殊模式或全部预设已验证。UI Damping Duration在此模型显示0.70，而键T0为0.01；不能直接把这个UI显示值当成键的释放推进时间。它们的生成关系仍需进一步恢复。

12项负对照：分别将T0/T1/k第一端点翻倍，各产生198项差异；packed或runtime的单项目标扰动各一个差异。错误getter指令、log/special模式、非递增坐标、存储音高、目标地址和缺失记录均严格拒绝。

## 保存读回与真实音频

采集后用官方API保存当前完整预设到本轮唯一临时bank，复制到私有分析目录后删除该临时bank文件。没有改用户预设、原应用或持久偏好。对比本轮载入后的215项参数，只有Last Damper从91变64；新原版进程读回全部215项，零差异，正常exit0。

原版和副本随后用这个同一保存文件及原MIDI分别进行普通CLI渲染，均exit0；完整1066752帧、双声道24-bit/48kHz PCM逐字节相同：

```
94ba1efa451669d47b62965e4629db589f45a65809f97afbd4bb3b9404457424
```

另用原版工厂NY Steinway D Mix渲染同一MIDI作实际干预比较，正常exit0：工厂基线134144帧，Last Damper64版本1066752帧；共同268288个交错样本有266372个不同，RMS差0.03027359772172668，首差frame919。波形确实改变，并非只改变API显示。差异在松键前已经出现，不能将此实验解释为仅有一个释放包络变化，或据此反推出完整接触力公式。

以上音频是两个**原生程序**普通渲染的对照。附加采集不是离线音频窗口，未把pass71旧运行与本次曲线拼装成“同一次完整声音验证”；630项也没有冒充新的480万项全链检查。尚无从这些模型曲线独立生成的完整WAV或浏览器声音等价证明。

REA累计331条证据已导出、保存快照并关闭。一次大函数查询触发MCP完整响应大小限制，证据保留后通过分页读取；未把传输限制当成无代码证据。私有材料：`rpc-pass72-curve-source/`、`audio-pass72-saved-model/`、`audio-pass72-unmodified/`、`audio-pass72-debug-copy-unhosted/`、两份失败调试启动目录和`pass72-*`。不提交目标曲线、预设或WAV。
