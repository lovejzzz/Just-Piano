# pass123：声源偏移缩放不再读取外部powf结果

完整复刻尚未完成。新E仍挂在调试器启动，未产生新的原生观察或音频。本轮复用已经保存的初始化记录，将pass70恢复的系统scalar powf接入更早的声源准备路径，移除该路径对外部powf结果的计算依赖；没有把旧原生PCM称为新模块生成的音频。

## 计算依赖的变化

`prepareModalInputs`原来仅能自行处理频率比为1或指数为0的情况，其他情况要求调用者提供offsetScale。现在默认调用`modalOffsetScale`，先按float32计算frequency/440，再用已有`nativeScalarPowf`计算幂值，直接生成scaledOffsets、耦合端点及其后续输入。

保留显式offsetScale作为旧诊断接口，但返回offsetScaleComputed=false。两个声源验证器均要求该标志为true，不再把校准文件里的result传入准备函数；该文件只作为输入身份/结果的比较目标。报告区分nativePowfOracleRequired=false与powfValidationOracleRequired=true，避免把“验证仍需要对照记录”误写成“计算仍读取对照结果”。

本轮没有重新实现powf或改其数学常数，没有用Math.pow替代它。scalar powf的恢复及既有系统对照范围见pass70；这里不作全浮点域或所有平台等价声明。

## 系统数学对照与反向验证

新增独立核对器，对已有调律报告的105个频率及基础存档的偏移指数，比较默认准备函数所用的偏移缩放与自编C程序直接调用本机系统powf的结果。105项零差异。本组直接Math.pow候选亦零差异，因此不能拿这105项声称候选在一般范围已被排除。这只是系统数学对照，不是105个音符的Pianoteq音频验证。

五项针对原始初始化记录的反向验证均符合预期：

- 改note70校准文件的powf结果并保持位字段一致：恰好一项powf比较差异，全部耦合输入预测不变。
- 改A4极点校准文件的powf结果：恰好一项powf差异，lambda、中心、频率和衰减的预测及比较结果均不变。
- 校准结果与位字段不符：明确拒绝。
- 删除一个耦合调用：140个剩余输入虽相同，仍因缺少第36次调用失败。
- 重复一个耦合调用：明确拒绝，不以重复补覆盖。

原始校准文件和捕获摘要在测试结束后不变。新增公开单元测试确认默认路径确实生成并应用缩放、指数变化会改变缩放后的偏移、旧诊断覆盖显式标记，以及无效输入拒绝；已加入npm test，整套通过。
