# 五声部连续计算与实际分轨音频：pass97

本轮把首声部窗口扩展到同次实验中五个声部的全部已捕获工作线程块。独立计算与原生内部组输出逐位相同，并首次将这些自算组输出导出为实际WAV。它们仍不是最终音板/麦克风/立体声输出；完整琴槌—弦—制音毡耦合与全部预设仍未完成。

## 真实计算中修正的三个细节

1. **删模态后保留尾槽A/B。** 8db8b0复制末槽A/B到空位；尾槽自己的A/B保留。清零的是O+30的输入耦合权重及P/Q，而不是O+8的递推系数。先前每块立刻刷新掩盖了这个错误；长时间跳过刷新后才出现148个A及148个B目标位差。`modal-energy-pruning.mjs`现保留原尾槽A/B，辅助数组仍按原顺序交换。
2. **零释放增益也会延后生成位置权重。** 43dcb0将V+926清零，并用`((noteIndex XOR 0x3a9) % 40)+8`初始化V+92c；6e4f5c逐块递减，倒计时结束而权重尚未生成时调用288f38，该函数生成权重并置V+926。A4的模型noteIndex=69，公式得12，故第五声部age768首次生成权重。之前漏掉该路径，前段诊断出现1247处权重位差；没有按观察到的age768硬编码。新增`positionWeightWarmupBlocks`从源noteIndex计算当前MIDI范围的倒计时。当前固定位置分支中，首次到期发生在已观测的真实刷新点；其它控制/调度组合未据此宣称覆盖。
3. **全空声部跳过延迟尾部搬运。** 4e2c84..2cb8清空输出后跳到4e37b4，避开起音、内核和延迟搬运。若仍将前一块尾部搬进来，就会在声部3的age30400和声部4的age27840多出24+8个实际音频采样。当前全空分支直接输出零并保留原尾部，不推进起音状态。部分组为空而其它组仍活动时，原传输顺序继续执行。

空模态组现在可与非空组共同参与衰减刷新；全部组为空仍不作为正常系数刷新输入。没有以容差、目标状态重置或删去失败采样修复上述问题。

## 严格结果与反向测试

5075354个float32、4114个double、20个uint32，共**5079488项零差异**，包括643200个实际内部输出采样、3350次块后状态、666次删模态及1076个十二模态尾部组/块。前段诊断明确`diagnosticOnly=true, passed=false`，原1543处缓存位差及后续32处音频差异报告保留；它们没有被当作完整通过。

12项新反向扰动全部拒绝：单改声部1输出、声部2块后Q、空声部零输出、跳过刷新时的Q或A，各只检出一处位差；改变非零延迟源、源noteIndex，删除块后状态/输出/控制决定/中间块，或截去第五声部末块，也均拒绝。改变noteIndex同时影响起音和权重倒计时，该用例不冒称只隔离验证后者。原384块模式严格回归通过。

报告区分`sampleAge`、`readyAge`与真正最近一次刷新的`coefficientAge`，不把跳过后的可渲染年龄误称为系数生成时间。全声部模式也不再把默认8块参数显示为实际验证窗口。

## 独立生成的音频文件

重放器接受可选的`--worker-stems=新目录`。只有完整验证通过且为工作线程输出模式时，才由自己在内存中的计算样本生成15个单声道IEEE float32 WAV；无归一化、无裁剪，不从原生矩阵写音频。每声部按自己的连续计数拼接三条组分轨，manifest保留帧数、峰值、RMS及PCM SHA256，并明确`finalStereo=false`、观察模型/控制输入仍存在。

另一个Python读取器独立解析RIFF/fmt/fact/data，逐字节比较这些文件与同次原生工作线程矩阵：15个文件、643200个float32 PCM全部相同，包括浮点位模式。它还核对48kHz、单声道、32-bit float、帧数及SHA256。分轨是实际自算音频，不是把原生WAV复制后改名。

完整原生WAV仍只有143360帧，参考为148224帧，长度严格检查失败，PCM SHA256为`680cccc3dd6759128a328bd666bf6764c95ab590e5fdd8609ce7f2648e4f63d8`。内部单声道组分轨通过不能替代最终立体声WAV通过。
