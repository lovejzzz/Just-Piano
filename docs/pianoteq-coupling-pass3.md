# Pianoteq 9 耦合追踪：第三轮

分析目标为已安装 9.2.5 的 ARM64 副本。这里将算术证据与物理身份分开；未把通用合成器的约束更新冒称为完整钢琴琴槌—琴弦—制音器系统。

## 非线性记录的准确逐样本语义

重新逐分支核对 `FUN_1004e285c`，可进一步明确 [上一轮状态递推](pianoteq-state-recurrence.md) 中的非线性部分。设容器为 V、模态状态对象为 O。记录数量在 V+0x260，记录内嵌于 V+0x268，步长 0x70。仅当 V+0x718 的首字节为 1 时进入此路径。

| 记录偏移 | 此使用处的作用 |
|---|---|
| +0x00 | 已达到阈值的持久标志 e |
| +0x04 | 修正增益 g |
| +0x08 | 激活阈值 a |
| +0x0c | 较早的历史值 h0 |
| +0x10 | 较新的历史值 h1 |
| +0x14 | 本样本修正幅值 f，先清零 |
| +0x18 | 观测权重 w 的向量首地址 |
| +0x40 | 反馈权重 v 的向量首地址 |
| +0x68 | 归一化比例 r |

二阶线性递推已经先更新 Q（O+0x80）。随后每条记录计算 `d = Σ w_i Q_i`，限定在当前模态组的处理区间。按以下分支执行：

```text
f = 0
if d >= a:
    e = 1
    next_history = d
else if e == 1:
    f = g * max(0, (h0 - d) * r)
    Q_i += v_i * f
    next_history = h0
else:
    next_history = d
h0 = old(h1)
h1 = next_history
```

这里的两个细节影响重建结果：

1. e 在此分支内只被置为 1，没有在 d 下降时自动复位；外部复位时机尚待追踪。
2. 多条记录顺序更新同一 Q。后一记录读到前面已经修正的状态。并非先同时求出所有力再统一求和；修正分支保存的历史值也不是重新计算的 `w·Q`。

此更新包含门限、记忆及状态反馈，已经是确切非线性计算。它没有直接给出 felt 压缩幂律、接触质量或可识别的 SI 单位，因此不能把 f 称为牛顿、把 d 称为米。其代数形状与单边约束投影相容，但“制音器/琴槌”身份仍缺生产者证据。

代码中无状态区间时存在独立分支，可产生 f 和历史更新但无 Q 写回；不能把该分支简单删除。输出在此模式下重新对 O+0x58 的历史状态使用 V+0x6f0 权重求和，而不是直接输出本次修正后的 Q。因此也不能将这一路输出当成直接接触力。

## 权重生产中的加权正交化

在 `FUN_100863008` 中，反馈向量不是总等于原观测向量逐项乘 H。对多条记录，先进行一轮加权正交化，然后才乘 H。设原始观测权重为 w_j、临时反馈方向为 b_j，处理区间内的 H 是上一轮已恢复的对角向量：

```text
b_j = w_j
for k = 0 .. j-1:
    c = Σ_i b_k[i] H[i] w_j[i] / Σ_i b_k[i]² H[i]
    b_j -= c b_k
# 所有记录均做完上述步骤后：
v_j[i] = H[i] b_j[i]
r_j = 1 / Σ_i H[i] b_j[i]²
```

标量循环明确给出分子、分母、减法和最终权重写入。分母为零会走断言路径。数值计算使用浮点及 SIMD 展开，以上为数学表达，不保证逐位等价。尤其较大 SIMD 分支的反编译存在 load/store 顺序表达不清的现象，真正逐位复现还需该段汇编核对。

这比单条记录的 `v=H w` 更完整：首条记录恰好没有投影，后续记录先减去此前方向的分量。由此可以解释为何渲染期按记录顺序反馈，而不是把原观测权重当成独立接触点直接相加。此代数解释仍不确认物理接触点的位置、质量、刚度或所属乐器。

补查 `FUN_10037c6b4` 排除了一个错误方向：它只用 `__cxa_guard_acquire/release` 将传入首字节写入全局 `DAT_100c45e21`，是一次性静态初始化。该全局选择逐样本路径，V+0x718 随后选择非线性分支。这个 helper 本身不计算物理参数，也不是每块重新求系数。证据 `pass3-nonlinear-check.json`：`ev_e28803303c7f7e2abcd97b70bd948269c9b1b9ad1e63a789df78008a4bacd55d`。

## 真实钢琴音频路径的运行时确认

本轮后续用 Pianoteq 官方独立程序，以 `--headless --no-prefs --preset "NY Steinway D Mix" --midi dense.mid --wav dense.wav --rate 48000 --bit-depth 24 --dither OFF` 成功渲染。没有使用 Pedalboard。只读 `/usr/bin/sample` 取得该隔离进程（17133）的栈；命令、退出码、WAV 与报告保存在 `audio-pass3/sample-render/`。

该次镜像运行时基址为 `0x100380000`，Ghidra 的首选基址为 `0x100000000`。必须按镜像偏移转换，不能直接把 ASLR 后地址输入 Ghidra：

| sample 中的镜像偏移 | 对应已恢复函数 | 动态意义 |
|---|---|---|
| `+0x20b378` | `FUN_10020b28c` | 真实钢琴调用外层激励/合成分派 |
| `+0x4e3718`、`+0x4e2b5c` | `FUN_1004e285c` | 真实钢琴经过通用渲染函数 |
| `+0x7c0d44` | `FUN_1007c0bcc` | 块式二阶历史状态渲染确实执行 |
| `+0x8636d4` | `FUN_100863008` | 模态系数刷新确实执行 |

这消除了“该路径也许只供另一种乐器使用”的一部分疑问：**上述函数确实在 NY Steinway D Mix 的真实音频生成中运行。** 然而采样是离散栈快照，不能由它恢复模态数据值、逐样本轨迹或未采到的短分支。此轮没有在栈中捕获 `FUN_10032ce58`，不能因此断言它未执行；也不能反过来宣称非线性记录分支已在该实验执行。完整三体耦合与参数到接触系数的映射仍待证明。

## 找到了非线性记录的实际生产者

为避免仅沿名称或调用者猜测，本轮对同一 ARM64 副本做只读 `otool -tv` 指令检索，找到 `0x10095192c` 对 `+0x260` 的写入，再由 REA 解析所属函数 `FUN_1009511bc`。确认依据不只是一个偏移相同：该函数连续操作记录数量、`0x70` 步长、观测/反馈两个向量、历史字段及 `+0x6c8/+0x6f0` 缓冲，均与渲染消费者一致。

令该函数三个主要对象分别为容器 V、运行配置 T、模型数据 K（避免与前文 cos 系数 K 混淆；此节 K 仅指对象）。它执行：

- V+0x0c ← `1 / float(T+0)`，把先前递推公式中 τ 的来源推进到运行配置首字段；单位仍需调用者验证。
- 记录数 ← `uint(K+8)`，要求不超过 10；10 条内嵌记录恰好占满 `[V+0x268,V+0x6c8)`。
- 每条记录的 e、h0、h1、f、r 清零，g ← `float(T+0x20)`。
- 阈值 a_j ← `float_array(K+0x110)[j]`，要求绝对值小于 100。
- 观测权重 `w_j[i] ← float_array(K+0xc0)[K.u32[0] × K.u32[1] × j + index[i]]`。其中 `index` 来自 V+0xc0 向量的 float 元素，再转换为整数索引。
- 非线性模式的输出权重 ← `float_array(K+0xe8)[index[i]]`。

此外，V+0x20 的基础频率样数组来自 K+0x20 的源数组按同一 index 重排；V+0x1b0 的 J 数组在指定分组范围外计算“本元素值 − 该组首元素值”，范围内置零。这推进了相位 `F+J(k−1)` 的数据来源，但仍不足以把分组叫作具体某根琴弦。

**物理身份的重要限制：** K+8 非零或 K+0xc 非零会开启 V+0x718 的模式；此路径日志实际写着 `bzzmode while nb_planes={} nc={}`。因此可称“bzzmode 的带阈值记录”，不能将其直接定名为钢琴琴槌或制音器。真实 NY 钢琴采样证明通用渲染器被使用，尚没有证明这些 bzzmode 记录在该预设中非零。

REA 证据 `pass3-contact-producer.json`：`ev_606b180dfd3d4f95c4da5c0717658969f0578bc670eb27afb010bb419c3d66b8`。构造函数 `FUN_1000de578` 独立确认上述容器布局和初始清零，证据 `pass3-contact-init.json`：`ev_aa127c055a2fcb0347b81874bb111134d5a60cb4b3271038b538bcc615343faf`。相关原始反汇编与候选列表留在本地证据目录，不写入应用源码。

## 位置权重与阈值的再上游

`FUN_100715f98(X,K,Kother)` 构造描述对象，将 `G=*(X+0x2fb8)` 与 K 传给 `FUN_10043dcb0`，后者再调用上述 `FUN_1009511bc`。运行配置首字段来自 `G+0x98`，修正增益 g 来自 `G+0x208`。同函数另有 `44100.0/(G+0x98)` 缩放，支持此字段与采样率有关，但单凭常数比例仍不作为单位的最终独立证明。

在一条 K 扩充路径中，它检查 `*(G+0x1240)+0x5c0 > 0`，并核对位置数组与阈值数组长度相同。设 `R=*(G+0x1240)`，实际阈值由下式生成：

```text
z_j = float_array(G+0x1f0)[j] / max(0.01, float(X+0x80))
a_j = -clamp(z_j, -50, 50)
```

位置来自 `float_array(R+0x5a8)[j]`。对应 K+0xc0 的观测矩阵元素包含如下因子：

```text
sin(π × position_j × (mode_index + 1)) × existing_output_weight
```

代码为不同分组填充权重，并将其余分量清零。它不只是“某处有 sin”——结果明确写入上文初始化器随后读取的 K+0xc0，阈值写入 K+0x110。因此已连接“位置/阈值数组 → 模态观测矩阵 → 正交化后的反馈方向 → 带历史门限的模态状态修正”。

但 position_j 的公开参数身份仍未确认，不能把它标成 `Damper Position` 或 `Strike Point`；X+0x80 的物理单位也尚未确认。bzzmode 的证据约束继续适用。这里恢复了一个具体约束子系统的数据和数学链路，**没有恢复全部钢琴接触系统**。

证据：`pass3-contact-parent-a.json`（`ev_db4efea5cff6539dc3833a0ae544dd937eaef40e5035964fc3e70b60a5218093`）、`pass3-contact-parent-c.json`（`ev_6a6f37279c105390ce56cde67a52b1f1dc17d9013c7b761b25e6c3587c67871c`）。
