# pass79：确认Rattle控制非零x，保留动态状态假设失败

已通过官方参数接口和实际只读硬件采样确认：此前释放系数公式中的x受**Rattle Pedal**驱动，不能把这个字段凭名称或立方形式认定为普通制音毡压力。5档初始来源比较10项逐位同；实际动态x下，29次D/rate/gain计算共87项逐位同。**把x按击键初值固定保存的假设失败27处，整体审计仍失败，未取得本轮非零Rattle的独立完整WAV。**

## 来源身份与用途边界

REA证据`ev_993089bd10edbe80a553c8d834b8088dcaf08c0a679ddc5573aebe8e0dfa8519`及当前ARM64指令确认：

- `35f2b8..35f2c0`：从R+e4复制到新声部+306c，R=*(manager+e00)。
- `07ac48..07ac4c`：初始+306c复制到声部+2f38。
- `7184a4..7184ac`：初始化时从+306c送入模态setter。
- `460254..46025c`：运行时从+2f38送入模态setter。
- `511828`：将实际输入s0存入V8c4；V=声部+168。

初步实时候选对照中，Mute、Buff Stop、Soft、Sostenuto、Harmonic、Celeste、Pinch Harmonic、Glissando、Thunder和Aftertouch均未在对应采样中把R+e4变为1；Rattle=1时R+e4和新声部+306c均为1。随后独立采样0/.25/.5/.75/1，均相等。此结论限定于当前NY Steinway和采样工况，不主张其它参数在任何配置都不能间接影响它。

正式B重新读取全部215项参数，每档只有rattle_pedal与基线不同，击键前保存完整读回值。5档顺序为.25/.5/.75/1/0。回调绑定真实来源与新声部；每档的官方参数值→R+e4→新声部+306c共2项，合计10项同。参数归零和结束后215项基线全部恢复。

[官方手册的Pedals章节](https://www.modartt.com/user_manual?product=pianoteq)将Rattle描述为产生弦上嗡鸣的bassoon踏板，并与Buff Stop、Celeste分别说明。这提供用途背景，不替代上述运行值证据；也不能据此把此前所有bzzmode、琴槌接触或普通制音器计算都重新命名为Rattle。

## 非零立方项的实际计算

[采集器](../scripts/pianoteq_capture_rattle_coefficients.py)在已运行、音频设备running的授权调试副本上只读附加，使用2个固定硬件地址：

| 地址 | 内容 | 正式B命中 |
| --- | --- | ---: |
| 35f2c4 | 来源R+e4与已写入的新声部+306c | 5 |
| 6e5360 | 系数源字段、实际u与D/rate/gain目标 | 47 |

系数回调只保存已登记声部、模态计数≤8192的记录，得到29次刷新。47是站点总命中，29是过滤后记录数，不能混为一谈。新声部可能复用地址，因此增加epoch，实际模态必须等于当前epoch声部+168。**这是有限系数快照，非逐块连续模态/包络窗口。**

复用已有`releaseCoefficients`，按真实float32/FMA次序计算：

```
h = f(x * f(x*x))
r = min(u, f(1-clamp(f(h*cubicScale), 0, 1)))
q = f(f(r*r) * f(r*r))
D = FMA32(q, FMA32(q, FMA32(q, FMA32(c4,q,c3),c2),c1),c0)
rate = f(double(rateScale) * doubleword(3fbd791c5f888823) / double(D))
gain = max(f(f(1-u)*gainScale), f(h*cubicGainScale))
```

活动条件仍是flag位或x>0，否则D/rate/gain清零。29次中28活动、1非活动，5次r受立方项上限限制，17次选择立方增益分支；87个D/rate/gain输出逐位同。这里的x/u/flag和模型系数仍为快照输入；没有从原生D/rate/gain回填自己的计算。

## 固定x假设明确失败

[重放器](../scripts/pianoteq_replay_rattle_coefficients.mjs)分别保存三个范围的结果，不以局部算术通过抹掉整体失败：

| 范围 | 比较数 | 差异数 |
| --- | ---: | ---: |
| 官方参数→初始来源/声部 | 10 | 0 |
| 使用实际动态x的系数算术 | 87 | 0 |
| x固定为击键初值的假设（含x及系数） | 116 | **27** |
| 合计 | 213 | **27，整体失败、退出1** |

例如一个初始x=.25的声部，稍后快照中x=.5；固定假设算出的D为954.3549194335938，原生为684.5508422851562；gain分别为.10546875与.84375。另一个初始x=.75的声部随后出现x=1、再出现x=0。因此改变Rattle不只影响后续新音，仍在发声的声部也会更新。

尚未采到运行时setter的完整事件序列，不能从本轮数据断定更新是直接赋值、平滑还是经其它控制步骤；下一步须绑定+2f38生产与setter，再与系数消费的真实先后关系核对。没有将失败假设改成输出回填后宣称状态携带通过。

14项负对照对**相应组件**全部拒绝：x/u/多项式/rateScale/cubicScale/cubicGainScale、三个输出目标、两个来源目标、错误模态、缺失来源和不完整窗口。基准整体已失败，所以测试不是仅检查程序exit1，而是要求原本通过的来源或算术范围新增差异，或结构明确拒绝。最初将u=1增加到上限以上的扰动被限幅吞掉，没有造成差异；该试验保留为不敏感对照，正式u扰动改为.5，产生3项算术差异。

## 不成功的路径与音频边界

1. **Mute候选被否定。** 使用官方GUI/API将Mute设为.5，音频设备running后保存，新进程215项读回仅Mute变化。离线采样x仍为0。该采集又遇到不支持的LLDB内部停顿ID，关闭硬件点后让原生完成exit0，保留不完整数据，不扩宽守卫通过它。
2. **Buff Stop踏板未随该FXP恢复。** GUI值为.5，新进程读回为0，验证脚本明确失败；不能用该文件作非零条件。临时bank文件已复制到私有目录后移除，未修改用户预设。
3. **CLI设置/读取参数的两次渲染失败。** 第一次误用RPC ID，CLI报告找不到参数；第二次按REA读取器使用一基索引15，确认Buff Stop=.5。两次均在渲染时报同一未处理异常、exit134。原因未定，停止重试该路径，没有归因于特定物理模型或绕过检查。解析器证据为`ev_222d020991a9555f0e71822b76e237998ea6fa1813cdf63acbee9835946b2381`、`ev_c87f54d61c6fcf4ebdc8e3634d7cc3c57c2cad07fe723b4e5aa5852f8a078f59`。
4. **实时A窗口不完整。** 依靠固定墙钟延迟时仅4档进入采集，末尾参数恢复断言失败。保持complete=false；恢复原干声预设后，B改为等待实际source回调确认，再发下一档。两轮不拼装计数。

实际Mute原版干预WAV为142080帧、双声道24-bit/48kHz，与原干声参考有272108个交错样本不同，最大整数差178318，首差frame4804。这证明Mute干预确实改变声音，但不能证明它就是x。该不完整Mute调试采集的完整原生WAV与相同Mute原版也不一致：180686样本不同、最大差11379、首差4865。

**正式非零Rattle B是实时GUI系数采样，没有录得该运行的完整WAV，未通过实际声音等价验收。** 成功detach、官方quit返回且进程终止；执行会话返回−1，不记作原生exit0。没有把Mute WAV或之前pass78的音频当作Rattle场景验证。
