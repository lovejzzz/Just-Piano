# pass64：从反馈注入前声部组生成九行源与完整PCM

将pass63恢复的反馈注入接入整段立体声链。从同次处理前的三个三行组和全局反馈开始，计算九行卷积源并持续推进全部后处理。完整113152帧PCM仍与原生及官方参考逐字节相同，共3105504项检查通过。

## 边界向上游移动

[重放器](../scripts/pianoteq_replay_feedback_stereo.mjs) 在每个块先保存全局入口的三个声部组，随后用本次S+0x118三行反馈和S+0x114增益执行：

```
source[g*3+r][i] = fma32(feedback[r][i], gain, groupBefore[g][r][i])
```

这九行计算值直接进入完整头部与尾部卷积。原生卷积入口九行源仅作为核对目标，不进入DSP。辅助矩阵也取更早全局入口的值，核对其到卷积入口未变，然后送入后处理；后面的辅助值不作为计算输入。

全局路由、反馈支路、IR时域初始化与处理前声部组仍观察；本轮没有声称恢复了它们的完整生成算法。其余路由缓存、卷积与后处理状态均独立推进，最终原生立体声样本只比较和校准，不用作音频生成输入。

## 同次捕获与四个活动硬件点

[采集器](../scripts/pianoteq_capture_feedback_stereo.py) 初始化阶段启用时域复制 `2a4334`、全局入口 `6c2ac4`、卷积入口 `0ef37c`、最终PCM `1bc114`。第一次全局入口时，IR初始化已完成，关闭复制点，启用固定的全局路由前 `6c2fd4`。

逻辑上登记五个已知地址，同时最多四个启用。本次转换日志为frame0关闭copy、开启global、activeSites=4；采集器当场断言，重放器也核对转换记录。没有修改目标指令、运行数据或系统安全设置。

首次尝试的断点字典漏了workspace地址，初始化KeyError后仅安装copy点。原生最终正常exit0，但采集没有有效阶段、窗口不完整，明确保留为失败。其间对尚未完成WAV的一次提前读取被截断检查拒绝，也未计作验证。之后确认进程终止，修正完整地址字典并在启动前解析检查；成功窗口来自全新目录，没有覆盖旧记录。
