# pass54：完整512帧输入交接与1024点计划系数

16个九行512帧输入包，全部与同次工作线程入口逐位一致，共73728个float32，包括pass53尚未直接验证的9216个包尾样本。16次工作调用均正常返回；本次完整原生PCM与官方基准相同。

另外恢复了该1024点计划的联合三角函数系数生成，1002个有效值逐位同。工作线程完整FFT及卷积输出仍未独立计算，不能由输入交接或系数通过认定尾部生成已经完成。

## 同次输入交接

[捕获器](../scripts/pianoteq_capture_tail_worker.py) 同时记录主线程的64帧源输入、尾部节点 `7ccca0` 的512帧入口/返回，以及末级立体声点。工作节点由主状态实际持有的尾部节点指针绑定，避免把同一函数的64帧头部调用混进来。

[重放器](../scripts/pianoteq_replay_tail_worker.mjs) 从本次主线程源样本重新写入九行队列，每八块形成一个512帧包，按实际工作调用顺序核对完整输入。没有读取工作线程输入来补算包尾或选择最相似包。

| 检查 | 结果 |
| --- | --- |
| 完整包样本 | 73728项float32逐位同 |
| 包含其中的最后64帧样本 | 9216项逐位同 |
| 单位增益状态 | 516项float32逐位同 |
| 主帧位置与工作节点入口/返回时钟 | 161项精确相同 |
| 已完成包 | 16个 |

工作入口时钟从0按512推进，返回值为下一512边界；模式均为0。16次工作调用来自同一独立线程。为等待最后一个包返回，采集到全局8256帧；该前缀的最终浮点块编码与同次WAV一致。

另将pass53保存的16个计算包与本次工作入口比较，73728项也全部一致。这是跨运行佐证，不计作第二次新的原生采集。

## 尾部银行和变换计划

实际尾部节点含一个512帧、九输入、一步工作的银行。计划头部为：

```
N=1024, vectorCount=128, realCore=256, factorCount=4
factors=[4,4,4,4]
```

本轮取得768个实数最终组合系数和256槽核心旋转表。根据已恢复radix循环的索引范围，旋转表中234个值参与运算，另22个位置不在读集中；这些位置含非零存储值，不能把整段分配区都当作有效旋转系数。生成器对未使用位置置零，仍需完整1024点运算的动态验证来检验其无影响性。

## 联合函数与独立函数不同

初版 `Math.sin/Math.cos` 生成与表数据有24处差异：22处位于上述未使用位置，两处为有效余弦值。改为分别调用恢复的独立sinf/cosf逻辑后，又有28个有效值不符；两个失败诊断均保留，没有放宽ULP标准。

系统库的联合 `__sincosf_stret` 使用不同的路径：先将角度乘2/π、舍入象限，在这个归一化余量上用两路double多项式和FMA求值，最后转float32并变换象限。因此不能用两个独立接口代替联合接口。

[联合实现](../dsp/native-scalar-sincos.mjs) 经独立系统C oracle的4247个输入、8494个结果逐位检查通过。另补充独立cosf的4247个结果检查；独立正弦算法保持原样。范围限于本机系统库已恢复的有限快速分支 `abs(x)<120`，不是所有平台和输入域的证明。

[1024点系数生成器](../dsp/real-fft-coefficients.mjs) 采用联合算法，768个最终组合值和234个有效旋转值，共1002项与本次原生表逐位一致。该结果验证固定计划的有效系数；目标初始化实际调用点尚未动态绑定，完整1024点FFT仍待实现及验证。

## 出队时序的失败假设

将本次工作输出与pass53消费记录按“一包512帧延迟”对应，23040项中有20388项不符，假设失败。两个运行的输入包一致，完整PCM也均同基准，但这不足以推断工作结果何时进入可消费链表。

该失败单列保留，没有改成寻找最相似偏移。下一步需要同次记录工作输出目标块的身份/代次，以及主线程当前输出块的身份和位置，直接绑定所有权与时序。仅凭入口/返回时钟不能认定消费延迟。

## 实际音频与控制

原生进程45430正常exit0，完整113152帧、48kHz、双声道24-bit PCM与官方参考逐字节相同，SHA-256为 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`。

九个负对照全部失败：工作输入末样本、主线程包尾源样本各改一ULP，入口/返回时钟各加512，最终组合系数和有效旋转系数目标各改一ULP，分别恰好一项不匹配；删除一个主输入、改相加模式、改分解因子被结构检查拒绝。

WAV由原生程序生成，工作输出和末级立体声仍观察。完整工作卷积、出队时序、旧音频变体、全部物理模型/预设、完整琴槌—弦—制音毡耦合与网页整段声音等价性均未完成，尚未最终合并或部署。

私有证据为 `debug-pass54-tail-worker/`、`pass54-*`；系统库调试仅运行自有oracle程序，没有向Pianoteq注入函数调用或修改指令。
