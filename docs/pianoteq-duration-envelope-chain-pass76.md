# pass76：时长系数自计算，连续传入释放包络与再击

释放时长不再直接作为包络的观察输入。源控制和模型多项式→自己计算时长/速率/增益→连续包络→实际复制提交→旧释放→再击控制，在同一完整原生运行中完成26228项逐位比较，零差异。**完整PCM仍失败，没有独立完整声源WAV，网页声音等价尚未完成。**

## 从源系数到时长

[重放器](../scripts/pianoteq_replay_duration_envelope_chain.mjs)复用[releaseCoefficients](../dsp/physical-controls.mjs)，按当前ARM64的`6e4f5c`函数、`6e525c..6e5378`指令顺序计算。V为模态对象，f为float32舍入，FMA32为一次舍入的融合乘加：

```
active = (releaseFlag & 1) != 0 || f(x) > 0
if active:
    h = f(x * f(x*x))
    z = f(h*cubicScale)
    r = min(u, f(1-clamp(z, 0, 1)))
    q = f(f(r*r) * f(r*r))
    D = FMA32(q, FMA32(q, FMA32(q, FMA32(c4,q,c3),c2),c1),c0)
    rate = f(double(rateScale) * doubleword(3fbd791c5f888823) / double(D))
    gain = max(f(f(1-u)*gainScale), f(h*cubicGainScale))
else:
    D = rate = gain = 0
```

| 来源 | 字段 |
| --- | --- |
| x、u | V8c4、s1实际源寄存器 |
| releaseFlag | V924 |
| c0、c1..c4 | V914、V94c..V958 |
| cubicScale、rateScale | V91c、V910 |
| gainScale、cubicGainScale | V90c、V920 |
| 比较目标D、rate、gain | V944、V7e4、V7b0 |

公共观察点`6e5360`位于活动与非活动分支合流、缓存写入之前。模型helper `288f38`可能在计算前刷新多项式，因此读取的是**helper执行后的源系数**，没有把刷新前的模型快照假定为当前输入。s1此时仍保留实际u。目标D/rate/gain只比较，不回填自己的状态。

每个新声部的包络与系数从本刺激的持键冷态0初始化；系数生成编号按实际刷新事件递增。包络消费必须绑定同一个声部和生成编号，使用自己缓存的D，原生D仅比较。包络前后通过线程与模态对象配对；自己的位置、uint32样本计数、复制表和旧释放持续推进。baseDuration、timestep、块长和源系数仍观察，源控制/模型字段的完整生产没有在本轮恢复。

## 五个固定硬件站点

此前“四个点”是采集方案限制，并非实测硬件上限。先以自己的小型C程序验证5个同时启用的硬件断点，每处命中一次、exit0；正式Pianoteq采集也由LLDB明确列出5处均为hardware。只证明本机本次支持**至少5点**，没有测最大数量。

[采集器](../scripts/pianoteq_capture_duration_envelope_chain.py)固定站点如下，不在运行中重排：

| --- | --- | ---: |
| 35ef10 | 已匹配旧声部和新击键输入 | 5 |
| 6e5360 | 当前源系数、u与D/rate/gain目标 | 59 |
| 472f80 | 包络更新前、计数/块长/控制 | 3734 |

正式B进程53871完整渲染并exit0，无读取错误、待配对为空。8次普通Continue：7条常规守卫sidecar，另1次复制站点的硬件异常。该异常最初被守卫拒绝；只读核对最后回调的线程、声部、计数和两个释放值与现场全部相同后，用单独守卫续行。失败守卫、现场与续行脚本均保留，没有手动补造采集记录。

公开助手后来加入同样的复制条件。新增分支以真实停顿元数据回放通过，并拒绝6种线程/声部/计数/值/待配对扰动；**该公开整理分支没有另做一次原生重跑**。本轮没有写目标内存、改PC/寄存器、注入内部函数、修改完整性/授权检查、使用软件断点或Pedalboard。调试副本`__text`继续按既有哈希核验。

| 检查 | 结果 |

本刺激x全部为0，u覆盖0、1及7个中间实际值，releaseFlag覆盖0和1。**非零x的立方反馈仍未经过本轮动态验证**；不能把系数算术称为完整制音毡接触力。

4次再击的自算r依次为0.02583368495106697、0.011980867944657803、0、0.04155844449996948。复制时模态计数领先声部计数512的3658次，其余13次为64/128/192/256/384/448。这里只报告内部计数关系，不把它解释为听觉提前或全部调度差异的根因。

先前A使用4站点、仅包络返回，没有保留更新前点。该进程47766也exit0，59次系数刷新算术都吻合，但18730项比较中有794处样本计数差异；首声部出现128→640和2944→3072缺口。A仍明确判失败，不能因为位置未变而跳过计数判据。五点B成功没有证明A缺口的具体成因。

18项负对照全部拒绝：源多项式/u/rateScale/gainScale/释放flag、D目标、baseDuration、timestep、块长、前后计数、前后位置、复制值、删除完整包络对并同步修改块数、错误对象、错误生成编号、不完整窗口。释放flag扰动传播出2232处差异，baseDuration/timestep各2224处；删除完整对仍有803处独立累计计数差异。D目标单独改动只产生1处比较失败，证明原生目标没有驱动自己的包络。
