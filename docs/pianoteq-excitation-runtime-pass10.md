# 第十轮：硬度斜率到实际激励幅度的运行验算

本轮用真实内部值验证了 `s→L→exp(L)→W`，没有只对系统指数函数做测试：两份独立单音符采集覆盖正、负斜率，**72 个对数谱 L 全部 float32 逐位一致**；另一次采集的 **108 个非零模态幅度乘积全部逐位一致**。这三次采集均正常退出，最终实际 PCM 分别与官方原版同输入逐字节相同。

独立 `float32(math.exp(L))` 与原程序调用的向量 `vexpf` 并非全部逐位相同，最大绝对差 `1.1920928955078125e−7`。这项差异明确保留，不能把现有浏览器 `Math.exp` 当作已完成原程序逐位复刻。

## 同一次调用内取得斜率、模型表、对数谱与指数返回值

单点位于 `1006950e8`：`10071033c` 已返回，四个 L 尚未被原地覆盖。该包装的原生指令明确把 x0/x1 转到 v0，调用系统 `_vexpf`，再把 v0 转回 x0/x1。因此能在一个硬件断点同时取得输入和输出。

| 数据 | 捕获来源 |
|---|---|
| 原始四个 L | `*(x19+278)+16*x24` |
| 四个 exp 返回值 | x0/x1 的原始 float 位模式 |
| 斜率 s、基础表倍率 cB | scratch x19+230、+240 |
| 参考量 r、下界 lo | s15、s10 |
| 模态坐标 k | 模型 x25+7b8 的向量 |
| 基础表 B | scratch+1c0 指向的向量头，继续取其数据指针 |
| 附加表 E | scratch+2a0 的指针 |
| N、当前四值组 | scratch+f8、x24 |

这些模型表和缓存都是实际捕获，不是根据音频拟合的未知系数。当前 r 的物理单位尚未确认；这里给出的只是它的精确计算角色。

## 可独立重建的完整 L 算式

令 `r32` 表示一次 float32 舍入，`fmaf` 表示 float32 融合乘加，`fma64` 表示 double 融合乘加。上界 `hi=20`（s>0）或 `hi=0`（s≤0）。对每个有效 i：

```text
t = r32(s * r32(r32(k_i−1)−r))
L0_i = fmaf(cB, B_i, clamp(t,lo,hi))
```

若 `r32(k_i−1)<N`，还须应用实际 E 表：

```text
x = max(r32(k_i−1),0)
a = floor(x)
b = min(a+1,N−1)
u = r32(x−a)
e = fmaf(r32(1−u),E_a,r32(u*E_b))
L_i = r32(fma64(double(e),K,double(L0_i)))
K 的准确 double 位模式 = 0x3fbd791c5f888823
```

否则 `L_i=L0_i`。常数 K 不能提前换成 float32；实际汇编 `1006950a8..50bc` 在附加表插值后转为 double，再融合乘加，最后转回 float32。前面的基础表贡献也使用 FMA，不能任意拆成两次舍入。

A4 力度96首个有效模态的实际 s 为 `−0.03701772540807724`，cB 为 `0.12096518278121948`，r 为 `0.7191667556762695`。第2个模态 k=2，B=`0.047054700553417206`：

```text
L0 = -0.004703827667981386
L  = -0.022745346650481224
vexpf(L) = 0.9775113463401794
float32(math.exp(L)) = 0.9775114059448242
```

L 的逐位重建成立，而指数返回有一位 float32 差异，两件事必须分别报告。

单音符力度96、127各取得10次向量返回、36个有效 L；总计72个 L，其中44个含非零 E 贡献。正斜率采集值为 `0.034931011497974396`，已执行正斜率的零下界钳位；负斜率采集执行了零上界钳位。当前捕获 k 均为整数，因此 E 的非整数插值权重仍没有运行验证。未触及正斜率20上界，也未从五节点原始输入重算本轮 s；本轮起点明确为实际斜率缓存。

## 指数权重确实乘进模态幅度

另一独立单点 `100695190` 位于 scalar 幅度乘法之后、内存写回之前，同时读取：

```text
原始 W = *(float*)(x16+4*w17)
原始 H = (*(float**)(scratch+278))[x8]
应用的 H = s2
结果 W' = s3
```

静态门限为准确 double `1e−9`，原程序先将 H 提升 double 比较，低于门限时应用0；否则应用 H。此次108个单音符样本中 H 均超过门限，`W'=r32(H*W)` 全部逐位一致，全部结果非零；门限清零路径仍未运行验证。

例如，首模态另一分量：

```text
W  = 0.026148580014705658
H  = 1.0045205354690552
W' = 0.026266785338521004
```

这证明硬度准备阶段产生的谱倍率真正改变发声幅度数组；它仍是准备阶段的谱操作，没有从当前 P/Q 求瞬时压缩与接触力。

## 真实 PCM 对照及多音符的反例

三次单音符采集均用已保存干声预设、CC64=0、48 kHz、24 bit、dither OFF。力度96的谱采集及幅度采集分别与同输入官方对照完全一致，113152帧双声道 PCM：

`1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`

力度127的谱采集与新官方对照完全一致，128768帧双声道 PCM：

`f51d57cbf36f46b8ff57a045a8af6e3530d1594083947490c1e746fda48221d9`

另做五个音符的扩展 MIDI，包括A4重复力度32/64/127、A2力度96和C6力度127；采集70次向量返回、263个有效 L 全部逐位通过，包含7种正/负斜率、104个非零 E 贡献；另一采集512个非零 W乘积全部逐位通过。但这些多音符采集的最终 PCM 与官方对照不同，不能作为无扰动音频证据。

进一步复验发现官方自身重复同一多音符 MIDI 的 PCM 也不同，首次差异在 frame16010，第三次重击附近；独立调试副本无断点渲染也在同处出现差异。由此只能限定为这份多音符控制尚不具有逐字节可重复性，不能仅据差异归因调试断点，也不能据正常退出忽略差异。各份 WAV、首次差异位置与哈希均保存；单音符对照另行通过，没有删除多音符失败记录。

## 证据与实现范围

公开四个脚本为：`pianoteq_capture_excitation_spectrum.py`、`pianoteq_verify_excitation_spectrum.py`、`pianoteq_capture_excitation_gain.py`、`pianoteq_verify_excitation_gain.py`。验算失败返回非零；它们面向本次macOS/LLDB环境，复用已有准确 `__text` 校验。两次断点实验各自仅使用一个固定硬件断点，未修改寄存器、代码、许可检查或原始应用。

本机证据目录均位于 `~/.local/share/just-piano-analysis/`：`debug-pass10-spectrum`、`debug-pass10-spectrum-forte`、`debug-pass10-gain-single` 为单音符成功控制；`debug-pass10-spectrum-v2` 和 `debug-pass10-gain` 保留多音符结果及其音频差异。每个目录保存采集、日志、数值验算和哈希清单，相关目录另有实际 WAV 及 PCM 比较。

仍缺：硬度原始输入到斜率的同次联合捕获、E表全部生产者、非整数坐标插值、极小指数门限、系统向量exp的精确跨平台实现，以及位置修正/随机音色/追加模态/归一化的完整组合。未发现本段包含逐样本琴槌质量、毡压缩、弦位移反作用的积分；不能将上述验证改名为完整瞬时接触模型或所有预设的声音复刻。

## JavaScript 实现与真实快照重放

新增 `dsp/excitation-spectrum.mjs`，实现上述 s→L、准确double乘加后float32舍入，以及使用外部给定原生权重的H→W。`approximateExpWeights` 的名称明确标为近似；没有实现原生 `vexpf` 算法。Node 重放器为 `scripts/pianoteq_replay_excitation_spectrum.mjs`：

```text
node scripts/pianoteq_replay_excitation_spectrum.mjs SPECTRUM_RUNTIME_JSON GAIN_RUNTIME_JSON REPORT_JSON
```

对多音符真实快照重放，JavaScript 计算的263个 L 及使用实际原生H的512个 W 全部 float32 字节一致。正负斜率独立单音符快照各36个 L、单音符108个 W 也全部字节一致。重放报告将 `native_vexpf_implemented` 和 `entire_native_pipeline_bit_exact` 固定为false；`Math.exp` 的39/263处差异单独统计，不允许通过取原生H来隐去该缺口。这里“已恢复阶段通过”仅指L及给定原生H后的乘法。

当前实现仍依赖调用方提供模型表、参考量及斜率，没有生成预设或自动从网页控件计算这些表。非整数坐标公式已按原指令写入，但真实采集的 `fractional_coordinates=0`，未以合成fixture冒充实际覆盖。此次没有把研究模块接入现有网页发声路径，完整音色一致性仍未成立。
