# 动态 Rattle 来源、交接与实际音频：pass80

目标为本机 Pianoteq 9.2.5 ARM64。本轮解决 pass79 固定声部 x 假设失败；未完成独立完整声音或浏览器集成。

## 同次动态链

[采集器](../scripts/pianoteq_capture_rattle_updates.py)在独立调试副本上使用六个固定硬件站点，只读观察。原生进程83600正常 exit0，窗口完整、无待配对事件、错误为空，最终六点关闭。

| 站点 | 作用 | 记录数 |
| --- | --- | ---: |
| 10035f2c4 | R+e4 → 新声部+306c | 5 |
| 10085ed9c | R+e4 → 声部+2f38，运行更新A | 3304 |
| 1007cbaf4 | 同字段运行更新B | **0，仅静态证据** |
| 10051182c | 实际setter参数与模态V+8c4 | 3318 |
| 1006e5270 | 实际消费x的立方值及模型源字段 | 117 |
| 1006e5360 | D/rate/gain与实际u | 121 |

[重放器](../scripts/pianoteq_replay_rattle_updates.mjs)按声部epoch携带初始、当前和模态x；区分初始化caller1007184b0与运行caller100460260。运行更新由观察的R源赋值，自算x交给setter，活动消费处冻结当前x，自算立方与已有releaseCoefficients输出；原生目标只作比较，不回填计算。5个声部共11次实际x变化，**13981项逐位比较全部一致**。121次系数中117活动、4次非活动。

23项负对照全部拒绝，包括来源、目标、所有权、caller、活动配对、模型/u、缺失初始化、窗口不完整，以及整段改变源值（414差异）和整段移除对应更新（246差异）。这比只篡改一次冗余赋值更能验证实际状态传递。

边界：R全局输入、u和模型源字段仍观察；活动/非活动由真实执行分支识别，尚非自算gate。未连接同次模型初始化、连续包络或完整声部输出，也没有动态覆盖更新B。Rattle是嗡鸣效果，不能据此宣称普通制音毡完整耦合已恢复。

## 可重复正常 MIDI 刺激

官方录音器实验产生133字节MIDI，包含5次note-on/off但没有Rattle自动化，故不能当动态刺激。随后用[私有预设构造器](../scripts/pianoteq_make_rattle_fixture.py)仅将普通FXP的A+1518四踏板向量从[2,3,4,1]改为[2,3,4,6]，重算普通dlla数据MD5；应用二进制和保护逻辑没有修改。源码拒绝仓库内输出、已有文件、非默认源向量和损坏校验；4项保护检查通过。所有其它模型字段与字节均保持，校验区域除外。

编号5候选经官方API/MIDI读回只改变Super Sostenuto；编号6候选只改变Rattle，CC64=64读回.5。这是运行证据，静态reader本身不证明枚举含义。官方loadFile加载后再savePreset保存规范文件，临时bank移除，原干声预设及215项参数恢复。GUI编辑未成功，不列作成功路径。

[MIDI构造器](../scripts/pianoteq_write_rattle_fixture.py)产生5次A4重击和CC64的32/64/96/127/0变化，作用于仍发声旧音。--zero仅将这五个控制值归零，保留相同音符/时间。两种生成结果均与正式刺激逐字节核对。原生渲染使用官方重新保存的规范预设，不是直接声称源码克隆文件等于官方重存文件。

## 调试停顿证据

最初守卫拒绝的unsigned -2已查明是LLDB自身线程创建内部断点，属于libsystem_pthread.dylib的start_wqthread/_pthread_wqthread/_pthread_start。新守卫同时检查内部属性、位置索引、模块、file/load地址，并要求另一线程存在已登记真实硬件站点；内部断点本身不能满足继续条件。同一进程只执行一次普通Continue后正常结束。没有关闭内部断点、改写目标代码/数据/寄存器或修改PC。

宿主模拟检验覆盖实际配对成功一次，以及非内部、错误模块/file/load、位置越界、未知ID、没有自有站点七种拒绝；错误情况Continue次数均为0。模拟只是守卫验证，实际运行证据另存。先前pass79失败窗口仍保持失败，不追溯改为通过。

## 实际音频：严格一致性仍失败

正式采集、原版参考、原版重跑和零控制四次正常CLI均exit0，没有Pedalboard。完整双声道24-bit/48kHz音频比较：

| 对照 | 帧数 | 不同交错样本 | 最大整数差 | 首差帧 |
| --- | ---: | ---: | ---: | ---: |
| 正式采集 vs 原版 | 两者148224 | 79306 | 7 | 14979 |
| 原版重跑 vs 原版 | 两者148224 | 185119 | 379 | 14848 |

不将差异归为量化噪声，不放宽门槛，也不把原生WAV称为独立实现输出。原版自身重跑差异原因仍待查。

零控制143104帧，Rattle148224帧，完整格式比较不通过。仅为干预分析，另比共同143104帧：272462样本不同、最大差1074739、归一化RMS差.004686669233177089、首差4808。这说明普通MIDI干预改变实际声音及尾长；共同前缀截取不能用于声音等价验收。
