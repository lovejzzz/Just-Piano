# 多分量极点的浏览器可执行实现：第十轮

`dsp/modal-poles.mjs` 将已恢复的 lambda→复多项式→复根→频率／衰减变成无 Node 依赖的 JavaScript ES module。这里的求根采用独立 Durand–Kerner 迭代，**不是**原版 `484ce4` 的 QR 特征值求解器；当前也没有把它接入网页来代替完整声学模型。

## 真实采集重放结果

`scripts/pianoteq_replay_poles.mjs` 读取原始采集文件，保留每条误差、求根残差、索引和失败，失败返回非零。当前结果为：

| 对照 | 真实范围 | 结果 |
|---|---|---|
| lambda→复系数 | 第七轮一组 N=3，8 个实／虚 double | **8/8 逐位一致** |
| 实际复根→频率、衰减 | 第八轮 32 组，18 组 N=3、14 组 N=2 | **164/164 逐位一致** |
| 独立求根→频率、衰减 | 相同 32 组、82 个分量 | **164/164 逐位一致** |
| 独立根与原版根集合 | 同上；穷举排列匹配，不依赖返回顺序 | 最大复平面距离 `1.831026719408895e−15` |
| 独立求根归一化多项式残差 | 同上 | 最大 `2.0430581309500194e−16` |

该运行没有失败记录。原版根和独立根的 double 本身并非逐位一致；上表输出相等是 `Math.fround` 后的结果，不应扩展成 native 求根过程已完全重现。第七轮和第八轮是不同调用的两份采集；没有联合捕获 lambda 到所有输出的同一次完整调用。

## 消除剩余的系数误差

之前普通 double 乘加只有 7/8 系数逐位一致，唯一项差 `7.862351722316528e−22`。本轮核对保存的 ARM64 原始指令后按执行次序复现：

- `476748` 和 `476768` 按源系数索引递增，先对当前项执行常数乘加，再对下一项执行斜率乘加，两次均为 `FMADD`。这与先乘出所有积、再普通相加不同。
- `476934`、`476944` 最后因子同样使用 `FMADD`，继续保留实际 `beta[N−2]` 索引。
- `4769d8`、`4769dc` 和 `476a24`、`476a28` 的复输出使用融合减乘；虚部按一次舍入计算 `S−q*T`。
- beta 按 `((1−delta)*0.5)/mean` 的实际次序计算。

`fma64` 将有限 binary64 操作数拆为有符号整数和二次幂，用 BigInt 完成精确乘积、加法与最近偶数舍入。它只用于模型系数／表准备，不在每音频样本的循环调用。初次 2003 个向量对照均通过。随后主线程审阅发现两个尚未覆盖的边界：精确零返回会丢失负零；有限乘积单独求值溢出、同时加相反无穷大时，普通乘加回退会产生错误 NaN。现已分别保留两个零项都为负的负零结果，并在 a、b 有限而 c 为无穷大时直接返回 c。

新增独立平台对照脚本 `scripts/pianoteq_verify_fma64.py`，通过平台 `libSystem.fma`／`libm.fma` 生成 oracle，再用 Node 加载共享浏览器函数。输入和输出通过 binary64 十六进制位传递，保留有符号零及无穷大；NaN 仅比较分类，不要求 payload 相同。边界构造覆盖下溢 midpoint 两侧、次正规到最小正规过渡、最大值附近溢出 midpoint、精确相消及非有限组合：

| 类别 | 通过／总数 |
|---|---|
| 有符号零 | 64/64 |
| 次正规／下溢 | 648/648 |
| 溢出 | 144/144 |
| 非有限／NaN 分类 | 729/729 |
| 特定相消 | 3/3 |
| 固定种子随机向量 | 2000/2000 |
| 合计 | **3588/3588** |

完整结果为本机 `pass10-fma64-boundary-verification.json`。这是明确列出的边界验证，不声称穷举全部 binary64 输入。修正后再次运行真实极点采集重放，8/8 系数及两条 164/164 输出对照保持不变。

第七轮历史失败和普通乘加验算仍保留在原证据目录的 `coefficient-verification.json`；没有覆盖旧结果。

## 求根与排序边界

系数首项仍为最高次项，独立求根默认最多 256 次，返回根、迭代数和每根残差；残差超过 `2e−14` 时抛出错误。只有次数 2 或 3 且首尾系数非零的路径开放。N<2 快路、零系数剔除和更高次数显式拒绝，避免悄悄替换成未经验证的处理。

输出严格按 `key=fma(F,1e−16,v)` 递减排列。排序首项的虚部除以 floor ratio 形成所有衰减的下界；最后频率和衰减舍入到 float32。独立迭代的根排列可以与原 QR 不同，所以只在同一原根数组重放时比较原排序索引；独立求根比较最终排序后的频率／衰减。相同 key 当前显式拒绝。实际采集尚未覆盖衰减下界真正钳制的分支。

## 原 QR 的进一步恢复

本轮通过现有 REA 会话补取 `484ce4` 及 `4ee5a4`、`3ea1ec`、`97cde0`、`6f30a0`，没有新启调试进程或 Ghidra 实例。

`484ce4` 的实际控制流是矩阵复制、`4ee5a4` 准备、`3ea1ec` 检测解耦区块、反复调用 `97cde0`、再由 `6f30a0` 提取 1×1／2×2 块根。无进展迭代计数达到 10 和 20 时传入特殊 shift 标志；总尝试预算与矩阵阶数的 100 倍相关，失败抛出 `QR algorithm failed`。N<3 的解耦检测直接终止迭代，后续 2×2 提取使用复判别式平方根。QR 主体及其精确舍入尚未移植到 JS，不声称已完成该算法复刻。

原始新反编译保存在本机 `pass10-eigensolver.txt`、`pass10-eigensolver-helpers.json`、`pass10-0x100*.txt`；没有把商业二进制或完整反编译代码放入仓库。

```sh
node scripts/pianoteq_replay_poles.mjs \
  "$HOME/.local/share/just-piano-analysis/debug-pass7-poles/attempt4-runtime.json" \
  "$HOME/.local/share/just-piano-analysis/debug-pass8-roots/runtime.json" \

```

采集内容不随公开仓库发布。JSON 结果保存在上述本机路径。本轮是浏览器模块的系数与数值重放验证；没有生成新的实际音频，也不能借用前轮 PCM 对照来声称本模块已经产生与 Pianoteq 相同的琴声。

FMA 边界对照无需专有采集文件，运行 `python3 scripts/pianoteq_verify_fma64.py [result.json]`；要求 Python 3、Node.js 与平台的 `fma` C 函数。
