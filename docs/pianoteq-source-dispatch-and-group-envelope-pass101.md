# 源提交分支与释放后组包络（pass101）

目标仍是独立浏览器声源与完整音频。本文记录的完整采集重放通过，只覆盖已观察模型／控制输入下的内部链路，不代表该目标完成。

## 真实分支修正

pass100 的独立源提交窗口中，每次观察到的源事件都有后续 setter。pass101 B 联合采集在第五个声部附近失败：最后源记录属于 epoch 4，随后 setter 属于 epoch 1，严格配对断言拒绝。保存了原始记录、失败时寄存器和调用栈；正常 Continue 后原生 exit 0。没有改写原生缓存、寄存器、PC 或指令。

REA/Ghidra 与不可变二进制的指令读取显示，不能把源写入和模态提交等同：

- `85ed98` 写 H+2f38 后，`278154` 检查声部状态低位；未置位可返回。
- `4601a0` 检查缓冲状态低位；置位时调用就绪检查。
- `4601ac` 消费该检查的实际返回低位。未就绪且 multi=1 时可绕过 setter。
- `511828` 写 V+8c4；运行时调用者返回地址为 `460260`。

新采集器让同一个硬件槽依次观察源、实际分支、setter 或跳过返回 `85ede4`。始终六个注册且启用的硬件点，替换前删除旧点，切换后通过显式停止屏障及普通 Continue 恢复。分支输入仍是观察值，不声称已独立生成缓冲就绪调度。

`rattle-dispatch-control.mjs` 根据实际分支输入计算路由。重放遇到跳过时只更新自己携带的 current，保留自己的 modal；原生 modal 只作比较。14 个分支用例、6 个非法输入及一次跳过后再提交的状态测试通过。

## 释放后组包络

恢复 `428784` 与四通道乘法 ramp `322148`：四个 lane 的浮点运算顺序与每四样本的步进必须保留，不能用逐样本标量循环替代。三个组在活动块入口共用同一个起始 gain，各组分别令 elapsed 增加 64；严格 `elapsed > duration` 才清 active。

直接观察到一个旧声部首个消费块已经处于衰减中：gain=0.7302838563919067、step=0.9996222853660583。64 样本后三组的 gain=0.7128382921218872、elapsed=192。重放只在每个声部首次消费观察处初始化包络，后续自己携带状态；后来的原生 gain、step 和输出均作比较，不回填预测。

新增 `460a4c` 三组完整输出与后状态观察，覆盖释放附加信号和上述组包络。组包络调用按实际 voiceFlags/skip 控制决定执行或旁路，旁路时不推进包络、不乘残留 gain。前置 gain 目前只支持实测的单位增益旁路；其它控制转换严格拒绝。早期释放位置的同次观察桥、模型表与其它源控制仍有观察依赖。

## 失败与验证边界

- A 联合采集缺少一次工作完成回调：epoch 2，expected=19008，actual=19072；对应调度与刷新存在。完整采集仍失败，局部前缀诊断不计作整链通过。
- B 联合采集触发上述源／setter 归属断言，完整采集仍失败。实际完整 WAV 同为 148224 帧，99752 个交错采样不同，最大整数差 9。
- 旧 pass99 C 回归保持 **6260940 项、2 项差异**，释放组件保持 531254 项零差异；新逻辑没有把旧失败改成通过。
- C 完整采集正常 exit 0，无待配对项；3349 个工作块、3314 次源事件，其中 3312 次运行 setter、2 次实际就绪分支跳过，11 次源值变化。21936 次槽位替换均有六槽及停止屏障审计。
- C 首次整链重放有 2240 个释放后输出差异。原因是 `460914/460970` 可跳过整个组包络调用，inactive 仍可能保存非单位 gain；原实现错误地继续乘 gain。保留该失败报告；修正为根据实际 dispatch 控制旁路，原生目标样本仍只作比较。
- 修正后同一完整 C 数据 **7072729 项零差异**：643008 个工作输出采样、514176 个延迟后采样，以及另一个端点的 514176 个释放后采样。释放组件 1336259 项同，1141 个组包络旁路块。前四声部只直接比较启用后的连续后缀，第五从 counter=0 开始。
- 从自算释放后样本导出 15 条 float32 单声道组分轨，独立读取器逐字节核对全部 514176 个原生观察采样相同；不归一化，保留负零，明确不是完整立体声输出。
- C 的完整原生 WAV 同为 148224 帧，但与参考仍有 106120 个交错采样不同，最大整数差 10，首差帧 14979，归一化 RMS 差 1.3516665180094794e−7。该完整音频比较仍失败。

`pianoteq_compare_pcm24.py` 对完整 24-bit WAV 严格比较格式、帧数和所有样本，不时移、不截短、不拟合增益、不设容差。已检查相同数据、24-bit 有符号极值、单整数差与长度差四类行为。完整原生 WAV 的比较也不等于独立 JS 声源已生成完整立体声。

REA 证据已导出至本地 pass101 bundle/snapshot，共 371 条证据。商业模型表、反编译内容、预设及原生音频不随代码上传。没有使用 Pedalboard；完整琴槌接触力／弦反馈／制音毡方程、全部模型预设和网页声音等价性仍未完成。

## 验证器本身的浮点边界

第一轮扰动测试在 late-root 用例报 342 个 Q 正负零差异。原因是测试夹具的 `JSON.stringify` 把原始捕获的 −0 改成 +0，并非 late-root 参与预测。旧失败目录保留。新增精确保留负零的 JSON 写入，重放报告也保留负零，之后在新目录重跑；没有删除 Q 位级检查或增加容差。

修正序列化后，完整父链基线 7072729 项同，**16 项联合测试全部符合预期**：

- 所有 3349 个晚到全局快照翻转后，预测逐位哈希不变，仍零差异。
- 7 项单独目标／后续预状态扰动，各恰好 1 项差异，预测哈希不变。
- 首次包络种子改动产生 41515 项差异、预测改变；旁路 dispatch 输入改动产生 192 项差异、预测改变。
- 缺输出、错误槽数、错误 owner、错误计数、错误分支及缺分支六项结构问题均拒绝。

这些测试要求整个父链与释放组件同时通过，未沿用“父链失败但组件成功即可接受”的旧组件测试入口。
