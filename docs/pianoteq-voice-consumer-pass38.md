# pass38：声部队列消费、延迟与增益的实际样本验证

本轮把 pass37 计算出的模态组缓冲接到主线程消费点，并实现每组环形延迟和后段增益。四个正式对照共 **205344 项 float32 检查逐位同**，各次原生运行的真实 PCM 与相应官方基准相同。释放时主组另有附加信号，尚未实现；因此本轮仍不构成完整声部输出或最终立体声复刻。

## 从运行栈到实际消费缓冲

四个固定硬件点的初次运行栈包含：

```
46066c in 460110
  ← 278238 in 278128
  ← 85ede4 in 85eb58
```

REA 的直接 callers 与此一致。`85eb58` 调度当前声部，`278128` 准备矩阵并调用 `460110`。后者从 worker 环形队列复制输出组，再进行本轮观察的处理。三个内部组仍不是最终左右声道。

[捕获器](../scripts/pianoteq_capture_consumer.py) 以同一 H 对象的消费块序号配对各阶段，不用可能提前7至8块的 worker counter 代替实际消费时间。每次覆盖96个64样本块，共6144样本、128ms。顺序和矩阵维度必须完整，丢失阶段即失败。

pass37 自己计算的15个组块，按 `sourceAge / 64` 对应消费块序号51..65；2880个输入样本与真实队列消费缓冲逐位同。相差一个块的两个候选均2880项不同，原诊断不作为通过结果。该15块窗口使用自己计算的缓冲作为下游输入；其余81块仍使用观测到的上游组输入，不能称为整段独立声源。

## 432样本延迟与逐样本干声增益

原生 `3e229c` 的每组状态位于 `H+2b48+72*g`，本批三个组均为：

```
length = 432
writeGain = 0.04775214195251465
initial dryGain = 1
target dryGain = 0.9522478580474854
initial smoothingRemaining = 4800
```

[voice-output-delay.mjs](../dsp/voice-output-delay.mjs) 实现的顺序是：

```
y = f32(input * dryGain)
if elapsed >= length:
    advance dryGain smoother
    y = f32(y + ring[elapsed % length])
ring[elapsed % length] = f32(input * writeGain)
elapsed++
```

乘法与加法分别舍入，不使用融合运算。平滑器在形成当前样本干声后才前进，达到延迟长度前既不读回延迟样本，也不推进平滑器。不能简化为固定干湿比例。

只在开始读取一次环形缓冲与平滑器初态，随后连续计算96块，不逐块注入原生历史、干声增益或计数器。比较每块前后增益、计数器以及首尾完整环形缓冲。平滑终点吻合目标；未观测的平滑器重新播种分支明确抛错，未用任意近似补齐。

## 后段增益

`460110` 中各组还乘以 `f32(H9c * Ha0)`；本批为 `f32(0.611924946308136 * 1)`。独立重放与96块的所有18432个原生增益后样本逐位同，之后至最后捕获点另18432个样本保持相同。

这段验证从观测到的增益前缓冲开始，释放主组附加信号仍是缺口。它没有与延迟模块伪装成已经连通的完整声部链。

## 严格审计与实际音频

[重放器](../scripts/pianoteq_replay_consumer.mjs) 拒绝不完整或乱序阶段，逐位比较而非仅比较能量。正式审计还要求完整窗口、原生退出0和真实24-bit立体声 WAV 的 PCM 相同。

| 正式场景 | 重放检查 | 原生 PCM |
|---|---:|---|
| 默认预设，后段增益 | 39744/39744 | 原版干声基准同 |
| 默认预设，组延迟 | 55200/55200 | 原版干声基准同 |
| 同流程保存的 Stereo Width .25，组延迟 | 55200/55200 | 宽度修改的官方基准同 |
| CC64=96后抬起，组延迟 | 55200/55200 | 对应踏板官方基准同 |

延迟报告55200项包含输入桥接、早期组传输、延迟样本、平滑增益、首尾环形缓冲和后续两个非主组的数值检查。计数器另外作严格结构判断。增益报告39744项包含2880项计算源桥接及两组18432项样本检查。报告明确 `fullConsumerChainVerified=false`、`primaryReleaseInjectionImplemented=false`、`finalStereoAudioVerified=false`。

仅修改一个延迟比较目标、计算源窗口的一个队列比较目标、一个尾部环形缓冲目标，各自恰好产生一项失败并exit1；删除一个阶段也exit1。没有通过宽容误差掩盖失败。

## 保留的失败和下一处计算

最初把延迟输出直接对比更晚的主组缓冲，出现3199项不同；而延迟状态及完整环形缓冲已吻合。更细捕获确定差异发生在 `460908` 之后，仅主组受影响。不能将其误判为延迟公式错误或用观测值覆盖差异。该诊断保留。

此处 `0fbb44` 根据变化中的控制量、样本幅值、滤波器及振荡状态生成附加信号；`428784` 还支持独立组包络。本批后者为非活动且增益1。下一轮应恢复前者的真实递推、滤波和信号加法，并验证主组3199项差异，再继续向 `51fad4/89806c/713804` 的后级混合推进。不能仅因释放触发，就把尚未解释的信号叫作完整制音毡耦合。

七个调试尝试中，最初一次因捕获模块文件写入目录错误而在导入前退出1，未运行目标、无WAV；日志保留，确认终态后才修正目录。其余六次均完整捕获、原生退出0、PCM同各自官方基准。两个中间细分运行用于定位，不冒充额外正式重放通过场景。

REA 首次通过npm入口的初始化未返回，保存Node采样栈，结束自己持有的进程树并确认终态。使用同版本已安装缓存入口和私有工作目录后初始化立即成功；没有重装、升级软件或修改客户端权限，也未证明首次等待的唯一原因。
