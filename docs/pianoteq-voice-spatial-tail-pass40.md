# pass40：声部尾部的空间反馈与辅助信号分配

本轮继续越过pass39的最后捕获位置。新发现的合并/还原、三行空间反馈、淡入和辅助信号分配已写入 [voice-spatial-output.mjs](../dsp/voice-spatial-output.mjs)，默认短音窗口 **176640项逐位同**。真实捕获的原生WAV正常退出0，PCM与官方干声基准逐字节相同。

这是同一个A4音符的96个64样本块，128ms；三个内部组及其三行输出仍不能命名为最终左右声道。尚无JavaScript整段立体声WAV，尚未接入网页。

## 先合并再还原并不逐位保持输入

`5be1fc` 把组1和2逐个加进组0；后续 `960b7c` 以同样组顺序减回。每步都舍入，所以不能把这对操作优化掉。本次96块有2072个主组样本发生逐位变化。

新 [捕获器](../scripts/pianoteq_capture_consumer_tail.py) 在合并前、合并后、空间处理后、辅助分配后读取真实矩阵。输入取自pass39重放计算出的三个增益后组，不把本次观察到的主组样本逐块用作预测输入。pass39报告新增保存这些计算结果，数值范围未改变，重新审计仍80996项通过。

本批 `H29f8/H29fc` 均为0，非线性分支未动态验证，重放器明确拒绝非零情况。

## 三行、四lane的五tap网络

`29c430` 的实际路径启用 `080e4c → 2a2910`，把三个组装入四lane向量的前三lane，分别经过三个空间行的反馈环形缓冲。第四lane为0。本次每行128个向量槽、512个float，五个tap。初始环形缓冲已核对为零，随后连续计算96块，不读取后续原生历史作输入。各行起始写入计数器由首tap延迟生成，与原生值吻合。

五个tap的读写位置、乘法、FMA、减法以及同一步先读取后写回的次序都按实际指令实现；三行的tap数据不同。末尾完整环形缓冲和每块计数器都作检查。当前tap系数和延迟仍从初始化观察读取，尚未恢复其完整参数生成。

空间效果在3ms后开始、用10ms淡入。淡入角度中的倒数先舍入float32，再用双精度π/2相乘；时间差用float32 FMA。达到终点后原生淡入计数停在624，并未继续按块增长。重放器验证了这一行为。静音组休眠优化和其它空间路径尚未覆盖，遇到相应输入拒绝重放。

## 为什么不能直接使用JavaScript正弦

首次连续重放时，环形缓冲已逐位同，但空间输出在淡入阶段有49项不同。原诊断保留，没有调整容差。

通过独立小程序用 `dlsym/dladdr` 只读系统库，确认本机macOS 26.5.1/25F80 arm64 `libsystem_m.dylib` 的 `sinf` 实现。重建其双精度范围缩减、原生多项式和FMA顺序后，49处差异消失。[native-scalar-sin.mjs](../dsp/native-scalar-sin.mjs) 只接受已检查的有限快路径 `|x|<120`，其它范围明确拒绝。

独立 [C oracle](../scripts/pianoteq_scalar_sin_oracle.c) 调用系统sinf，按IEEE位返回结果。[数学对照脚本](../scripts/pianoteq_replay_scalar_sin.mjs) 覆盖淡入输入、边界、正负零、次正规数与固定随机输入，2632项逐位同；这部分对照不是目标程序执行或注入。原始系统库字节不提交。

## 主组与辅助信号

空间处理把每个组展开成三个实际不同的行。`2e2044` 将每行辅助信号的一部分加回主组：

```
primary = fma32(auxiliary, fraction, primary)
auxiliary = f32(auxiliary * f32(1-fraction))
```

本批fraction=0.33199700713157654。辅助输入在新捕获位置已经有三个不同的行，不能只复制第一行。它们的来源尚未独立计算，本轮报告明确 `auxiliarySourceStillObserved=true`。空间反馈、淡入和主组样本来自计算，辅助源仍是观察输入，两者边界分开说明。

[重放器](../scripts/pianoteq_replay_consumer_tail.mjs) 比较了三组输入、合并结果、空间输出、未变的辅助输入、最终三行组样本、辅助分配、首尾完整反馈缓冲及计数器。176640项包括这些中间与末尾检查，不能当成176640个独立音符。

五个比较目标各改变一ULP（输入、空间样本、最终主组、辅助结果、末尾环形缓冲），分别恰好一项失败并exit1；删除一个阶段也exit1。这些比较目标没有被用于更新自己的反馈历史。
