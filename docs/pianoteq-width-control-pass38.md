# pass38：Stereo Width 保存与实际音频 A/B/A 对照

本轮补齐 pass37 缺失的保存流程对照。在同一个自己启动的官方 `--no-prefs` 实例、同一份干声初始预设和 running 音频输出下，按 `.5 → .25 → .5` 设置 Stereo Width，每次等待更新提交再保存。三次之间不重载预设。

[实验脚本](../scripts/pianoteq-width-aba.py) 核对 GUI 监听端口的 PID；创建唯一的新用户预设 bank；保存后将自己生成的 FXP 移到私有研究目录；依次用新进程恢复所有参数，再用官方 CLI 渲染同一短 MIDI。原程序、授权、厂商预设和用户偏好未修改。

所有 WAV 为 48kHz、24-bit、双声道，dither OFF。基准 A/A 的 226304 个交错整数样本全部相同，也与先前原版干声基准相同。B 与 pass37 修改预设的实际 PCM 相同。相对 A，B 公共长度内有224048个样本不同，首差为第980帧，最大整数差1471600，归一化 RMS 差0.013391630313525216；尾部多3840帧。

三份预设读回的参数 ID 集合一致，误差容限1e-6，没有不匹配。B 相对初始状态仅 `stereo_width` 改变；两份 A 无参数改变。三次新进程验证均正常退出0。临时 GUI 已请求 quit，已核对其进程消失、8341/8342端口关闭；该分离启动实例不虚构退出码。

这使“宽度修改后的音频变化”有了同流程、可重复的基准对照。结合 pass37 在 B 中三个模态组仍完全相同、H+128仍为1的实际捕获，可继续向后级寻找宽度计算。尚未恢复 Stereo Width 到具体底层系数的映射，不能把显示值0.20直接当作已证实的内部系数。

这不是 JavaScript 发出的等价钢琴 WAV。网页声源、最终立体声混合、完整初始化及所有模型/预设的等价性仍未完成。
