# pass102：释放后到下一处理端点（验证中）

pass101 的同次内部链路通过止于 `460a4c`。它不能直接接到空间处理：中间仍有主组／辅助矩阵清空、两个处理调用及后续增益、滤波等路径。当前完整声音目标保持未完成。

本轮将同一六槽采集扩展到 `460acc`。槽位依次为 consumer → consumerPost → consumerCross → consumer，不增加第七个硬件点。新计算只支持两个处理器实际 flag != 1 的旁路分支；遇到活动分支严格拒绝，尚未恢复其完整计算。

## 指令证据及输入边界

- H+30b5 的低位为零时，原生清空全部三个组。H+30b6 的低位为零时清空辅助矩阵。
- `076fec` 的第一个参数为 H+1740，入口 byte != 1 时直接返回。
- `627778` 的第一个参数为 H+1918，入口 byte != 1 时直接返回。
- `49cfd0` 通过 bzero 清空向量存储，逻辑样本应为正零，不能保留旧负零。

组输入来自同次自算释放后输出；`consumerPost.channels` 与 `consumerCross.channels` 都只作为比较目标。辅助矩阵目前仍以实际 consumerPost 观察为输入，明确 `auxiliarySourceObserved=true`，不声称它的声源已独立生成。

独立控制检查覆盖低位保留／清空、负零保留／正零清空，以及两个活动处理器的拒绝。现有 pass101 完整数据在新入口仍通过 7072729 项、零差异。新的真实 cross 端点尚未验证通过。

## 采集问题保留

A 次在第五次初始化之前缺少一次工作完成回调：epoch 3，expected=1280，actual=1344；完整采集严格失败，没有拼接或补造输出。原生随后正常 exit 0，但完整 WAV 143360 帧，参考 148224 帧，长度比较也失败。

A 另一次停止位于系统 `__psynch_cvsignal+8`，同时工作线程停在登记观察点。只读核对了系统函数名、模块、12 字节 mov/svc/返回分支、notify_one 调用栈和原生调用者；专用检查通过后执行一次普通 Continue。未改变程序代码、数据、PC、寄存器、信号或断点设置。

B 改为每个有效观察回调都显式停止，逐次审计普通 Continue，而非仅槽位替换后停止。全程仍六个活动硬件点。另一次内部 pthread 启动停点依据 LLDB 的 internal breakpoint −2 及其实际位置核对，当前指令明确不是 BRK，且存在同时命中的登记观察点。恢复规则与原有基础采集器的内部线程规则一致；其它停点仍拒绝。

完整重放现要求 B 的 `owned-resumes.jsonl` 审计：每条观察的硬件 ID／stop ID 必须对应已审计的停止与恢复，单独声明 `allObservationBarriers=true` 不足以通过。B 正在采集；目前已观察到三个组保留、三个辅助行保留、两个处理器关闭的实际配置。尚未宣布新端点整链或完整音频通过。
