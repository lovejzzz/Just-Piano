# pass102：释放后到下一处理端点（同次重放通过）

pass101 的同次内部链路通过止于 `460a4c`。它不能直接接到空间处理：中间仍有主组／辅助矩阵清空、两个处理调用及后续增益、滤波等路径。当前完整声音目标保持未完成。

本轮将同一六槽采集扩展到 `460acc`。槽位依次为 consumer → consumerPost → consumerCross → consumer，不增加第七个硬件点。新计算只支持两个处理器实际 flag != 1 的旁路分支；遇到活动分支严格拒绝，尚未恢复其完整计算。

## 指令证据及输入边界

- H+30b5 的低位为零时，原生清空全部三个组。H+30b6 的低位为零时清空辅助矩阵。
- `076fec` 的第一个参数为 H+1740，入口 byte != 1 时直接返回。
- `627778` 的第一个参数为 H+1918，入口 byte != 1 时直接返回。
- `49cfd0` 通过 bzero 清空向量存储，逻辑样本应为正零，不能保留旧负零。

组输入来自同次自算释放后输出；`consumerPost.channels` 与 `consumerCross.channels` 都只作为比较目标。辅助矩阵目前仍以实际 consumerPost 观察为输入，明确 `auxiliarySourceObserved=true`，不声称它的声源已独立生成。

独立控制检查覆盖低位保留／清空、负零保留／正零清空，以及两个活动处理器的拒绝。现有 pass101 完整数据在新入口仍通过 7072729 项、零差异。新的真实 cross 端点结果见下文；活动分支与清空分支仍没有本次原生动态覆盖。
