# pass255：两张附加谱表独立生成

[附加谱表生产器](../dsp/archive-excitation-extra-tables.mjs)从当前模型的B1a20与B1a50生成floor/blend表，并接入同次连续发声。当前A4的blend控制非零，因此后一张表实际参与声音计算；floor控制为0，不能把两者都称作本场景的活动音频分支。

## 完整生成过程

原生1c7b54..1c7b8c调用00bf48，由模型B1a20生成Gc98；1c7b90..1c7bcc调用736d40，由B1a50生成Gcb0。两个入口共同转到00bfa8：

1. 复用5be5fc的音符曲线列表构造，混合相邻成员并合并节点。
2. 读取结果最后一个X，向上取整为采样数，要求小于1000。
3. 在谐波1至采样数调用1d17f8，明确使用边界模式0。
4. 从末尾逐个移除精确零值，不改变中间零值。

这里不能直接用钳位插值替代模式0：多节点曲线在支撑区间之外返回0；单节点快速分支在左侧返回0，在右侧保留唯一Y。插值仍使用float32倒数再乘法，新项先落地、旧项FMA的顺序。合成边界测试覆盖非整数端点、单节点例外、正/负零后缀和无效输入拒绝，不作为原生音频证据。

普通非空曲线列表是当前支持范围。当前A4生成floor表13项、blend表12项，与两种源模式的目标完全一致。运行时生产器不读取对应捕获表；连续链将自产数组传给实际附加谱计算。

## 新原生与连续音频验证

[两点只读采集器](../scripts/pianoteq_capture_excitation_extra_tables.py)在1c84a0记录配置结果，在695108记录实际消费者使用的完整表及模式。[核对器](../scripts/pianoteq_verify_excitation_extra_tables.mjs)独立从存档生成预测。

新采集音符21、60、69、72、108，15条配置记录及10次按MIDI顺序的双模式消费者调用；465项表值对照，0差异。进程terminal、exitStatus=0，两组错误列表为空。父音板采集completed=false保留，五音符本批没有连续PCM等价结论。

## 因果验证与保留的失败

- 把第一组原生floor/blend目标的25个表值各加1：完整报告恰25处校验差异，49,152个自产音频样本全部不变。
- 第一次在私有解码模型的blend曲线内部Y加.1，填充了原有零后缀，使裁零后的表长改变；严格完整表检查立即拒绝。原失败输入和日志保留，没有放宽检查。
- 第二次把解码模型中全部blend成员的Y乘.99，保留零后缀：完整运行614,833项检查，190,545处差异；实际49,152个连续样本中49,148个改变。没有布局或表长拒绝，没有从停止后的区域推算音频差异。

后两项只改私有解码输入，没有改商业模型或预设。因果实验说明自产表参与声音，尚不是修改原生预设后获得新音频的等价验证。

## 证据与剩余

基础谱表、其余五张附加谱表、u/lowerControl等表达量仍未独立生成。完整接触/弦反馈/制音耦合、最终立体声、全音区与全部工厂预设、AudioWorklet、保存重载及实时性能验收仍未完成。网页音源未因这批离线研究自动获得Pianoteq声音；生产器整体仍限制已验证五击A4和明确运行时条件。
