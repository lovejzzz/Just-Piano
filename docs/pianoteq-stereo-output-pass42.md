# pass42：实际两声道路由、末级音量与 PCM 窗口

找到 `7d57a0` 内实际输出两行的路由缓存，新增 [路由捕获](../scripts/pianoteq_capture_output_routing.py)、[路由重放](../scripts/pianoteq_replay_output_routing.mjs)、[末级音量捕获](../scripts/pianoteq_capture_output_volume.py) 和 [音量/PCM重放](../scripts/pianoteq_replay_output_volume.mjs)。默认和width25各160个64样本块，四个正式重放共412160项float逐位同。两组计算出的PCM前10240帧分别同官方WAV的对应前缀，合计40960个交错整数样本无差异。

这没有完成独立声源：pass41全局输出边界已由计算报告核对，但到两声道路由前的处理中间段仍观察。默认窗口该段27575项不同，尚未解释。网页没有接入本批研究模块，也没有生成整段等价立体声。

## 三行如何送入左右两行

`28b728` 将输入三行复制到八行工作矩阵，余下五行清零；当前未启用其额外处理。捕获对照八行全部样本，确认前三行逐位等于路由前的三行矩阵，后五行全零。路由表固定为：

| 输入行 | 输出行 | 延迟 | multiplier |
| --- | --- | --- | --- |
| 0 | 左（0） | 0 | 1.1220183372497559 |
| 1 | 右（1） | 0 | 1.7782793045043945 |
| 2 | 左（0） | 0 | 0.39810711145401 |
| 2 | 右（1） | 0 | 0.39810711145401 |

所有tap首尾增益及外部增益为1。复用pass40的连续缓存实现，按表顺序FMA叠加，而非先用JavaScript双精度相加再舍入。初始缓存要求逻辑空，160块读头和有效标志全部由自己的历史更新并与原生核对；读取结果不用于回填历史。表仍从初始化观察，没有宣称已恢复GUI到这些增益的精确公式。

每场景163840项包括pass41计算边界30720、八行工作源81920、两声道结果20480、原三行未变30720。边界验证通过不代表中间的全局处理已经独立计算。

## 末级音量及输出格式

`4f9904` 对每个样本取得 `84df2c` 的当前电平，再分别乘两个声道。在两组实验中状态始终为：

```
current = target = 0.15848931670188904
multiplier = 1
remaining = 0
output = f32(stereoSample * current)
```

[output-level.mjs](../dsp/output-level.mjs) 只接受已验证的稳定状态；活动音量斜坡明确拒绝。输入来自另一次通过数值和真实WAV审计的两声道路由重放，未使用本次末级输出作预测输入。每场景42240项包括输入20480、输出20480、首尾状态1280。

最初直接24位round-even、截断、floor分别在默认窗口产生9071、7732、8处差异，报告保留。先舍入为signed32再取高24位消除了默认差异，但使用缩放值 `2^31` 在width25留下3处差异，失败报告和生成的前缀另存，未被最终报告覆盖。正确缩放值为 `2147483647`。

随后从不可变ARM64反汇编定位常数 `100b448c0`，核对其double值确为2147483647。实际路径 `91bae8..91bb08` 用双精度FMA计算：

```
biased = fma64(floatSample, 2147483647, 6755399441055744)
signed32 = reinterpret_low_signed32_bits(biased)
pcm24 = signed32 >> 8
```

[pcm24.mjs](../dsp/pcm24.mjs) 实现上述FMA舍入与高三字节输出。新增 [PCM捕获器](../scripts/pianoteq_capture_pcm_conversion.py) 在实际转换循环前后设两个只读硬件点，取得六个256帧写入块；[整数重放](../scripts/pianoteq_replay_pcm_conversion.mjs) 的3072项原生signed32全部相同，证明该float转整数指令确在CLI运行路径执行。输入包含发声样本。24位打包的具体下游指令尚未动态绑定，取高三字节的行为由两组真实PCM前缀验证。其它位深、dither、非有限值、饱和边界及活动音量斜坡未覆盖；实现对未验证范围明确拒绝。

## 真实音频、失败记录和负对照

五次原生捕获均完整、正常退出0，PCM同各自参考：

| 场景 | 原生帧数 | 完整原生PCM SHA-256 |
| --- | --- | --- |
| 默认 | 113152 | `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6` |
| width25 | 116992 | `839466790922acd983504f42cbed5451900125f0672a5adb4867112a799e23f0` |

这里的完整PCM核对证明捕获音频符合基准；JavaScript生成的是每组10240帧前缀，不能把整段原生WAV视为完整独立引擎的输出。前缀各约0.213秒，含起始静音和发声。

八个负对照均exit1：源矩阵目标、两声道目标、末级输出目标、末级状态目标各改一ULP，分别恰好一项float失败；改变缓存读头、删除路由事件结构失败；参考WAV改一个PCM整数时float仍通过但PCM恰好一项失败；原生signed32目标改1也恰好一项整数失败。数值比较、原生进程状态和PCM比较共同参与正式审计。

私有证据在 `~/.local/share/just-piano-analysis/` 的 `debug-pass42-*`、`pass42-final-audit.json`、失败量化诊断、`pass42-negative-controls/`、反汇编片段及清单。`pass42-width-volume-audit.json` 是先前缩放假设的失败审计，继续保留；`pass42-final-audit.json` 才是当前实现的最终重跑。REA导出282条累计证据及快照后关闭。硬件捕获只读，没有修改程序、授权或macOS安全设置，也没有使用Pedalboard。
