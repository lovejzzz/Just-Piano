# 第九轮：真实模态块状态递推与浮点运算次序

本轮把此前仅依据 REA 和 ARM64 展开的自由振荡递推补为实际运行数值验证。一个固定内部硬件断点同时读取整块开始前的 P/Q、系数和整块结束后的 P/Q：128 条真实记录、每条 16 lane、每块 64 sample，**4096 个最终 float32 状态逐位一致**。2048 个初始 lane 全部非零。该次采集完整渲染正常退出，最终 PCM 与官方原版相同。

这是普通无输入分支的实际状态反馈证据，未将它冒称为瞬时琴槌接触力或完整琴槌—弦—制音毡联立积分。

## 单点读取位置及边界

`1007c0bcc` 块核的 `1007c0d50`，位于内部四 sample 展开循环之后、16 lane 状态回写之前。此时内存仍保存块首状态，寄存器保存块尾状态，不需要入口/返回配对，也不需要在回调中切换断点。

| 数据 | 来源 |
|---|---|
| 初始 P/Q，16 个 float | x9 / x8 指向的内存 |
| A/B，32 个 float | x20；每四 lane 依次 A0/B0/A1/B1/A2/B2/A3/B3 |
| 最终 P | v21、v20、v23、v16 的四个 float lane |
| 最终 Q | v22、v19、v18、v17 的四个 float lane |
| sample 数量 | w21 |
| 累加输出缓冲 | x19，向上补齐至四 sample |
| 调用关联信息 | thread、sp、P/Q/系数/输出指针、x11/x24 剩余组数 |

128 条保存记录来自两个实际工作线程。没有为取得数值写入代码、寄存器、模型或许可状态。沿用经用户授权的独立重签名副本，装断点前验证准确 `__text` SHA256；不用 Pedalboard。

## 公式正确仍不足以逐位重现：四步展开的 FMA 顺序

数学递推为 `P'=Q, Q'=A*P+B*Q`。但不能在每一步都用同一 FMA 顺序。令 `r(x)` 表示一次 float32 舍入，`fma(a,b,c)` 表示只在乘加结束舍入一次，块首两帧为 `P0,Q0`。原始指令的四 sample 周期明确是：

```text
s1 = fma(B, Q0, r(A*P0))
s2 = fma(A, Q0, r(B*s1))
s3 = fma(A, s1, r(B*s2))
s4 = fma(A, s2, r(B*s3))
P0,Q0 = s3,s4
```

随后重复这一周期。第一步对应 `1007c0c74/78`，第二步对应 `1007c0c94/98`，第三步对应 `1007c0ccc/cd0`，第四步对应 `1007c0cec/cf0`。每步前后交换 P/Q 可写出相同数学递推，但乘积先舍入的是哪一项不同，浮点结果也会不同。

第一版验算器曾把第一步形式错误用于全部 sample，32 条记录的 1024 个最终状态中有 962 个不符。保留该失败输出于本地 v1 证据目录；修正为指令的四步周期之后，1024 个全部匹配。扩展至第二次独立采集的 128 条后，4096 个最终状态仍全部匹配。完全不使用融合乘加的负对照则有 3853 个状态不符。这些差异不能当作实现误差容忍掉；浏览器引擎若需要逐位复现，必须明确实现这种 FMA 和舍入次序。

第一条记录 lane 0 的实际数值为：

```text
A  = -0.9998866319656372
B  =  1.9965736865997314
P0 = -0.052373256534338
Q0 = -0.035850320011377335
64 sample 后：
P  = -0.1023063138127327
Q  = -0.1177024245262146
```

独立验算使用系统 `fmaf` 与显式 float32 乘积舍入；末态与读到的寄存器 float32 字节一致。每条记录的初始 P/Q 与系数都来自该条实际捕获，未拟合增益、相位或衰减，也未使用前条输出推测本条输入。

## 采集渲染自身的音频对照

同一 `audio-pass5-dry/dry.fxp`、同一新建的短 MIDI（A4，力度96，CC64=0）、48 kHz、24 bit、dither OFF，分别由本次带硬件断点的副本与官方原版 CLI 渲染。两次均正常退出；双声道 113152 帧的 PCM 逐字节相同：

```text
SHA256(PCM) = 1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6
```

这项对照只证明本次硬件采集没有改变这份实际输出，不能把一个预设/音符的相同输出推广到所有预设或独立网页引擎。

## 证据和剩余范围

公开脚本为 `scripts/pianoteq_capture_recurrence.py` 和 `scripts/pianoteq_verify_recurrence.py`。采集脚本需要 LLDB，导入前设置 `PIANOTEQ_CAPTURE_DIR`；复用相邻脚本的 `__text` 校验。验算器读取真实 `runtime.json`，失败时返回非零。它的系统 `fmaf` 库路径针对本次 macOS 环境。

本机完整证据为 `~/.local/share/just-piano-analysis/debug-pass9-recurrence-v2/`：128 条原始快照、日志、独立验算、WAV、PCM 对照与 SHA256 清单。v1 目录保留初次采集和错误统一 FMA 重放的结果。128 条还保存了块输出和关联指针，便于进一步验证模态求和的原始浮点顺序；本报告的 4096 状态计数不包括这些输出 sample，不能将尚未独立验算的输出计作通过。

该入口证明正在运行的固定系数自由振荡模式确实使用局部两帧反馈。它未覆盖有输入 C/D 分支、bzz 约束、系数刷新时的状态投影、模型全部替代实现或琴槌瞬时接触力。完整复刻仍缺这些分支、上游全部预设模型表、声板/效果和完整浏览器输出的验证。
