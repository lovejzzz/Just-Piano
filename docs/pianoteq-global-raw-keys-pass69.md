# pass69：节点时间推进与限幅聚合接到全局模态链

将pass68观察的原始键值改为独立计算。105键的节点位置按块时钟连续推进，计算两个上界及最大值聚合，再经过曲线映射、dirty标记、衰减限速、系数刷新与连续模态输出。128块4699172项检查逐位一致，完整原生PCM与官方参考相同。节点速度、键状态与链表成员仍是输入，完整接触力模型没有因此闭合。

## 节点、上界与原始键值

REA恢复的 `5e1d18` 接收dt、manager与键槽号，调用者 `096558` 遍历全部105键，将返回float写到原始数组并把数组flag清零。此后 `674a08`、`050220` 可能继续修改数组；本配置两个开关均为0，采集器与DSP明确拒绝活动分支。

[实现](../dsp/global-raw-keys.mjs) 从manager+c08的块长与采样率计算 `dt=float32(float32(samples)/sampleRate)`，原生s0只作比较。实际为64/48000，未把观测dt作为积分输入。

上界由同次控制字段计算，以下r表示每键320字节记录：

```
A = clamp(float32(float32(host.c0 + r30) * float32(1 - host.bc)), 0, 1)
if A < float32(0.01): A = 0
B = clamp(float32(root.e8 * float32(1 - r34)), 0, 1)
keyCap = float32(1 - A)
softCap = float32(1 - B)
```

普通活动节点以FMA32计算 `max(0, fma32(dt, velocity, position))`，先限制到keyCap并保存intermediate，再限制到softCap并保存position。键状态的另一标志可先强制起值1；无制音的分支直接保存两个1。dt=0路径只执行限制，未在本次正向窗口动态覆盖。

每键结果以r1e是否非零给0或1为起值，再取所有节点最终position的最大值。原生二值模式开启且root90>0.5时可覆盖为1；本次该模式为0，正例未覆盖。字段的物理单位尚未证明，不把这个有界状态直接称作弦位移或接触力。

## 持续状态与仍观察的事件输入

第一次raw阶段仅初始化一次105个已有节点位置；之后这些位置由自己持续推进。block14出现一个新节点，按已验证的零初态建立自己的状态，并核对原生零值；不以每块原生位置重置。

新节点的正速度为1e10，46次正向推进都钳到上界1；block60改为约−98.60134，自己计算8次非零释放推进，直到block67降到0。这个1e10值属于此状态机的推进控制，不能直接解释为物理琴槌速度。新节点的产生、速度更新以及键flag仍来自捕获，其上游事件/参数公式待恢复。

节点链表成员仍观察。核对旧节点消失时自己的position/intermediate均为0，但没有实现 `90cab4` 的完整链表清理、声部归属与回收算法；保存的旧状态不会注回新节点。`5e1d18` 同时写声部挂起控制、处理重复声部等其它副作用，本模块也不声称全部包含。
