# pass103：Rattle 后续峰值触发信号（组件实际音频通过）

`460dd0` 从 H+2f38 取实际控制值，调用 `30bd30`，对象为 H+28a8，主组输入和输出为同一矩阵。它位于 pass102 的 `460acc` 之后，不能把此前 Rattle→模态系数的验证当成这段音频处理已经实现。

以下计算已由同次原生组件观察验证；它仍以观察的上游主组和共享输入表为输入，并非完整独立声部。REA 证据为 `ev_74fbf0b0d291f63c0f6894e6e1e4f88f94ea5372eab5cd910e0d6fd08191cd52`，不可变目标 SHA-256 仍为 `8e375ff63fcb9056ae1eadd9770d28a0a61c7d79209f52a74f027c3bc13c2094`。

## 触发和控制参与计算

每个样本按 float32 推进 elapsed+=1，记录主组绝对值峰值。仅在 `period <= elapsed < f32(period+1)` 的区间执行触发检查，然后 elapsed 减 period，峰值清零。

历史 floor 取自身和当前峰值的较大者。控制 u>0 且 `double(peak) > double(floor)*1e-6` 时，计算：

```
product = f32(u * peak)
targetDb = product == 0 ? -980 : fma32(20, log10f(product), 20)
deltaDb = f32(targetDb - level)
level = f32(level + levelStep)
```

只有 deltaDb > −200 才开始新的表驱动信号。原生先计算 f32(u*u)，再依次相乘：

```
amplitude = f32(f32(f32(peak * scale) * u) * f32(u*u))
```

这给出另一条明确的控制→音频路径：幅度含 u 的三次方，但不能把三次乘法改成一次 double pow，也不能把该路径命名为完整琴槌或制音毡接触方程。

## 表、滤波和叠加

新信号使用共享输入表，从 cursor=0 开始。池中的每项占72字节，包含五个实际滤波系数、四项历史、表游标和幅度。新项放入循环池的 head 前一格，容量满时覆盖最旧项。

系数调用为 `0ab720` 的 type=3，归一化频率 `f32(2000/f32(sampleRate*0.5))`、Q 的实际 float32 常量0.4，deltaDb 作为增益控制。本次系数、FMA 次序、池生命周期与历史传递均已逐位对照。

每个活动项从共享表取得输入，按一次乘法和四次 FMA 的原生顺序更新四项滤波历史，再用 `fma32(filtered, amplitude, currentOutput)` 叠加。较旧活动项另以对象 decay 逐样本衰减；最新项的路径没有这一步。不能把它们合并成统一衰减循环。表读完后减少活动项数。

u=0 且没有活动项时，原生只清 elapsed 和 peak 后返回，输入保持不变；u 回零时尚未结束的项仍会继续发声。

## 实际验证与边界

新增独立的两固定硬件点采集器 `pianoteq_capture_rattle_burst.py`：函数入口与统一返回前，读取真实输入、控制、池状态、活动历史和输出，捕获共享表首次使用的数值。所有目标内存只读；只执行普通 Continue，不改程序状态。未使用槽的原始系数字保留为整数，避免把未使用内存误当有效 float；历史只读活动项。

该组件的主组输入和共享表仍是观察输入。必须先用同次真实音频验证，再连接到完整独立声部链，不能把组件通过改称最终立体声、全部预设或完整物理耦合已完成。两固定点采集已启动；首次实际读取到 sampleRate=48000、period=109.09090423583984、scale=1.9952622652053833、levelStep=0.30000001192092896、decay=0.9386420249938965。完整原生进程34527正常exit0，配对无缺口、错误为空；3314次调用、五个声部均从counter=0连续捕获。

`rattle-burst.mjs` 独立生成初始动态零状态，随后携带elapsed／peak／floor／level、池head／active、系数、游标、幅度和滤波历史。原生目标只比较，不逐块回填；未写入槽的垃圾位不作输入，也不当有效历史比较。

同一A4／48kHz MIDI场景的完整组件重放348482项零差异，含212096个真实输出采样，333次触发。40752个自算输出样本与原输入不同；73个控制已回零但旧项仍活动的块也匹配。两固定硬件点及6630条普通Continue审计对应所有观察。不是把关闭／静音旁路当作完整活动计算通过。

18项扰动测试全部符合预期：8个目标改动各恰好1项差异且预测不变；未写入系数槽改为NaN位仍通过且预测不变；实际控制、共享表、scale、decay四种源改动改变预测；缺返回、非零初态、未知表切换、无审计停点、错误观察地址五项结构拒绝。

从自算组件输出导出五条不归一化float32单声道WAV，另一读取器与本次原生返回点全部212096个样本字节一致。它们包含观察到的上游主组，不能标成网页独立发声或最终立体声。

完整原生WAV与参考均148224帧，但101091个交错样本不同，最大整数差10，首差帧13036，归一化RMS差1.5383668884109965e−7；完整音频比较仍失败。组件未与pass102跨运行拼接为通过整链。下一步必须恢复并连接中间处理及同次完整声部输出，移除共享表／上游观察依赖。
