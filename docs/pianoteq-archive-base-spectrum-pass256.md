# pass256：基础谱表接入独立连续链；A0频率缺口仍失败

[基础谱表生产器](../dsp/archive-excitation-base-tables.mjs)从模型频率锚点、两组向量曲线和独立构造的初始主源频率生成正/负斜率两张表。A4连续链已接通，自产坐标与选中的基础谱表同时传给谱加权及支持模态计算。没有把支持模态消费者遗漏在原生输入上。

本批新五音符严格核对**未全部通过**：A0初始源频率有差异。没有用诊断输入替换严格预测，也没有扩大连续生产器仍限A4的支持范围。

## 参数到基础谱的完整运算

2665bc从模型B10d0复制频率锚点，从B10f0/B1140按音符求两组向量曲线。1c721c..73e4把向量各值乘float32分贝幅度常量。1c8998..89d8对频率锚点逐项调用原生logf。

1c89d8..8c38以初始化主源第一列频率的logf为自变量，在上述对数频率锚点间作钳位线性插值。这里先float32除法，再以“新项乘法落地、旧项FMA”混合；不能用缓存倒数替代除法。两组输出分别保存到G248/G260。

后续695108前的谱计算按自产slope正负选择表。即使正在计算第二种发声模式，基础谱也来自**初始主源**，截取所需前缀，不能按第二源或力度/随机扰动后的频率重建。主源的高频裁剪决定坐标前缀；当前A4模型保存35项，独立源保留26行。首次实现误要求完整存档坐标数等于运行行数，被检查拒绝；修正为由独立源的保留行数决定前缀，失败v1日志保留。

正/负两张表在构造时一次生成，每次发声实际用自产硬度和谱控制选择。原生baseTable只作比较。相同自产表和坐标也用于supportLogAmplitudes及附加支持模态，消除了这两个消费者的捕获别名。

## 新原生多音符验证及真实缺口

[只读采集器](../scripts/pianoteq_capture_excitation_base_tables.py)在695108一个硬件观察点读取实际消费者、两张完整缓存谱、初始主源频率矩阵、坐标和采样率。[核对器](../scripts/pianoteq_verify_excitation_base_tables.mjs)从同一存档上下文构造各音符主源，再计算谱表，原生矩阵仅作严格预测的目标。

共3,252项检查，严格结果passed=false、退出码1。A0的207行单列初始频率在两次消费者中均不同，频率414项差异；负谱162项、正谱268项、选中谱162项差异。最大初始频率绝对误差约4.894Hz。矩阵形状无差异，其余四音符的初始频率、两种谱表及坐标均未发现差异。

核对器额外提供明确标记的诊断：**只在诊断支路**把原生初始频率交给谱生产器，五音符两张表共1,204项、0差异。它不参与strict pass，也不用于实际A4连续链。这将A0失败定位到独立初始频率生产路径，不能据此宣布A0独立发声已完成。

最终原生进程正常终止exitStatus=0，采集错误为空，实际10次双模式消费者调用按MIDI顺序完整覆盖。正斜率消费者未实测，标志保留false。第一次双点观察在1c8c3c遇到LLDB报告的未归属EXC_BREAKPOINT，驱动拒绝恢复；日志与terminal=false记录保留。确认进程已结束后改用现有实际消费者的单点观察，未修改驱动的停点归属规则，也没有绕过目标保护或写入目标。
