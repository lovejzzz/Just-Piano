# 非零动态 Rattle 到连续释放包络：pass81

本轮把pass80的动态Rattle源接到同次运行的系数和连续包络，不拼接不同采集。目标仍为本机Pianoteq 9.2.5 ARM64；完整声部、接触力和浏览器音频未完成。

## 同次计算证据

[采集器](../scripts/pianoteq_capture_rattle_envelope.py)保留六个固定硬件点：10035f2c4来源、10085ed9c运行更新、1006e5270实际立方消费、1006e5360系数输出，以及100472f80/100472fd0包络前后。与pass80相比，去掉本轮未命中的更新B和setter站点，加入连续包络两个站点；不能声称本轮也逐次观察setter。

正式B进程87398正常exit0：5个声部、3312次源更新、121次系数（117活动）、3350个连续包络块、11次x变化。窗口complete=true、两个pending计数0、errors为空，六点最终全部关闭，硬件属性均为true。

[重放器](../scripts/pianoteq_replay_rattle_envelope.mjs)由观察到的R源携带自己的声部x；在活动消费处比较自己的x与实际模态x及立方值，冻结消费时x并计算D/rate/gain。自己的duration随后进入ReleaseProgressEnvelope，声部每个epoch仅以0初始化一次，逐块携带位置和样本计数，不从原生包络前/后值重置。目标duration和包络前后位置仅供比较。每个块计数必须等于自己累计样本数，返回必须按线程/epoch/modal/计数完整配对。

**14085项float32比较零差异，3350个块的连续计数/配对检查通过。** 不把另行执行的整数结构断言加到这个float计数中，也不把pass78/80计数相加。

22项负对照全部拒绝：初始源/目标、整段改源、移除整段更新、cube/modal/model/u、三个系数目标、包络前/后/时长/计数/时间步、缺失返回、错误所有权、缺失活动事件、无依据重复返回及不完整窗口。改变u产生1008处差异，改变模型常数产生60处，说明错误系数会继续传到后续包络，并非只检查局部目标。

## 失败窗口与宿主停顿

A进程87206正常exit0，但采集在1019次包络返回命中时出现无pending的KeyError，只有1018个完整块；其窗口保持complete=false，六点关闭。没有拿其后续原生WAV补齐数据。实际原因尚未确认，不能断言就是重复回调。

为诊断加入严格重复返回识别：无pending时，必须与同线程上一个已完成返回的epoch、voice、modal、counter和position完全相同，才单独记duplicateEnvelopeResult；其它情况仍报错。**正式B重复返回数为0**，所以它的通过不依赖该例外。另行构造的宿主重放夹具验证精确重复可接受、无先前返回则拒绝；这不等于原生运行观察到重复。

B中普通Continue守卫遇到libsystem_pthread.dylib的start_wqthread+4异常停顿，元数据为[6,1,0]，同时另两线程在已登记updateA/envelope硬件站点。按LLDB的内部-2断点模块、file地址+4和load地址+4逐项核对后，仅重新定义宿主Continue辅助函数，采集记录、站点和目标状态不改写，然后继续同一进程完成。保留初次拒绝及现场输出。新守卫还要求另一线程匹配自有真实站点，不能单凭内部位置继续。

13项宿主守卫检查中，实际形态的两类配对各正常Continue一次；错误内部属性、模块、file/load、位置索引、未知ID、未知下一条指令及无自有站点共11类均拒绝且Continue为0。所有目标观察仍为硬件；LLDB自身内部断点不能因此称为硬件点。没有代码/数据/寄存器/PC写入或内部调用注入。

## 完整实际音频仍失败

沿用pass80官方重新保存的Rattle踏板分配FXP及正常CC64/五次重击MIDI，无Pedalboard。正式B与同输入原版参考均为148224帧、双声道24-bit/48kHz：

- 106599个交错样本不同，最大整数差10，首差frame14405；归一化RMS差1.4942939759586978e-7。
- B完整PCM SHA256为66e84b6ca55cdd0167e39f5ace8a05a259ea2e4bb49816fafef39a320290daa9。
- 不完整A的原生WAV也不同：127421样本、最大15、首差13103。

严格音频一致性均失败，不以容差、音色听感或原版自身重跑差异取代验收。3350块包络吻合证明的是局部连续控制链，不是独立声音。

## 仍待闭合

本轮R全局来源、活动分支、u和模型源字段仍观察，baseDuration及timestep也仍来自原生输入；没有把pass78源初始化跨运行拼接进来。setter逐次观察及更新B在本轮缺席。包络尚未接入声部实际复制、再击或最终立体声输出；普通琴槌接触力、弦反馈与制音毡完整方程、全预设运行语义仍未解决。

原始证据保存在私有debug-pass81-rattle-envelope-a/b、pass81-*；没有商业模型、目标数据或WAV入库。本轮复用已导出关闭的pass80 REA站点证据，未产生新的静态分析或宣称额外反编译进展。下一步需要在同次非零控制下继续接入复制/声部输出，并定位完整音频差异，最终才可集成网页、合并和发布。
