# pass41：全局输出路由与三行相加

沿pass40后续调用进入 `6c2ac4`，新增 [只读捕获器](../scripts/pianoteq_capture_global_output.py) 和 [重放器](../scripts/pianoteq_replay_global_output.mjs)。默认与Stereo Width normalized=.25各160个64样本块，两个场景共184320项逐位同；两次原生进程均正常退出0，完整WAV的PCM分别同各自官方基准。

这次验证的计算是全局输出函数末段的路由缓存和相加。前面的两个全局分支仍观察输入，尚未接上pass40各声部计算结果。该函数末尾仍为三行内部信号，不能将它称为最终双声道音频。

## 实际计算与验证位置

四个固定硬件点依次为函数入口 `6c2ac4`、路由调用前 `6c2fd4`、缓存读取后 `6c300c`、相加后 `6c301c`。每个场景640条阶段记录，无回调错误。捕获不修改指令、参数、缓存或授权状态，也未使用Pedalboard。

路由前的矩阵为两行、各64样本，路由后为三行。初始化表中行0送目标0、行1送目标1、行0再送目标2；第三条延迟为零。使用pass40的缓存实现，初始缓存要求逻辑为空，逐块更新环形数据、读头和懒清空标志，检查原生读前/读后状态。读取后的原生缓存样本只作比较，不用作下一块计算输入。

末段计算为：

```
delayed = readRoutedBlock(independentlyUpdatedCache)
output[row][i] = f32(delayed[row][i] + observedOtherBranch[row][i])
```

另一分支在路由前观察，并核对它到相加前未改变。原生 `130db8` 的实际指令在此执行普通float32加法；没有用相加后的结果反推输入或历史。未覆盖其它矩阵布局、变化路由或不同增益，遇到这些情况明确拒绝。

每场景92160项分为缓存读取30720、另一分支未变30720、相加结果30720。这些是同一160块窗口的中间检查，不能当成92160个独立音符或最终WAV样本。默认场景116块路由输入非零，验证窗口包含实际发声。
