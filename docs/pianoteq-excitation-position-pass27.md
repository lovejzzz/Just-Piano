# 击弦位置的实际振幅修正与保存验证：pass27

本轮把 pass26 的分量混合计算接到 `692ffc` 的位置修正；使用官方参数接口生成两个实际生效的击弦位置端点，并以运行时中间量及最终振幅验证。不是只识别参数名，也没有把旁路当成修正公式的正例。

## 创建有效的单变量预设

新开独立 `--no-prefs --serve` 实验实例，在 Devices 中选择系统默认输出后，`getAudioDeviceInfo.status` 为 running。通过官方 `setParameters` 写入 `strike_point` 的归一化 .25/.75，等待参数更新结束并保存，再在全新官方进程读回全部215参数。两份端点只有 Strike Point 改变；所有215项均在既有 `1e-6` 容差内恢复。写入 .75 后读回为 `.7500000596046448`，没有将接口归一化转换说成逐位一致。

完整 FXP 解析显示，三个实际保存案例的声学字段只改变 A+9a8 version10 控制对象的 `d8`：

| 设置 | A+9a8.d8 | A4 运行位置因子 |
|---|---:|---:|
| 基准，接口约 .557243 | .10778400301933289 | .11764705181121826 |
| .25 | .037162721157073975 | .04056338965892792 |
| .75 | .21022410690784454 | .229461207985878 |

运行参考位置保持 `.11764705926179886`、位置比例为1。上述关联仅限定这个版本、控制对象及实测案例；归一化到物理值、逐键缩放的通用公式仍未恢复。

一个失败/对照路径也保留：直接把文件中 A+ce0 曲线从1改为1.5，虽通过结构与普通预设 MD5 验证，但这里观察到的位置控制和两个分支的完整源表都没变。因此它不能作为**本步骤位置变化**的输入。它的最终 PCM 却变化，且两次原版重跑都与这份修改文件的采集一致（相对基准148865个交错采样值不同，最大9025个24-bit整数单位）。其它消费路径尚未查清，不能将其说成全局无效字段，也不能把它误认成此次全局 Strike Point 持久化字段。

## 修正错误的保存等待门槛

本轮官方实例的 `getInfo.modified` 保持 false，最初沿用“必须 modified=true”的等待因此失败。但正常保存后，新进程215项读回及实际渲染位置都证明修改已生效。

`scripts/pianoteq-live-parameter-experiment.py` 现在等待 `computing_parameter_update=false`，保留3秒稳定等待并再次核对更新状态；最终仍要求新进程全参数读回和目标值断言。移除的只是已被实际案例否定的元数据门槛，没有移除持久化成功判据。3秒不是普适提交保证，读回验证仍然必要。本轮实际 RPC 命令、保存文件和恢复结果独立保留；通用脚本修订通过语法检查，没有冒充重跑其全部旧案例。

所有本轮临时实例均通过正常 quit 退出，实验监听端口已关闭。未更改原程序代码或授权/完整性分支，未用 Pedalboard。

## 具体计算

`dsp/excitation-position.mjs` 对实际两个可选标志均为0的路径实现以下计算。这里 `f` 是 float32 舍入，`k` 为实际模态坐标，行号 `r` 从0开始、总行数为 N：

```
target = f(positionFactor * positionScale)
S(p,k) = Σ FMA(weight[j], sinf(f(((2*j-1)*π*k)*p)), accumulator), j >= 1
fade = f(1 - f(r/N))
numerator   = max(weight[0], f(fade * abs(S(target,k))))
denominator = max(weight[0], f(fade * abs(S(referencePosition,k))))
L = logf(f(numerator/denominator))
offset = f(logOffsetSlope*k)
z = logf(f(amplitude/amplitudeReference))
newAmplitude = f(amplitudeReference * expf(f(f(f(offset+z)+L)-offset)))
```

只有 `abs(f(referencePosition-target)) > .0001` 时才执行。零振幅跳过 log/exp。实际权重为 `[2,8,1]`，所以使用 `8*sin(πkp)+sin(3πkp)`，并由2设置下限；不能用简单 `sin(new)/sin(old)` 代替。行号淡出也不能用坐标 k/N 代替。即使从实数代数看 offset 会抵消，也必须保留原生三次 float32 加减的次序。

八项向量前缀先分别舍入乘积再顺序相加；余项使用 FMA。本批权重只有两项正弦，只覆盖余项路径。使用已恢复的纯 JS 标量 logf/expf；sinf 显式传入 `float32(Math.sin(x))`。本批加权和及最终输出吻合，**不代表通用系统 sinf 已移植或全部返回都与 Math.sin 舍入一致**。

REA 精确指令证据：`ev_f92735b7e03002da70497c5b1262fa2a1088f6faac3c756971e14abe7a0dd4ec` 核对加权和 FMA；`ev_6a99f18635bd95ac53d3cb43a8dd120ee10a6dbba4589fd3162424dd473818b5` 核对 log/exp 路径中的减法次序。完整公式同时依据已保留的 `692ffc` 反编译和 ARM64 指令。

## 实际数值与音频

分别在 `6930f0`（混合后、位置修正前）、`693e24`（位置修正后）、`693614`（真实 log 比值返回）单点硬件采集，每次独立运行，只读内存，全部正常 exit0、错误为空。

计算输入来自 pass26 的存档系数混合报告；先与两个修改预设的真实混合后表完整核对，再进入位置计算。两端点主/次两路共216个修正后振幅全部逐位同。另直接采到72行，每行四个实际中间量（参考正弦和、目标正弦和、offset、log比值），**288项也逐位同**。首行两个增益分别为 `.5283880829811096`、`1.6142926216125488`。

每个端点的验证报告共1008项，基准旁路报告864项，全部通过。人为把端点首振幅改动一个 float32 单位后，验证器 exit1，精确报告一处差异；负例保留。

对应的官方原版和全部八次端点采集（修正后初次/v2、混合后、逐行中间量）PCM 都逐字节一致，48kHz/24-bit 双声道113152帧：

- .25：`d3a2d1b7b88ba318878406668e54ecde092f01a3799228b95ab4dbd1c99e0106`
- .75：`7ae06b9eb8df4fb0cc2d46804fc57b58a681bf69544cfd6262391289afad8396`

基准采集仍匹配此前原版短音基准的 PCM 哈希 `1907f854d5c427908038ee9629a5c8997facbb71242e30b94874fc0553a4c9d6`。这些是原程序采集的无扰动对照，不是 JS 全声部 WAV 匹配；之前多音及一次 A4 异常仍保留，不能外推本轮一致性到所有运行。

## 剩余范围与证据

两个可选相位标志、其它权重长度、其它音高/预设尚未验证。模块拒绝非零标志，没有把未实现的相位翻转当成通过。控制值、模态坐标和正弦权重仍来自运行捕获。`692ffc` 后续硬度谱、其它振幅/相位变换及重击反馈仍需闭合；本步骤尚未替换 pass25 的完整两路原始激励输入，网页声音等价性也未完成。

私有证据为 `rpc-pass27-position/`、`debug-pass27-position-*`、`pass27-pcm-verification.json`。正例使用两个 `*-v2/final-replay.json`，验证器支持 `--row-capture` 直接核对中间量。临时文件编辑对照、错误 modified 门槛、端口重用失败及全部原始 WAV 均保留。商业预设/模型与反编译全文不提交仓库。
